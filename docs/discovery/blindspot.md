# blindspot

要件を理解したつもりでも、例外条件や影響範囲を見落としている可能性があるときに使います。

## 渡す情報

目的、現時点の案、変更対象、既存仕様、気になっているリスクを渡します。

## 依頼例

```text
blindspotを使って、依頼一覧に担当者フィルターを追加する案の見落としを確認してください。未割り当て、権限、0件表示、既存検索との組み合わせを含めて調べてください。
```

## 進め方

1. 現時点の案と前提を整理します。
2. 未検討の条件、暗黙の前提、破綻し得る状況を洗い出します。
3. 調査で分かることと人間に確認することを分けます。

## 成果物の例

実成果物の公開に伴う盲点を、現状のコードへ結びつけて洗い出しました。

**到達点：盲点と確認事項の整理。**

### 実行した依頼

```text
実入力、実成果物、画面画像、原本取得をdocsへ掲載する変更について、見落としと手戻りになりやすい前提を洗い出してください。現状のdocsとサイト設定を参照してください。
```

### 実出力の抜粋

以下は保存した原本の冒頭です。全文は原本から取得できます。

````markdown
# Blindspot Pass

目的: スキルの利用者が、実行で得られる内容を画像と原本で確認できるようにする。

## 1. 想定される unknown unknowns

- HTMLだけを配っても、相対パスで参照するJS・CSSが欠けると開けない。
- Markdown原本がサイトの文書として処理されると、原本取得と閲覧が混ざる。
- 検証ログにはローカルの絶対パスが含まれる。公開用の記録では環境固有情報を分離する必要がある。

## 2. 手戻りになりやすい論点

- 説明用の創作を実行結果と呼ぶこと。入力、正本、出力、検証を一組として残す。
- UIスキルの初回案を承認済みと呼ぶこと。人間の実際の回答がない限り承認待ちと記す。
- ダウンロード時にクライアントルーターがリンクを処理すること。native anchorで原本を取得する。

````

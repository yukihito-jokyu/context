# 初めて使う

スキルを指定すると、AIエージェントがその指示書に沿って作業を進めます。最初に達成したいことを決め、対象と制約を渡すと、成果物の良し悪しも確認しやすくなります。

## 1. 目的から一つ選ぶ

「何が分からないか」を整理したいなら[unknowns](discovery/unknowns.md)、既存実装を参考にしたいなら[reference](discovery/reference.md)、Issueを調査から進めて記録したいなら[issue-trace](documentation/issue-trace.md)を選びます。スキルをすべて順番に実行する必要はありません。

## 2. 対象と期待する結果を渡す

次の例は、チーム向け依頼一覧画面の検討を始める依頼です。

```text
unknownsを使って、依頼一覧画面を作る前の不明点を整理してください。
目的：チームの担当者が未対応の依頼を見つけられるようにする。
対象：このリポジトリの既存の一覧画面とIssue #123。
決まっていること：Reactを使い、既存の認証を利用する。
未決定：表示項目と、完了した依頼を一覧に残すか。
期待する結果：不明点の分類、次に使うスキル、人間が判断する論点。
今回は調査まで進め、コードは変更しないでください。
```

スキルを利用できる環境では、スキル名を指定します。まだ利用環境に配置されていない場合は、リポジトリ内の該当`SKILL.md`をエージェントに読み込ませ、その手順で進めるよう依頼します。画面やサービスごとに呼び出し方が異なるため、名前の記法より、指示書が実際に読まれることを確認してください。

Codex・Claude Codeへ導入する方法は[Skillとpluginの配布・導入](authoring/plugin-distribution.md)で確認できます。単一Skillは`npx skills add`、複数Skillのパッケージやhooks付き配布はpluginを使う方針です。skill-refiner用のローカル配布物は生成できますが、配布カタログは未公開のため、ガイド内のmarketplaceコマンドは公開後の導入方法を示しています。

## 3. 成果物を確認する

出力を受け取ったら、目的に対応しているか、確認できた事実と仮説が分かれているか、次に何を判断すべきかを見ます。画面案なら実際の操作、図なら構成と矢印の意味、計画なら作業順と検証方法を確認します。

「この案で進める」「一覧には完了済みを残す」など、何を承認したかが分かる言葉で返すと、その後の作業と記録がつながります。計画の承認と実装結果の確認は、それぞれの対象を確認してから行います。

## 4. 次のスキルへ引き継ぐ

出力の全文を繰り返すより、成果物の場所、確定した判断、残った問いを渡します。[ワークフロー](workflows.md)では、調査から計画、画面案から要件、レビューからPRまでのつなぎ方を説明しています。

```text
planを使って、先ほどの調査から実装計画を作ってください。
参照：調査結果のMarkdownとIssue #123。
確定事項：完了済み依頼は初期表示から除外する。
未確定事項：空状態の文言。
期待する結果：重要判断、作業順、検証方法、未決定事項。
```

# Unknowns Management

対象はIssue #57の実成果物展示への修正。ユーザーの「docsのすべてのスキルの説明に対する成果物の例」を入力として、現在のdocsとサイト設定を確認した。

## 1. 未知の分類

- 既知の既知: Docusaurusを採用し、23スキルの例を実行結果へ置き換える。Markdownの説明と原本ダウンロードが必要。
- 既知の未知: サンプルPR・IssueをGitHubへ実際に作成する範囲は回答待ち。外部投稿まで完了した実例にはできない。
- 無自覚の既知: 読者が画面を見て判断する画像の大きさや入力・成果物の順序。実ページを提示して確認する。
- 無自覚の未知: Markdown原本をdocsに置くと文書として索引化される可能性。ダウンロードリンクがSPAのページ移動として処理される可能性。

## 2. 作業リスク

- 分類: 中。
- 理由: 公開ファイルとドキュメントの扱いを変え、全スキルの例に影響する。GitHubの作成操作には別の許可範囲がある。

## 3. 使用する子スキル

1. referenceで設定、Markdownリンク、utilsの分類を確認する。
2. interviewで外部投稿を伴う実行範囲を確認する。
3. prototypeで画面と原本への導線を具体化する。
4. planで実行例の保存・表示・検証を依存順に並べる。
5. notesで修正中に見つかった制約を残す。

## 4. 最低限の成果物

- 23スキルそれぞれの実入力と実出力。
- 画面のある成果物の実ブラウザ画像。
- 原本および複数ファイルのZIP。
- 到達点と実施済み検証の記録。

## 5. 人間が判断すべき論点

- 外部投稿を伴う実例の作成先と実行範囲。
- 提示後の画像・説明量・成果物の使いやすさ。

## 6. AIが探索してよい論点

- /context/配下のファイル配信、原本の同一性、検索索引からの除外。
- 同梱スクリプトで生成できる形式と検証方法。

# 伝達設計

## 1. 最終的に伝えたいこと

このスキルへどの情報を渡すと、どの成果物が得られ、利用者が何を確認できるのか。

## 2. 読者の前提

スキルの名前と目的は説明ページで読める。実行前に成果物の形を確かめたい利用者を想定する。

## 3. 必要な前提知識

文章を出すスキルと、操作できるHTMLや複数ファイルを出すスキルがある。対話や承認を含むスキルは、初回出力と最終確定物が異なる。

## 4. 情報同士のつながり

- 出力を評価するには、実行した入力が必要。
- 画面の見た目を理解するには、原本から撮影した画像が必要。
- 手元で使うには、原本または参照関係を保ったZIPが必要。
- 完了状態を判断するには、実施した検証と未実施の段階を分ける必要がある。

## 5. 伝える順番

題材と到達点 → 実行時の依頼 → 実出力または画面画像 → 原本取得 → 検証記録。

## 6. 抽象と具体の配置

- 表に出す抽象説明: 何を実行し、何が得られたか。確認待ちの有無。
- 本文の具体例: 実際の文章の抜粋、実画面画像。
- 原本に入れる詳細: 入力全体、実出力全文、生成ファイル、検証結果。

## 7. 不明点・確認事項

提示した実ページの画像サイズと説明量が読みやすいかは人間の確認待ち。この実行では伝達設計を作成した段階までを成果物とし、承認済みの完成本文とは扱わない。

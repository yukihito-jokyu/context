# Implementation Plan

## 1. 重要判断

### 1.1 データモデル・構造

- スキルごとに入力、実出力、検証記録、必要な画面画像を保存する。
- 保存先はdocs/artifacts/examples/<skill-name>。Markdown原本を文書探索から除外する。

### 1.2 型・インターフェース

- 実行記録にはskill、skill_sha256、input、stage、artifacts、checksを持たせる。
- artifactsはファイル名、形式、SHA-256を記録する。実行していない検証をpassにしない。

### 1.3 UX・処理フロー

- 実行した依頼を読み、成果物を確認し、原本を取得する順に置く。
- 文章は実出力の抜粋と全文Markdown、画面は実ブラウザ画像とHTML、複数ファイルはZIPを用意する。
- ダウンロードリンクはnative anchorを使い、クライアント側の文書遷移を避ける。

### 1.4 既存仕様への影響

- 23スキルページの架空例を差し替える。スキルの正本と手順は変更しない。
- 既存の分類、検索、Pages CIを維持し、静的成果物と文書を区別する。

## 2. 実装ステップ

1. 正本を読み、各スキルの実行条件と承認境界を確認する。
2. 公開可能な実題材で文章、図、画面、レビューの成果物を生成する。
3. 同梱の検証と実ブラウザの撮影を行う。
4. Markdownページに実入力・実出力・画像・ダウンロードを反映する。
5. 型、ビルド、リンク、原本同一性、索引を確認する。

## 3. 機械的な変更

- 各ページへ共通の入力・到達点・原本リンクを追加する。
- ファイル一覧とハッシュから検証記録を作る。

## 4. 未決定事項

- サンプルPR・Issueの外部作成範囲。
- 人間による初回画面案・説明量の確認。

## 5. 仮定

- 掲載用の題材には実際の成果物展示と検索実装を使う。
- 人間の回答が必要な実例では、未回答・未承認を明示する。

## 6. レビューしてほしい点

- 実際の出力を見て、スキル利用後に何が得られるか判断できるか。
- ダウンロードした原本を手元で使えるか。

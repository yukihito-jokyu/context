# Pitch / Explainer

## 1. 背景

利用ガイドの「成果物の例」は架空の説明だったため、読者は実行後に得られる文章や画面を確認できなかった。ユーザーは全スキルページを実例へ置き換え、画像と原本の取得を求めた。

## 2. 変更内容

- 各正本を読んで、今回の要件、実検索コード、隔離したサンプルの実差分へ適用した。
- 文章の実出力、図と比較の単体HTML、HTML/Reactの初回画面案、実コミット、レビューHTMLを保存した。
- 原本をdocs/artifactsから配信し、Markdownの説明ページに実入力・抜粋・画面画像・取得リンクを載せる仕組みを追加した。

## 3. 主要な判断

- 表示のために成果物を作り直さず、実出力をそのまま渡す。画面画像は実ファイルを開いて撮影する。
- Reactのように複数ファイルを参照する成果物は、生成した表示一式のZIPを渡す。
- 対話・承認を伴うスキルは、実際の到達点を載せる。未回答や投稿前を完成と表現しない。

## 4. 確認してほしい点

- 入力と成果物を見て、各スキルの利用結果が判断できるか。
- 画像の文字が読め、原本を取得して利用できるか。
- 初回画面案、構成提案、投稿前の草案を区別できるか。

## 5. 注意点

自動検証の成功は、人間が内容を承認したことではない。実例のコミットは隔離したサンプル領域で作成したもので、context本体へのコミットではない。

## 6. 未解決事項

人間による掲載内容の確認、サンプルPR・Issueの外部作成範囲、main反映後のGitHub Pages公開確認。修正作業時点の説明資料として保存し、将来の公開成功を補作しない。

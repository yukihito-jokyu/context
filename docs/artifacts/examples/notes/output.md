# Implementation Notes

成果物例への修正中に、確認した判断と制約を記録する。

## 1. 計画から変更した点

- React用Registryのdetail-page.jsonが404だったため、提供元のローカル正本を一時領域へコピーし、配布JSONを生成して導入する経路へ変更した。
- test.mdはユーザーの修正対象と無関係だったため削除した。

## 2. 変更理由

- RegistryのHTTP応答は404と確認した。同じ提供元のローカル正本にはdetail-pageのソースとRegistry定義が存在した。
- ユーザーは「docsのすべてのスキルの説明に対する成果物の例」を修正対象としている。別ファイルへの記録では実例が見られない。

## 3. 遭遇したエッジケース

- archifyの配布失敗時には古い正常HTMLが残る。候補の検証に成功してからdeliverを実行し、その成功後に同じHTMLをvisual-checkした。
- docs配下のMarkdown原本をそのまま文書探索に含めると、ガイドと成果物の検索が混ざる。
- native anchorのdownload属性がないリンクは、HTML原本の取得ではなくページ表示になる。

## 4. 選択した対応

- 成果物原本を静的配信し、文書探索から除外する。
- 単体HTMLには実画面画像とHTML原本、複数ファイルにはZIPを付ける。
- 未回答・未承認・外部投稿前を実行の到達点に記す。

## 5. 選ばなかった対応

- Registryの問題を理由にDesign System部品を自作すること。
- 存在しない承認やGitHub投稿をサンプルに補うこと。
- 原本の内容を画像用に作り直すこと。

## 6. 後で確認すべきこと

- 全23ページの原本取得と画像の参照。
- Reactの生成、型・lint・ブラウザ検証。
- 公開後のPages URLの確認。

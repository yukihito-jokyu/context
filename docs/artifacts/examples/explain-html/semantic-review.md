# 実例の意味・文章・図の読み合わせ

確認者は実例を作成した同一エージェント。生成後に原文と出力を別の確認作業として読み合わせたもので、第三者レビューや人間の承認ではない。

## 技術題材

入力資料の同期実行、beforeFile、true/false判定、成功時のtarget返却、false時の停止、入力値を、5ページの本文・図・runner.mjs・before.mjs・config.jsonと照合した。全7項目の説明先を確認した。

- runner → before → 判定 → runまたはblockedの順序が一致する。runを呼ぶ前に判定する主体はrunnerであり、before自体がrunを停止するとは記述していない。
- Node.jsの実行結果はallowed:trueでsample.txt、allowed:falseでblocked。runner.mjsの5行目がfalse時にreturnするため、6行目のrun呼び出しは実行されない。
- 技術題材の詳細図は、最初の候補にあった無条件のrun呼び出しを、true/falseの二経路へ修正した。設定の読み込みと入力の検査は段階が異なることを本文に記載した。
- 図の具体例・本文・段階説明は同じtargetとallowedを使う。最小コードと折りたたんだ全文は元の行・字下げを保持する。
- 入力資料にない例外・非同期処理・復旧を存在すると説明していない。実在製品ではなく架空仕様の説明と明記した。

## 一般題材

入力資料の持参、有効性確認、無効時終了、記録作成、14日後の期限、本の受け渡し、返却と記録終了、延滞中の新規貸出制限を逆照合した。全8項目の説明先を確認した。

- 利用者が会員証と本を持参し、職員が確認・記録・貸出する。利用者が返却し、職員が記録を閉じる。各主体の動作と対象を分けて記述した。
- 2026年10月1日から14日後は10月15日。10月16日にも未返却なら期限超過に該当する。複数の延滞記録がある場合は、別の記録による制限が残ることを説明した。
- 詳細図へ延滞状態と返却による記録終了を追加し、本文にある記録の状態変化が図でも追えるようにした。
- 会員証無効は貸出前の終了、延滞は既存記録による新規貸出制限。二つの理由を混同せず、全体図の別枝と説明先を設けた。
- 記録の表形式・具体日付は説明用の仮定として区別した。罰金、予約、延長、会員証更新を実在の制度として捏造していない。一般題材へコードや比較相手を追加していない。

## 表示と文章

各ページの前提・動作文・図の説明・表・補足・資料欄を読み合わせた。全体像ページの短い答えと前提を図の後から前へ移動し、読者が図を読む前に題材と登場主体を把握できるようにした。図の標準出力は変更せず、読みにくい文字を拡大する操作と、本文サイズの説明リンクを追加した。

画面の最終確認と操作結果はbrowser-validation.jsonに分けて記録する。原図のモデルと配布・画像化のレシートを保存した。補助SVG処理を実ブラウザの画像エクスポートやPNGの画素一致確認として扱っていない。

## 確認の限界

上記は保存した架空資料の範囲での内容確認。実在の自然現象・制度の網羅性、生成の再現率、トリガー精度、独立した人間による読みやすさは未検証。残る内容上の問題は今回の読み合わせでは見つからなかった。人間による成果物確認は待機中。

全体像

searchDocumentsの検索対象は、呼び出し元が渡したtitleとcontentです。Aはcontentを空文字にするため、本文中の語を見つけられません。Bは同じ関数へ実本文を渡すため、本文だけにある「再作成」も見つけられます。

先に押さえる前提

この比較はcontextリポジトリの plugins/site-search/search-core.js にある1関数を対象にします。呼び出し元は検証用の同じ4文書・同じ検索語・既定上限8を使い、Aのcontentだけを空文字に変えました。実サイト全体や検索製品の性能は比較していません。

「タイトルのみ」はtitleだけのオブジェクトを意味しません。関数は normalize(document.content) を呼ぶため、呼び出し元はAでも content: "" を渡します。contentを省略すると、normalizeがundefinedを扱えず失敗します。実コード9行目。

Aの呼び出し元は各文書のcontentを空文字にします。検索関数はtitleと空文字を判定するため、タイトルにない「再作成」を候補にできません。

Bの呼び出し元は実本文を保ちます。検索関数は本文の一致も候補に含め、本文の一致に1点を加えます。

共通の実コード

配置：<repository>/plugins/site-search/search-core.js。以下は実ファイルの全行です。保存した原本。

 1 function normalize(value) {
 2   return value.normalize('NFKC').toLocaleLowerCase('ja');
 3 }
 4 
 5 function searchDocuments(documents, query, limit = 8) {
 6   const terms = [...new Set(normalize(query).trim().split(/\s+/).filter(Boolean))];
 7   if (!terms.length) return [];
 8   return documents
 9     .map((document) => {
10       const title = normalize(document.title);
11       const content = normalize(document.content);
12       if (!terms.every((term) => title.includes(term) || content.includes(term))) return null;
13       const score = terms.reduce((sum, term) => sum + (title.includes(term) ? 10 : 1), 0);
14       const position = Math.max(0, content.indexOf(terms[0]));
15       const start = Math.max(0, position - 32);
16       const excerpt = `${start ? '…' : ''}${document.content.slice(start, start + 150)}${document.content.length > start + 150 ? '…' : ''}`;
17       return {...document, score, excerpt};
18     })
19     .filter(Boolean)
20     .sort((a, b) => b.score - a.score || a.title.localeCompare(b.title, 'ja'))
21     .slice(0, limit);
22 }
23 
24 module.exports = {searchDocuments};

正規化・得点・抜粋・上限

①関数はqueryとtitle/contentをNFKCで正規化し、日本語ロケールで小文字化します。queryの前後空白を除き、空白で語を分け、重複語を除きます。②関数はすべての語がtitleかcontentのどこかに含まれる文書だけを残します。語はtitleとcontentへ分かれていても構いません。③関数は各語につきタイトル一致を10点、それ以外の本文一致を1点にします。同じ語が両方にあれば10点です。関数は得点降順、同点なら日本語ロケールでtitleを比較して並べ、slice(0,limit)を返します。既定limitは8です。

関数は最初の検索語が本文に現れる位置から32文字手前を抜粋の開始点とし、原文contentから150文字分をsliceします。関数は必要なら前後へ…を付けます。最初の語がタイトルだけにあれば、関数は本文先頭から抜粋します。空本文のAのexcerptは空文字です。

関数はcontentを取得せず、語形変化や意味の類似、typoを扱いません。NFKC後の位置を原文のsliceに使うため、正規化で文字数が変わる文字の前後では抜粋位置がずれる可能性があります。JavaScriptのsliceはUTF-16の位置を使い、字形の境界を保証しません。関数はlimitの範囲を検査していません。実行したlimit=-1では末尾1件が除かれました。呼び出し元が正の整数を与える必要があります。

使い分け

見出しの名前から探す画面を作る開発者はAを選べます。Aは本文の語による候補を出さず、入力本文を検索関数へ渡す必要がありません。

説明文の内容からも探す画面を作る開発者はBを選びます。Bの呼び出し元は本文の収集と入力サイズの管理を担当します。Bでも検索関数はタイトル一致を強く評価するため、本文一致が常に先頭になるわけではありません。

この試行は性能・メモリ・検索品質の利用者評価を測っていません。開発者は「本文を渡すと高速」「Aが常に適切」といった結論をこの試行から出せません。

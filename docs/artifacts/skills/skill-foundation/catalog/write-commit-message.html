SKILL.md の「2. 手順」と出力の決まり（assets/contract.json）から描いた流れ。左の番号が手順、右が最後のラウンドの収束テストで、独立エージェント（これまでの会話を持たないエージェント）が残した記録。カードに重ねると本文が出る。

チェックポイント（run.py start・check・finish）のある手順hooks が働く範囲↻ 繰り返す 通るまで繰り返す手順（エラー 0 件まで、すべて成功まで、直してやり直す）。番号の横の輪■ 終了 途中で終える道（「〜なら…終える」）◇ 条件 文の頭の「〜なら、」「〜なければ、」で変わる作業↩ 戻る 手順の文にある戻り（「手順Nに戻る」）。戻る元のカードに、戻る場合と戻り先、「└ なぜ」に終了コードの意味（スクリプトの説明の「終了コード:」の行）と戻った先で直すことを書くID機械が確かめるルールIDスクリプト・ひな形IDレビュー・文書だけ（✓ ✕ は、違反の見本を検査が止めたかどうか）
手順の本文（SKILL.md の「2. 手順」）
  1. 依頼から「3. 入力」の項目を読み取る。表で「start の前に聞く」とある項目が依頼に無ければ、ここでまとめてユーザーに聞く（CTL-03）
  2. python3 <skill>/scripts/run.py start --set ticket=<チケットID> "<依頼文>" を実行する。終了コード3なら、出力された質問をユーザーに聞き、答えを --set で渡してやり直す（CTL-01）
  3. python3 <skill>/scripts/collect_diff.py を実行する。終了コード4なら IN-01、終了コード2なら STEP-04 に従って中断する。出力に出たファイルと差分だけを材料にする。git はこのスクリプトの中だけで使い、git add・git commit を実行しない（IN-02、STEP-01、STEP-03）
  4. 1行目を <チケットID> <要約> の形で書く。チケットIDは start が出した ticket の値を使い、要約は「<対象>を<動詞>する」の形にする。[skip ci] のような CI を止める記法は書かない（OUT-02、OUT-03、OUT-04、OUT-05、OUT-06）
  5. 2行目を空行にし、3行目から本文を、collect_diff.py が出した「本文の単位」と STEP-02 の場合分けに従って書く。形は見本 assets/examples/commit-message.txt と同じにする。書いたものを .skill-runs/write-commit-message/out/commit-message.txt に保存する（OUT-01、STEP-02）
  6. python3 <skill>/scripts/run.py check を実行する。「整形」で始まる行は check が契約の format で自動で直した記録なので、ファイルを読み直す。指摘があれば、ルールIDを「4. ルール」で引いて出力を直す
  7. 決めきれなかったことがあれば .skill-runs/write-commit-message/notes.md に「- 」の箇条書きで書き、python3 <skill>/scripts/run.py finish を実行する。終了コード1なら手順6に戻る。終了コード0なら、出力された本文をそのまま返答する（RPT-01）

UserPromptSubmit このスキルが使う

ユーザーの発言を Claude が処理する前に呼ばれる。

write-commit-message の hooks がすること

ユーザーが発言するたびに、write-commit-message が質問の答えを待っているか（run.py wait の後か）を確かめる。

  1. 待っていれば、待ちを解き、休んでいた検査を再開する
  2. 提示済みの成果物に届いた発言を原文と版で記録し、指摘かどうかの分類を案内する
  3. 修正前後の確認画面で承認した版だけを成功例として収集する
  4. どちらのときも、発言を止めたり書き換えたりはしない

ねらい質問の答えをもらったら、休んでいた検査を自動で再開する（質問している間は、run.py wait が検査を休ませている）。

セッションが記録されている場合、別のセッションの発言は混ぜない。承認は確認画面で受け取る。

止められるか
止められる。止めると、発言は Claude に届かない。
絞り込み
絞り込めない。いつも呼ばれる。

Stop このスキルが使う

Claude が応答を終えようとするときに呼ばれる。

write-commit-message の hooks がすること

write-commit-message を実行している間、Claude が応答を終えようとするたびに、作った出力をすべて検査する。

  1. 指摘が残っていれば、応答を終えさせず、指摘を Claude に返して直させる
  2. 指摘が無くても、そのままは終えさせず、run.py finish を実行して報告するよう伝える
  3. 3 回止めても終わらなければ、それ以上は止めず、この実行を失敗として記録する
  4. 完了後と質問待ちでは、提示する成果物の版を指摘収集用に保存する

ねらい検査に通らない出力のまま「完了」と返されることを防ぐ。

止められるか
止められる。止めると、Claude は応答を終えずに作業を続ける。
絞り込み
絞り込めない。いつも呼ばれる。

チェックポイント（run.py start・check・finish）のある手順hooks が働く範囲↻ 繰り返す 通るまで繰り返す手順（エラー 0 件まで、すべて成功まで、直してやり直す）。番号の横の輪■ 終了 途中で終える道（「〜なら…終える」）◇ 条件 文の頭の「〜なら、」「〜なければ、」で変わる作業↩ 戻る 手順の文にある戻り（「手順Nに戻る」）。戻る元のカードに、戻る場合と戻り先、「└ なぜ」に終了コードの意味（スクリプトの説明の「終了コード:」の行）と戻った先で直すことを書くID機械が確かめるルールIDスクリプト・ひな形IDレビュー・文書だけ（✓ ✕ は、違反の見本を検査が止めたかどうか）
手順の本文（SKILL.md の「2. 手順」）
  1. start の前に必要な質問を済ませる（CTL-03）。依頼がステージ済みのgit diffを要約するものかを確かめる。コミットやpushの依頼なら、その操作は行わず対象外と返す（IN-01、STEP-03）。
  2. python3 <skill>/scripts/run.py start "<依頼文>" を実行する（CTL-01）。
  3. python3 <skill>/scripts/collect_diff.py を実行する。終了コード4ならIN-01、2ならSTEP-04に従ってrun.py abortで中断する。終了コード0なら、返されたステージ済みの差分だけを材料にする（IN-02、STEP-01、STEP-02）。
  4. 変更対象と変更動作を日本語で1行にまとめる。50文字以内で行末に句点を付けず、本文と箇条書きとIDは付けない。見本は assets/examples/commit-message.txt を読む（OUT-02、OUT-03、OUT-04、OUT-05）。
  5. 要約を .skill-runs/write-commit-message/out/commit-message.txt にUTF-8で保存する（OUT-01）。
  6. python3 <skill>/scripts/run.py check を実行し、整形されたときは出力を読み直す。指摘があれば出力を直す（CTL-02）。
  7. python3 <skill>/scripts/run.py finish を実行する。終了コード1なら手順6に戻り、0なら出力本文をそのまま返す（RPT-01）。

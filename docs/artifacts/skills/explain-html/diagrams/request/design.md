# 正常通信の設計

問いは「202の後にクライアントが何を取得して結果を表示するか」。時間順の要求と応答なのでsequenceを選ぶ。図はクライアントとAPIの外部通信境界へ限定する。ワーカーが状態を保存することは③と④の解説に置き、架空のキューやDBアクセス方式を発明しない。

図内は①POST、②202とjob_17、③GETと未完了状態、④GETと完了応答。具体的なJSON、GET /jobs/job_17、resultUrl、表示動作は同じ番号のasideへ移す。queuedとrunningはこの正常例で順に観測した値であり、すべての呼出しで観測できる保証ではない。

主図は2参加者・8通信に絞り、editorialとspreadを使う。横のasideに4段階を対応づけ、狭幅は縦に並べる。図の標準出力は無改変。段階再生は同梱flow.jsでasideだけを強調する。SVG overlayと動く線分はゲート未対応のため実装せず、図の同期再生と呼ばない。

実表示で狭幅の文字サイズ未達を確認。workflow v2の縦投影も試したが、標準キャンバス幅864と補足8pxで悪化したため不採用とし試作を削除した。最終束は問いに最適なsequenceの主図のみ。可読性制約はreview.jsonへ残し、画像改変や投影追加で合格を偽らない。

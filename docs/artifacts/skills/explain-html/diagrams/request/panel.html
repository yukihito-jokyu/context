① 初回はジョブを作る

POST /jobs へ img_42 と req_A を送ると、サーバーは job_17 を作り、202とjobIdを返します。202は受付であり、変換の完了ではありません。

② 再送も同じジョブへ

同じ依頼を同じ req_A で送ると、サーバーは重複ジョブを作らず、同じ job_17 を返します。キーを新しく作り直さないことが対応を保つ条件です。

③ jobIdで状態を読む

クライアントは GET /jobs/job_17 で同じジョブの状態を取得します。202だけで成功を表示せず、取得した状態に応じた表示へ進みます。

完了・失敗の状態と表示内容は状態の図で説明します。

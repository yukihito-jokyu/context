画像変換の受付と完了は、別の通信で確認します。架空APIの成功例で、クライアントが受付番号を受け取り、同じジョブの状態を取得する流れを追います。

①から④へ上から下に読みます。③のqueuedとrunningは、この例で観測した未完了状態です。

① クライアントの入力はimageId: img_42とrequestKey: req_42です。② APIが返すjobId: job_17を、③と④のGET /jobs/job_17で使います。④ completedの応答にはresultUrlが入り、クライアントは結果を表示します。

202だけでは結果を表示できません。クライアントがすべての途中状態を観測できるとは限らず、GETの間隔や処理時間は架空仕様で指定されていません。この図は503やfailedを含まない正常例です。

HTTPの202の意味はRFC 9110 §15.3.3、GETの意味は§9.3.1で確認しました。requestKey、状態名、パスは説明用の架空仕様です。

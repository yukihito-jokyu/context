## 原資料・本文・図の意味の照合

構成は、画面の空き枠表示と実際の受付の間に別の申込みが入る可能性を理由に、二重申込み・定員の判定と登録を一つの処理単位へ集める案とした。責務の図と処理の図でも、確定前に同じ条件を判定する。これは設計案であり、実装が同時申込みに耐えることを今回実証したものではない。

画面は、社員が研修の条件を確認して申し込み、結果から自分の一覧へ進める案とした。本人の取消と担当者の登録は入口と権限を分ける。採用理由はそれぞれの操作目的と結び付いており、入力で決まっていない取消期限を常時取消可能な画面として確定していない。

データは、研修情報を申込みごとに重複させず、本人の結果確認と研修別の定員集計を同じ申込みから行うため、社員・研修・申込みに分けた。確定と取消の区別は状態図とも一致している。待機の記録や順位は未決のため導入せず、必要になった場合の影響を質問へつないだ。

外部連携は、入力の「外部システムとの連携はありません。」に従って不採用とした。連携の設計と外部へのシーケンス図を置かず、本人・担当者の識別方法は外部連携を前提にせず質問へ残した。

利用技術、取消期限、待機と空き枠の優先順、本人と担当者の識別、性能・可用性・運用、保存と削除、端末と操作上の配慮について、質問と確定できない設計範囲が対応していることを確認した。未決の設計は未決の状態と質問参照を持ち、利用者による承認を記載していない。

詳細設計への引継ぎは項目間を比較した。製品・配置と運用、受付規則と競合時の検証、物理データと保存、識別と権限、画面の5項目に分け、同じ具体化作業の重複を残さないよう整理した。

# タイトル画面用ループBGM 実行結果

ブラウザゲームのタイトル画面に流す、明るい8小節ループBGMを作りました。通常版とゲームボーイ風の両方を書き出してあります。音は再生していません。

## 成果物

| 種類 | パス |
| --- | --- |
| 設計図 | `songs/title_screen.toml` |
| 通常版 | `output/title_screen/title_screen.wav`（パート別の音源は `output/title_screen/stems/`） |
| ゲームボーイ風 | `output/title_screen_gameboy/title_screen_gameboy.wav`（チャンネル別の音源は `output/title_screen_gameboy/stems/`） |
| 実行ログ | `render.log` |

## 曲の設計

| 項目 | 内容 |
| --- | --- |
| テンポ・調 | BPM 152、D major |
| 構成 | 8小節、4/4 |
| コード | `1 - 4 - 6 - 5 - 1 - 4 - 27 - 5`（最後を `5` にして曲頭の `1` へ戻す） |
| リズム | `bongo_lo`、`bongo_hi`、`tambourine` を互いの隙間に配置 |
| ベース | `pizz_bass`。各小節の頭はルート |
| コード楽器 | `pizz_violin` の裏拍 |
| メロディ | `xylophone`。強拍はコード構成音。後半4小節で音域を上げ、最終小節は曲頭へ下りる動き |
| アレンジ | `melody_octave`（`copy_of` でオクターブ重ね）、`glockenspiel`（1小節目と5小節目の頭の飾り） |
| ミックス | `voice_dip_db = 0`（ナレーションを重ねないため）、`reverb_t60 = 1.0` |

## 実行した手順

1. `command -v uv` で `uv` があることを確認しました。
2. 依頼から、BPM・調・楽器を決めました。ユーザーへの追加の質問はしていません。
3. `assets/sample.toml` の書式を読み、「作曲の順番」に沿って `songs/title_screen.toml` を新規に書きました。旋律は既存曲を参照せずに作りました。
4. `render.py` で通常版とゲームボーイ風を書き出しました。
5. 「つなぎ目」「パート別」を読み、通常版の `gain_db` を直して再度書き出しました（次節）。
6. 最終版をもう一度書き出し、WAV のハッシュと標準出力が一致することを確認しました。

## 修正した内容

初回の書き出しで打楽器とコードが見本の値より小さかったため、通常版の `gain_db` だけを直しました。パターンは変えていません。

| パート | 変更 | 平均 dBFS（修正前 → 修正後） | 見本の値 |
| --- | --- | --- | --- |
| `bongo_lo` | `-9` → `-7` | -34.8 → -33.1 | 打楽器 -31〜-33 |
| `bongo_hi` | `-9` → `-7` | -34.8 → -33.0 | 打楽器 -31〜-33 |
| `tambourine` | `-16` → `-14` | -45.9 → -44.1 | 小物 -42〜-46 |
| `chords` | `-11` → `-10` | -28.7 → -27.9 | chords -27 |

ゲームボーイ風は `gain_db` が効かない方式なので、変更はありません。

## 数値で確認した範囲

### 形式・長さ（2ファイル共通）

- 48000 Hz / 16bit / ステレオの WAV
- 長さ 12.632 秒（606316 サンプル）。BPM 152 の8小節（32拍）の計算どおりです。
- ファイルサイズ 2,425,308 バイト

### つなぎ目

| 版 | 判定 | 曲末→曲頭の段差 | 曲中の小節境界の最大 |
| --- | --- | --- | --- |
| 通常版 | OK | 0.1539 | 0.1704 |
| ゲームボーイ風 | OK | 0.4210 | 0.4298 |

どちらも曲末→曲頭の段差は、曲中の小節境界の最大値を下回っています。

| 通常版 | -16.0 LUFS | -3.0 dBFS | 0.00% |
| ゲームボーイ風 | -16.0 LUFS | -6.2 dBFS | 0.00% |

### パート別（通常版）

| パート | 平均 dBFS | ピーク dBFS | 見本の値（平均） |
| --- | --- | --- | --- |
| `bass` | -22.4 | -10.7 | -22 |
| `melody` | -23.6 | -11.0 | -24 |
| `chords` | -27.9 | -10.3 | -27 |
| `bongo_lo` | -33.1 | -11.9 | -31〜-33 |
| `bongo_hi` | -33.0 | -12.1 | -31〜-33 |
| `melody_octave` | -36.1 | -22.2 | -37〜-38 |
| `glockenspiel` | -36.3 | -17.9 | -37〜-38 |
| `tambourine` | -44.1 | -21.4 | -42〜-46 |

- `bass` は `melody` より 1.2 dB 強い範囲で、目安の「3 dB 以上」には届いていません。
- 最も小さい `tambourine` と飾りの差は 8 dB 弱で、目安の「10 dB 以上」には届いていません。
- `melody_octave` と `glockenspiel` は見本より 0.7〜1.9 dB 大きいままです。目安の警告条件には当たらないため、直していません。

### パート別（ゲームボーイ風）

| チャンネル | 平均 dBFS | ピーク dBFS | 見本の値（平均） |
| --- | --- | --- | --- |
| `ch1_pulse_melody` | -23.6 | -15.1 | -24 |
| `ch2_pulse_harmony` | -30.9 | -16.0 | -29 |
| `ch3_wave_bass` | -25.7 | -22.0 | -24 |
| `ch4_noise_drums` | -27.3 | -15.0 | -27 |

`ch2` と `ch3` は見本より 1.7〜1.9 dB 小さい値です。今回は8小節で音数が見本（16小節）と異なるため参考値として扱い、変更していません。

### 再現性

最終版の設計図で再度書き出し、両方の WAV の SHA-256 が前回と一致しました。標準出力も `render.log` と一致しました。

## 聴いて判断してほしい点

Claude は音を聴けないため、次の点は数値では確認できていません。

- 全体の印象がタイトル画面に合う明るさか、BPM 152 が速すぎないか
- ループを何周か聴いたときに、つなぎ目で違和感がないか
- 8小節の繰り返しが、タイトル画面に長く留まったときにしつこくないか（長くするなら16小節に増やせます）
- `melody_octave`（B7 付近まで上がります）と `glockenspiel` が耳に刺さらないか
- ゲームボーイ風で、`ch2` のアルペジオと `ch3` のベースが埋もれていないか
- メロディが特定の既存曲に似て聞こえないか（既存曲を参照せずに作りましたが、類似の照合はしていません）

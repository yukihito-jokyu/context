<a id="UI001"></a>
### UI001 備品予約と結果照会

| 項目 | 内容 |
| --- | --- |
| 項目 | 備品名、現在残数、取得時刻、数量入力、本人予約ID、保存状態、期限、受付用識別子、確定した操作結果を持つ。操作時の残数と現在残数は別欄である。ST001はactive=予約中、cancelled=取消済み、expired=期限切れ・返却済みと表示する。activeかつdeadline_reached=trueは期限到来・返却待ちと表示する。 |
| 入力検査 | quantityは1〜1000000の整数を画面で検査し、表示残数を超える場合は再取得を案内する。残数は変わり得るため保存側でも判定する。識別子保持に失敗した場合は送信しない。取消はcurrent.cancel_allowed=trueの本人予約だけを有効にする。 |
| 表示状態 | ST002はready=入力可能、sending=処理中、unknown=結果未確認、result=操作結果ありと対応する。初回読込みとGET待機は操作のbusyフラグで表示し、既存の操作結果を消さない。初回取得失敗は再読込みだけを示す。未登録の結果照会では未確認を保つ。 |
| 操作と可否 | ready・resultで現在値取得と結果照会を行える。新規作成と取消は各条件を満たすときだけTR004/TR005でsendingへ進む。sending中は新しい作成・取消・GETを開始しない。unknownでは同じ受付識別子の結果照会と現在値取得だけを許可する。not_recordedでは新しいキーの自動発行も更新の自動再送も行わない。 |
| 保存結果 | committed・rejectedは保存済み結果、conflictは今回内容の識別子競合、invalidは保存前拒否、rollbackは保存未成立確認、unknownは未確認として表示する。foundは元のrecordを表示し、現在値だけの取得を元操作の成功にしない。 |
| フォーカスとキーボード操作 | Tab/Shift+Tabで数量→予約→取消→受付用識別子→結果照会→現在値更新へ移動し、EnterまたはSpaceで押下できる。入力不正は該当入力へ、取消不可は状態説明へフォーカスを戻す。処理結果は見出しとaria-live=politeで一度通知する。unknownでは結果照会ボタンへ移し、非表示の操作へフォーカスを残さない。 |
| 更新通知 | 更新応答後にIF004の明示した読取りを行い、元のrecordを残して現在値を更新する。期限までの補助タイマーは取消を早めに無効化できるが成功を確定しない。期限到来時と画面再表示時はGETだけを行い、監視の返却結果を取り込む。要求番号で古い応答を捨てる。自動の更新要求・外部通知はない。 |

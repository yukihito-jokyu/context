# sample-release-check

sampleプロジェクトのリリース候補を、人間が確認できる短いチェックリストにまとめる。

## 対象と範囲

sampleプロジェクト専用。指定された変更差分と検証記録を確認する。コミット、タグ、push、公開は行わない。

## 手順

1. 対象のブランチまたは差分と、検証記録の場所を特定する。指定が足りなければ不足を確認する。
2. 差分から利用者に影響する変更を要約し、対象ファイルと根拠を示す。
3. 検証記録を読み、成功、失敗、未実施を区別する。記録がない項目を成功としない。
4. 残課題を列挙し、公開可否の最終判断は人間に残す。

## 出力

- 対象の差分
- 利用者に影響する変更と参照先
- 実施済みの確認と結果
- 未確認事項・残課題

秘密情報を含むログは引用せず、安全な要約だけを記す。

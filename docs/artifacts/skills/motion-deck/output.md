## ナレーション（Qwen3-TTS）

`synth --dry-run` で3シーン・343文字・目安約2分と出たので、目安が1分を超えるためバックグラウンドで実行した（`synth.log`）。

| シーン | 文字数 | 音声 | 合成にかかった時間 | シーンの尺 |
|---|---|---|---|---|
| branch | 106 | 18.8秒 | 33秒 | 613フレーム |
| switch | 122 | 18.7秒 | 30秒 | 608フレーム |
| merge | 115 | 17.7秒 | 29秒 | 609フレーム（`hold` 1秒） |
| 合計 | 343 | 55.2秒 | 93秒（コマンド全体の実測） | 1830フレーム |

合成前の `local-tts server status` で、Qwen3-TTS は既に別に起動されていた（`listening, started elsewhere`）。synth はそのサーバーを使い、自分では起動していないので、作業の最後にも止めずに残した。

## 検査と静止画

- 音声を作る前の `check` で、merge の「git merge」の吹き出しがまとめの表と重なる注意（文2の終わり）が出たので、合流の図を `data-until="sum"` で消すようにした。
- 合成後の `check` はエラー 0 件・注意 0 件、発表モード12ステップ。
- `still --cues`（`contact.png`、12枚）と `still --live`（`live-contact.png`、12ステップ、別の `--out`）を見て、見出しが左上、太枠とずらした影、紙色の背景、章バーと字幕の帯（動画のみ）がそろっていることを確かめた。
- PDF の確認で、merge の合流の線が枝の線より約40px上から始まり、緑のコミットが main の線から浮いていることに気づいた（合流の図を別の箱に分け、上の余白を手で合わせていたため）。合流の線とコミットを同じ図の中に入れ直し、`check`・`still --cues`・`still --live`・`pptx`・`pdf` をやり直した（原稿は変えていないので音声は作り直していない）。公開しているのは直した後の結果。

## PDFの書き出し

`pdf` の出力：「完了: `<work>/git-branch/out/git-branch.pdf`（12ページ）」。

PDFKit（macOS の `PDFDocument`）で開いて次を確かめた。

- ページ数は12で、発表モードのステップ数（12）と同じ。全ページ 1440×810pt。
- 全ページで `page.string` から文字を取り出せる（例：1ページ目「ブランチとは 作って移る 合流／ブランチ ＝ 作業の枝分かれ／本流を止めずに、横で作る」、12ページ目「今日のまとめ／git switch -c 枝を作って移る／git commit 枝の上に記録を積む／git merge main に合流させる／次は、小さな機能で枝を一本作る ▶」）。字幕の文は入っていない。
- フォントは JetBrains Mono（TrueType の部分埋め込み）とヒラギノ角ゴ（Type3 の部分埋め込み）。画像の XObject は0個で、走者のキャラクターも図形として描かれている。
- 1・4・6・10・12ページを PNG にして、同じステップの `still --live` の画像と見比べ、配置・文字・図が一致することを確かめた（PDFKit の縮小画像は色がわずかに淡く見える）。
- メタデータは Title「index.html」、Creator は HeadlessChrome、Producer は Skia/PDF。絶対パス・ユーザー名・メールアドレスはない。

## PowerPointの書き出し

`pptx` の出力（`pptx.log`）：

| シーン | スライド | クリック | 図形 | 文字 | 画像 |
|---|---|---|---|---|---|
| branch | 1 | 3 | 15 | 8 | 0 |
| switch | 1 | 3 | 8 | 14 | 3 |
| merge | 2 | 3 | 28 | 28 | 0 |
| 合計 | 4 | — | 51 | 50 | 3 |

「図形にできず画像にした要素」の一覧は出なかった。画像3枚は switch の差分の重ね（ターミナルの打ち込みと、`Motion.scene` で動かす走者の移動）。枝の線とコミットの丸は SVG ではなく箱（`theme.css` の `.ln` と `.dot`）で描いたので、図形のままワイプ・ズームのアニメーションになった。

PPTX の XML（`ppt/slides/slide1〜4.xml`、`ppt/notesSlides/`）で次を確かめた。

- 文字はテキストボックス（`txBox="1"`、スライド順に8・14・7・21個）に入っている（章名、見出し、`main`・`feature/login` のラベル、ターミナルの行、まとめの表など）。switch の最初の打ち込み `git switch -c feature/login` はテキストではなく差分の重ねの画像に入っている。
- アニメーションの対象（`p:spTgt`）はグループが46・25・14・14件、画像が0・6・0・0件で、単独の図形を対象にしたものはない。出現の効果は14・12・5・5件、クリックの起点は3・3・1・1件。
- 画面切り替えは branch→switch がプッシュ（`p:push`）、switch→merge が円（`p:circle`）、merge の2枚目がフェード（`p:fade`）。
- ノートに台本と、文のメモ「枝は捨ててもよい、と一言添える」、シーンのメモ「最後に質問を受ける」が入っている。
- `docProps` の作成者とアプリケーションは `motion-deck`。

PowerPoint で開いての再生は確かめていない（XML の確認まで）。

## 修正の列

ヘッドレスの Chrome（1600×900）で動画モードを開き、switch の文2（commit）のところで `I` を押し、feature/login のカードの文字をクリックして「親へ」でカード全体を選び、指示「今いる枝のカードを、走者と同じ高さにそろえて少し目立たせる」を書いて「指示を追加」した（`player-edit.png`）。溜めた指示が1件になったことを画面と DOM で確かめた。この指示は撮影のための例で、デッキには反映していない。

## 直したい所の伝え方（修正の列）

動画モードで開くと、ステージの左右に修正の列が出る（発表モードでは`E`で出せる）。

1. 左の「シーン」で、シーンへ移る。シーン全体を直したいときは「＋」で対象にする。
2. 要素なら右上の「DOM選択」か`I`でステージの要素をクリックする。文なら右の「原稿」で文を押す。
3. 「対象と指示」に直したいことを書いて「指示を追加」（⌘/Ctrl＋Enter）。
4. 「全部コピー」で、「motion-deck のデッキを直してください。」で始まる文をそのまま Claude に貼る。
5. 直ったら再読み込みして確かめ、済んだ指示を「×」か「全部消す」で消す。

## 気づいたこと

- `still --live` の静止画のファイル名のシーン名が、発表の時間軸ではなく動画の時間軸のシーンで付いているように見える（例：switch・merge のステップの画像が `000280-branch.png`〜`000588-branch.png`、merge の最後が `000696-switch.png`）。画像の中身と一覧画像は正しい。
- `synth` の最後の行の停止コマンドには `--engine` が付いていない（今回はエンジンを指定して合成したが、表示は `local-tts server stop`）。

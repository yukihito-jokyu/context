## 開き方

| 使い方 | 開き方 |
|---|---|
| 人が発表する | `open "<work>/git-branch/index.html?mode=live"`。→・Space・クリック・リモコンで1ステップずつ進み、←で戻る。`N`で発表者ビュー（今話すこと・次のクリック・台本・経過時間）。`V`でナレーションのオン・オフ（`&narration=1`で最初からオン）。`B`/`W`で画面を隠す |
| 動画として見せる | `open "<work>/git-branch/index.html"`（動画モード）。`P`で発表モードと切り替え |
| PowerPoint | `git-branch.pptx`。1画面＝1スライド、1文＝1クリック。ノートに台本（【スライド開始】【クリック n】の区切り）とメモ |

## 直したい所の伝え方（修正の列）

動画モードで開くと、ステージの左右に修正の列が出る（発表モードでは`E`で出せる）。`player-edit.png` はその画面の例。

1. 左の「シーン」で、シーンへ移る。シーン全体を直したいときは「＋」で対象にする。
2. 要素を直したいときは、右上の「DOM選択」か`I`を押し、ステージの要素をクリックする。文を直したいときは、右の「原稿」で文を押す。
3. 「対象と指示」に直したいことを書いて「指示を追加」（⌘/Ctrl＋Enter）。指示は「溜めた指示」に溜まる。
4. 溜まったら「全部コピー」を押し、コピーされた文（「motion-deck のデッキを直してください。」で始まる）をそのまま Claude に貼る。
5. 直ったらページを再読み込みして確かめ、済んだ指示を「×」か「全部消す」で消す。

`player-edit.png` は、シーン2（作って移る）の文2のときに、`I`で注釈のカード「＊ ＝ 今いる枝」を選び、「この注釈カードをもう少し右に寄せたい」と書いて指示を1件溜めたところ（選択モードは終わった状態）。

## シーンの構成

| シーン | 尺 | 型 | 画面 |
|---|---|---|---|
| idea（ブランチとは） | 19.9秒 | 色帯の見出し＋分岐する線と走者 | 「作る・移る・合流する」のチップ、`main`の線とコミットを描き、`feature/login`の枝が分かれて走者が進む。結論のカード「main は そのまま」 |
| switch（作って移る） | 24.6秒 | コードの解説 | 左にターミナル風の`pre.code`（文ごとに強調する行が移る）、右に小さな図で走者（今いる枝）が移り、注釈のカードを文ごとに差し替える |
| merge（合流とまとめ） | 20.5秒 | 図＋ターミナル → まとめ | 枝がメインに戻る線を描き、`git merge`を打つ。最後は見出しごと`.summary`の3行（switch -c／switch／merge）に差し替え |

切り替えは idea→switch が slide、switch→merge が iris。`scenes.js`には switch の走者の移動（`Motion.scene`）だけを書き、ほかは `data-*` と部品で書いた。

## 静止画で見て確かめた範囲

- `contact.png`（各文の終わり13枚）と `live-contact.png`（発表の13ステップ）を全枚数見た。
- 見出しは左上（色帯つき1枚、通常の見出し3枚）、カードは太枠とずらした影、紙色の背景、上の章バー、下の字幕の帯がそろっている。
- 色の意味：青＝枝（主役）、黒＝main、黄＝注釈と走者、緑＝結論・合流のコミット。
- はみ出し・重なりは check でも 0 件。
- `still --cues` は次の文の直前を撮るため、`data-until` で消える要素（switch の注釈カード、merge の3文目の画面）は消えかけの薄い状態で写る。発表のステップの絵（`live-contact.png`）では、どれも完全に表示されていることを確かめた。

## 作業の流れ

1. `init` → 雛形と仮の timeline.js（6シーン）を作成
2. `script.json`（3シーン・13文・381文字）、`lexicon.json`（Git→ギット）、`index.html`・`theme.css`・`scenes.js` を書いた。コマンドを含む文は`say`で読みを与えた
3. `check`（音声なし）→ エラー0件、注意2件（仮の尺、ナレーションの切り替えは未確認）
4. `still --cues` → 一覧画像を見て、見出しが左上、太枠と影、余白、色の意味がそろっていることを確かめた（直す所はなかった）
5. `synth --dry-run` → 3シーン・373文字、目安 約3分
6. `synth`（バックグラウンド）→ 終了コード0、177秒。idea 18.3秒・switch 23.0秒・merge 17.9秒の音声
7. `timeline` → 3シーン、1.08分（1950フレーム）、音声あり
8. `check` → エラー0件、注意0件、発表モード13ステップ（`check.log`）
9. `still --cues`（`contact.png`）と `still --live --out out/live`（`live-contact.png`）を見て確認
10. `pptx` → 4スライド、約5秒で書き出し。ノートに台本とメモが入っていることを確かめた
11. `local-tts server stop` → 「No server started by this tool is running」。VoxCPM2 のサーバーはこの実行の前から別のアプリが起動していた（`started elsewhere`）もので、合成中も他の利用があったため、local-tts の片付け手順に従って止めずに残した
12. 修正の列の画面（`player-edit.png`）を、ヘッドレスの Chrome（1600×900）で動画モードを開き、Chrome DevTools Protocol で`I`→要素のクリック→指示の入力→「指示を追加」と操作して撮った

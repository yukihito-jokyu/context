# Blindspot Pass

目的: スキルの利用者が、実行で得られる内容を画像と原本で確認できるようにする。

## 1. 想定される unknown unknowns

- HTMLだけを配っても、相対パスで参照するJS・CSSが欠けると開けない。
- Markdown原本がサイトの文書として処理されると、原本取得と閲覧が混ざる。
- 検証ログにはローカルの絶対パスが含まれる。公開用の記録では環境固有情報を分離する必要がある。

## 2. 手戻りになりやすい論点

- 説明用の創作を実行結果と呼ぶこと。入力、正本、出力、検証を一組として残す。
- UIスキルの初回案を承認済みと呼ぶこと。人間の実際の回答がない限り承認待ちと記す。
- ダウンロード時にクライアントルーターがリンクを処理すること。native anchorで原本を取得する。

## 3. 既存仕様・既存コードへの影響

- docsの23スキルページの「成果物の例」を差し替える。
- docusaurus.config.tsで成果物を静的配信し、文書の探索から除外する。
- 検索テストのMarkdown件数から成果物原本を除外する。

## 4. 確認すべき前提

- HTMLは単体で読めるか、ZIPを展開してサーバーで開く必要があるか。
- 掲載画像は実際の成果物を撮影したものか。
- ビルド後に取得したファイルが保存した原本と同じか。

## 5. 人間に確認すべき質問

1. サンプルPR・Issueも外部へ作成するか。回答がなければ投稿前の実草案までとして扱う。

## 6. 次に使うべきスキル

- referenceで実設定を確認する。
- prototypeで入力、画像、原本への導線を提示する。
- planで配信と生成の依存関係を整理する。

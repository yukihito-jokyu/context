確認事項

  • Customer・Subscription・InvoiceにはEntity基底型やentity注釈がないためconceptにした。業務上の同一性をどの規則で判定するかは未確認。
  • 参照先の多重度1は必須の単一プロパティ宣言に基づく。顧客ごとの契約数、契約ごとの請求書数、プランごとの契約数を制限するコードはなく、逆方向の多重度は未確認。
  • readonlyはプロパティの再代入を制限するが、参照先の寿命を所有する根拠にはならない。顧客・契約・請求書の削除や生成を連動させる規則は未確認。
  • 領域は宣言元の親ディレクトリによる配置単位であり、業務上の境界として妥当かは未確認。

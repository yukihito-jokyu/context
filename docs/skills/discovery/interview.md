# interview

回答によって設計や優先順位が変わる未決定事項があるときに使います。コードから分かることは先に調べ、人間の判断に集中します。

## 渡す情報

目的、未決定事項、既に調べたこと、AIが判断してよい範囲を渡します。

## 依頼例

```text
interviewを使って、完了済み依頼の表示方針を決めたいです。担当者は日々の未対応確認を重視しています。後から履歴も確認したいので、一問ずつ選択肢と影響を示してください。
```

## 進め方

1. 回答の影響が大きい論点を優先します。
2. 理由と回答によって変わることを添え、一度に一問だけ出します。
3. 回答を仕様・制約へ反映し、次の問いへ進みます。

## 成果物の例

この会話で実際に提示した質問と、まだ回答がない状態を保存しました。

**到達点：質問提示・回答待ち。**

**移行時の確認：既存の実行記録を移行しました。本文の一致は確認しましたが、過去の実行時の同梱資料全体は特定できていません。**

このハッシュは移行時の変更検出用の基準です。同梱資料全体をこの版で再実行した証拠ではありません。

### 実行した依頼

```text
PRやIssue作成を伴う実例の実行範囲が未確定です。実例の到達点が変わる最重要質問を一つ提示してください。
```

### 実出力の抜粋

以下は保存した原本の冒頭です。全文は原本から取得できます。

````markdown
# Interview

## 現在確認すべき最重要質問

実際にこの会話で提示した質問:

> pr・to-issuesなどGitHubへの作成を伴うスキルの実行例は、どこまで進めますか？ その他のスキルは、公開可能なサンプル題材を使って実際に成果物を生成・検証します。

提示した選択肢:

1. 投稿前のPR本文・Issue草案まで実行し、到達点を明記する。
2. 専用のGitHubリポジトリにサンプルPR・Issueも作成する。

## この質問が重要な理由

外部にPRやIssueを作ると、ドキュメントのファイル生成だけでなくGitHub上の操作が発生する。掲載できる実例の到達点が変わる。
````

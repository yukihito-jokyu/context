# to-issues

大きな計画を、個別に着手・確認できるチケットへ分けたいときに使います。ひとつのIssueで利用者の動作が完結する、薄い垂直スライスを作ります。

## 渡す情報

計画、仕様またはPRD、対象トラッカー、ラベルのルールを渡します。

## 依頼例

```text
to-issuesを使って、依頼管理の計画をIssueに分けてください。登録から一覧確認までを最初のスライスにし、分割案と依存関係を確認してからGitHubへ作成してください。
```

## 進め方

1. 会話・計画と必要な既存実装を確認します。
2. スライスごとの目的、HITL／AFK、依存関係を提示します。
3. 人間が分割を承認した後、依存順でIssueを作成します。

## 成果物の例

実計画を入力にした分割案とIssue本文の草案です。実際の投稿前までを例として保存しています。

**到達点：分割案作成・分割承認とGitHub投稿前。**

**移行時の確認：既存の実行記録を移行しました。本文の一致は確認しましたが、過去の実行時の同梱資料全体は特定できていません。**

このハッシュは移行時の変更検出用の基準です。同梱資料全体をこの版で再実行した証拠ではありません。

### 実行した依頼

```text
Issue 57の実成果物展示への変更計画を、単体でデモできる垂直スライスへ分割してください。HITL/AFK、依存関係、ユーザーストーリー、Issue草案を示し、承認前にはGitHubへ投稿しないでください。
```

### 実出力の抜粋

以下は保存した原本の冒頭です。全文は原本から取得できます。

````markdown
# Issue分割案

Issue #57の実成果物展示への修正計画を入力に、独立して確認できる垂直スライスへ分割した。GitHubへの投稿は未実施。トリアージラベルも未指定のため公開時に確認が必要。

1. **実行した文章を入力とともに取得できる** — AFK。ブロック: なし。ユーザーストーリー: 読者が依頼と出力全文を対応づけて確認する。
2. **生成したHTMLを画像と原本で確認できる** — AFK。ブロック: 1。ユーザーストーリー: 読者が操作できる成果物の形を見て、実ファイルを開く。
3. **複数ファイルの成果物をZIPで再現できる** — AFK。ブロック: 1。ユーザーストーリー: 読者が参照関係を保った生成物を取得する。
4. **全スキルの実例と到達点を確認する** — HITL。ブロック: 1、2、3。ユーザーストーリー: 利用者が掲載内容から各スキルの実際の結果を判断する。

## Issue案1: 実行した文章を入力とともに取得できる

### 親

https://github.com/yukihito-jokyu/context/issues/57

### 何を構築するか
````

## 確認するポイント

HITLは人間の判断や操作が必要な作業、AFKは人間との逐次対話なしで進められる作業です。実装レイヤーだけの分割になっていないか、依存と完了条件が明確かを確認します。

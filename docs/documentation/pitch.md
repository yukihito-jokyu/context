# pitch

実装結果を他者へ共有する前に、何が変わり、なぜそうしたかを説明したいときに使います。レビューしてほしい点も整理します。

## 渡す情報

計画、実装ノート、実装結果、検証結果、未解決事項を渡します。

## 依頼例

```text
pitchを使って、担当者フィルターの変更をレビュー担当者へ説明してください。計画とnotesを参照し、URL保存の理由と確認してほしい点を含めてください。
```

## 進め方

1. 背景と変更内容をつなげて説明します。
2. 主要な判断理由とレビュー観点を整理します。
3. 注意点と未解決事項を示します。

### 実行した依頼

```text
実成果物展示への修正で実際に生成した成果物と配信機構を、背景、変更内容、判断理由、レビュー観点、残事項へまとめてください。
```

### 実出力の抜粋

以下は保存した原本の冒頭です。全文は原本から取得できます。

````markdown
# Pitch / Explainer

## 1. 背景

利用ガイドの「成果物の例」は架空の説明だったため、読者は実行後に得られる文章や画面を確認できなかった。ユーザーは全スキルページを実例へ置き換え、画像と原本の取得を求めた。

## 2. 変更内容

- 各正本を読んで、今回の要件、実検索コード、隔離したサンプルの実差分へ適用した。
- 文章の実出力、図と比較の単体HTML、HTML/Reactの初回画面案、実コミット、レビューHTMLを保存した。
- 原本をdocs/artifactsから配信し、Markdownの説明ページに実入力・抜粋・画面画像・取得リンクを載せる仕組みを追加した。

## 3. 主要な判断

- 表示のために成果物を作り直さず、実出力をそのまま渡す。画面画像は実ファイルを開いて撮影する。
- Reactのように複数ファイルを参照する成果物は、生成した表示一式のZIPを渡す。
````

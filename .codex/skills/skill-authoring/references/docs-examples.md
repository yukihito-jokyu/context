# 公開成果物の再作成

Context Repository の `utils/skills/` 内の共通Skillを追加・更新するときに適用する。`docs/skills/` は利用者向けの解説、`docs/artifacts/skills/<skill-name>/` はそのSkillを実行して得た原本である。解説の更新だけで原本が最新になったとは扱わない。

## 更新の単位

本文に加え、scripts・references・assets・vendor等の同梱資料の変更も対象とする。サブエージェントには更新後のディレクトリ全体と、公開可能な題材、入力、許可する操作・終了条件を渡す。実行に外部の資料やプラグインが必要なら、その資料と版も実行記録に残す。

1. Skillの編集を完了し、今回の実行で確認する用途と入力を決める。
2. `node scripts/reset-example.mjs <skill-name>` で該当する成果物ディレクトリを全削除する。他のSkillの成果物を削除しない。作り直しが終わるまでは成果物検査が失敗する状態とする。
3. 新しいサブエージェントに、更新後のSkillを読んで実際に題材へ適用させる。古い出力の書き換えや、実行せず作った見本で置き換えない。実行用の作業場所は公開成果物と分ける。
4. 実際の入力を `input.md`、実出力と必要な画像・HTML・ZIP・検証記録を同ディレクトリへ保存する。確認や承認が必要なSkillは実際に到達した段階で止め、承認や外部投稿を捏造しない。公開サンプルのためのIssue・PR投稿やインストールは、その操作の明示的な許可がなければ行わない。
5. `execution.json` に題材、到達点、確認結果、サブエージェントの識別子と実行タスク、実行した正本のファイル一覧・SHA-256、全成果物のファイル一覧・SHA-256を記録する。`runner` は `{kind: "subagent", agent_id: "実際の識別子", task: "実行した依頼"}` とする。ファイル一覧の作成には `scripts/example-skill-source.cjs` のヘルパーを使う。ハッシュは変更検知であり、実行の事実はサブエージェントの実行結果と原本で確認する。
6. `npm run examples:sync` で解説へ反映し、`npm run examples:check` と公開ガイドの検証を実行する。最後に本文や同梱資料を編集した場合は、再び全削除からやり直す。

実行に失敗したら、旧成果物を復元して最新として掲載しない。失敗と未完了の範囲を報告する。サブエージェントが利用できない場合も、親エージェントによる代行をこの手順の完了とは扱わない。

## 保存するもの

公開に必要な入力、出力、その閲覧・再現に必要な依存ファイルと検証記録を保存する。試行途中の出力、不要なキャッシュや無関係なファイルを残さない。`execution.json` 自体を除く全ファイルを `artifacts` に登録する。登録だけして古いファイルを残さず、削除してから今回の実行結果だけを保存する。

既存成果物の構成移行時には、過去の実行時の同梱資料を後付けで証明できない場合がある。移行時点の変更検知用一覧には `source_baseline` と限界の説明を付け、再実行済みと表示しない。これは初回移行の記録に限り、以後のSkill更新で利用する例外ではない。旧版の本文を保存しても、更新後の再実行の代わりにはならない。

pluginのガイドは `docs/plugins/`、生成・検証した配布物は `docs/artifacts/plugins/<plugin-name>/` に分ける。plugin本体や同梱Skillを更新した場合は、依存する配布物も削除して再生成・検証する。配布物の生成と、導入・有効化・hooksの実動作確認を区別する。

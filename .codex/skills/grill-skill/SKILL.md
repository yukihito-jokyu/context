---

ユーザーが考えている Skill について、相互理解に到達するまで、あらゆる側面を徹底的にインタビューしてください。
設計ツリーの各分岐を順番にたどり、意思決定間の依存関係を一つずつ解消していってください。
各質問では、推奨回答と、その推奨理由を短く提示してください。

質問は必ず一度に一つだけしてください。

もし質問の答えをコードベースの調査によって得られるなら、ユーザーに聞くのではなくコードベースを調査してください。
コードベースの調査に基づいて判断した場合は、根拠となるファイルパスや構造を簡潔に示してください。

曖昧な回答や矛盾がある場合は、次の論点へ進まず、その場で追加質問して解消してください。
構想に矛盾や運用上の破綻がある場合は、差し戻して再定義を要求してください。ただし、参考として暫定案を添えても構いません。

新規 Skill を前提にせず、まず既存 Skill の流用・拡張・統合で足りないかを必ず検証してください。
既存 Skill との重複や統合可能性がある場合は、そのリスクと統合案を優先して提示してください。
少なくとも、責務の重複、保守コスト、発見性、運用整合性の観点で、新規案との比較を簡潔に示してください。

配置先は既存のコードベースや運用規約から判断してください。
判断できる場合はその配置先を採用し、判断できない場合のみユーザーに確認してください。

既存の `SKILL.md` がある場合は、それを正として読み込み、差分最小の改訂案を作成してください。
既存の `SKILL.md` が存在しない場合のみ、新規の `SKILL.md` 草案を作成してください。

少なくとも、以下の論点が埋まるまで終了しないでください。

- 目的
- 対象ユーザー
- 責務範囲
- 既存 Skill との重複可否
- 配置先
- 最終出力形式
- 未解決論点の扱い
- 運用上の制約

議論が完了したら、最終出力には少なくとも以下を含めてください。

- 採用案
- 代替案
- 保留事項
- 配置先パス案
- 既存 `SKILL.md` を更新するのか、新規作成するのかの判断
- その判断の根拠
- `SKILL.md` 草案

未解決論点が残る場合は、保留事項と暫定前提を明示した暫定案として出力してください。
共通認識に到達した場合のみ、確定案として出力してください。

`SKILL.md` 草案は以下のテンプレートを基準にしてください。ただし、既存 Skill の構造や文体がある場合はそれを優先してください。

## SKILL.mdのテンプレート

```md
---
name: スキル名
description: スキルの詳細な説明
---

<スキルの目的>

## Scope

- 対象ユーザー
- 扱う範囲
- 扱わない範囲

## Rule

- ルール1
- ルール2

## Task

1. タスク1
2. タスク2

## Output

- 最終的に出力するもの
- 暫定案の場合に含めるもの
```

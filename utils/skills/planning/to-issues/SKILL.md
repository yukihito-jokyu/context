# イシューへの変換

垂直スライス（トレーサー弾）を使って、計画を独立して着手可能なイシューに分割する。

イシュートラッカーとトリアージラベル語彙が提供されているべきです。提供されていない場合は `/setup-matt-pocock-skills` を実行してください。

## プロセス

### 1. コンテキストの収集

会話コンテキストに既に存在するものから作業してください。ユーザーが引数としてイシューの参照（イシュー番号、URL、またはパス）を渡した場合、イシュートラッカーから取得し、本文とコメントをすべて読んでください。

### 2. コードベースの探索（オプション）

まだコードベースを探索していない場合は、現在のコードの状態を理解するために探索してください。イシューのタイトルと説明はプロジェクトのドメイン用語集の語彙を使用し、触れる領域の ADR を尊重してください。

### 3. 垂直スライスのドラフト

計画を **トレーサー弾** イシューに分割してください。各イシューは 1 つのレイヤーの水平スライスではなく、すべての統合レイヤーをエンドツーエンドで貫く薄い垂直スライスにしてください。

スライスは `HITL` または `AFK` のいずれかです。`HITL` スライスは人間のインタラクションが必要です。`AFK` スライスは人間のインタラクションなしで実装・マージ可能です。可能な限り `AFK` を `HITL` より優先してください。

<vertical-slice-rules>
- 各スライスはすべてのレイヤー（スキーマ、API、UI、テスト）を貫く、狭いが完全なパスを提供する
- 完了したスライスは単体でデモまたは検証可能である
- 少数の厚いスライスより多数の薄いスライスを優先する
</vertical-slice-rules>

### 4. ユーザーに確認

提案した分割を番号付きリストで提示してください。各スライスには以下を含めてください。

- **タイトル**: 短い説明的な名前
- **タイプ**: `HITL` / `AFK`
- **ブロック**: 完了が先に必要な他のスライス（あれば）
- **対象ユーザーストーリー**: このスライスが対応するユーザーストーリー（元資料にある場合）

以下の点をユーザーに確認してください。

- 粒度は適切か
- 依存関係は正しいか
- スライスを統合またはさらに分割すべきか
- 正しいスライスが `HITL` と `AFK` にマークされているか

ユーザーが分割を承認するまで反復してください。

### 5. イシュートラッカーにイシューを公開

承認された各スライスについて、イシュートラッカーに新しいイシューを公開してください。以下のテンプレートを使用してください。これらのイシューは AFK エージェントが対応可能とみなされるため、指示がない限り正しいトリアージラベルで公開してください。

`ブロック` フィールドで実際のイシュー識別子を参照できるよう、依存順で公開してください。ブロッカーを先に作成してください。

## 何を構築するか

この垂直スライスの簡潔な説明。レイヤーごとの実装ではなく、エンドツーエンドの振る舞いを記述する。

具体的なファイルパスやコードスニペットは避ける。すぐに古くなるため。例外として、プロトタイプが文章よりも正確に決定をエンコードするスニペット（状態マシン、リデューサー、スキーマ、型の形）を生成した場合はここにインラインし、プロトタイプ由来であることを簡潔に注記する。残すのは決定の豊富な部分だけであり、動作するデモ全文ではない。

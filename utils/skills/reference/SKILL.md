# reference

言語化が難しい仕様、好み、設計意図、既存慣習を、実物の参照によってAIに伝える。

## Purpose

- 一般論ではなく、現物に合わせるべき点を抽出する。
- 命名、構造、責務、振る舞い、制約、見た目の意図を読み取る。
- 合わせるべき点と、今回合わせなくてよい点を分ける。

## When to Use

- 既存コード、既存画面、既存仕様に合わせる必要があるとき。
- 言葉で説明しきれない設計思想や好みがあるとき。
- 参考実装、参考デザイン、過去成果物を渡されたとき。
- 別言語や別技術でも、同じセマンティクスを移植したいとき。

## Inputs

- 参照すべきコード。
- 参照すべき画面。
- 参照すべき仕様書。
- 参照すべき過去成果物。
- どの観点を合わせたいか。
- 今回の作業対象。

## Process

1. 参照対象を実際に読む。
2. 命名、構造、責務、振る舞い、制約、エラー処理、テスト観点を抽出する。
3. 今回の作業に流用すべき意図を整理する。
4. 合わせるべき点と、合わせなくてよい点を分ける。
5. 参照対象と今回の作業の差分を明示する。
6. 実装や設計に反映する参照ルールを作る。

## Outputs

- Reference Analysis。
- 抽出した意図。
- 合わせるべき点。
- 合わせなくてよい点。
- 今回の作業への適用方針。

## Output Format

```markdown
# Reference Analysis

## 1. 参照対象

- ...

## 2. 抽出した意図

- ...

## 3. 合わせるべき点

- ...

## 4. 合わせなくてよい点

- ...

## 5. 今回の作業への適用方針

- ...
```

## Rules

- 参照対象を読まずに一般論で進めない。
- 表面的な構文だけでなく、意図とセマンティクスを抽出する。
- 参照対象との差分も明示する。
- ソースコードは最優先の参照対象として扱う。

## Anti-patterns

- 「似た感じ」で済ませる。
- 参照対象のコピーだけを行い、今回の文脈に合わせない。
- 合わせなくてよい点まで過剰に踏襲する。

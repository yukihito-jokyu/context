# blindspot

作業前に、ユーザーやAIがまだ考慮できていない「無自覚の未知」を洗い出す。

## Purpose

- 後から手戻りになりやすい未知を先に見つける。
- 既存システム、運用、UX、データ、権限、例外条件への影響を広げて確認する。
- より良い指示、参照、質問、計画につなげる。

## When to Use

- 要件定義前、設計前、実装前。
- 大きな変更や未知のコード領域に入る前。
- 「何を見落としているか分からない」と感じるとき。
- ユーザーが短い依頼だけを渡しており、AIが推測で補いそうなとき。

## Inputs

- 実現したいこと。
- 現時点で分かっていること。
- 現時点で分かっていないこと。
- 対象となる機能、画面、コード、仕様。
- ユーザーの理解度や不安点。
- 参照できる既存物。

## Process

1. 作業目的を一文で言い換える。
2. 既知の既知、既知の未知、無自覚の既知、無自覚の未知を仮分類する。
3. 仕様、データ、権限、互換性、運用、テスト、UX、パフォーマンス、セキュリティの観点で盲点を探す。
4. 後から手戻りになりそうな論点を優先する。
5. 確認すべき前提を列挙する。
6. 人間に確認すべき質問を、重要な順に絞る。
7. 次に使うべき子スキルを提案する。

## Outputs

- Blindspot Pass。
- 確認すべき前提。
- 人間に確認すべき質問。
- 次に使うべきスキル。

## Output Format

```markdown
# Blindspot Pass

## 1. 想定される unknown unknowns

- ...

## 2. 手戻りになりやすい論点

- ...

## 3. 既存仕様・既存コードへの影響

- ...

## 4. 確認すべき前提

- ...

## 5. 人間に確認すべき質問

1. ...

## 6. 次に使うべきスキル

- ...
```

## Rules

- 一般論だけで終わらせず、対象コードや対象仕様に結びつける。
- すぐ実装へ進まない。
- 質問は、回答によって設計や作業順が変わるものを優先する。
- 後続の `reference`、`interview`、`prototype`、`plan` へ接続する。

## Anti-patterns

- 「問題なさそう」と早く閉じる。
- 低影響の論点を大量に並べる。
- ユーザーに聞かず、AIの推測で前提を固定する。

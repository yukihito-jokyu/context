# 文章の書き方

SKILL.md、決定、references、報告は、読む AI と人が同じ意味に取れるように書く。書いた人（AI）と読む人では、見えているものが違う。書いた人は調べた内容と会話の流れを知っているが、読む人はそれを知らない。前提が書かれていない文章や、文と文のつながりが切れた文章は、読む人ごとに違う意味に取られる。この違いが出力の揺れになる。

この章は、1章で文章全体の流れを、2章で1文の書き方を、3章で用語を、4章で人への報告の書き方を示す。

## 1. 流れ

- 結論 C を伝えたいとき、前提 A、A と C をつなぐ B、結論 C の順に書く。前提を省かない
- 節の最初の段落で、その節で何を決めるか、なぜ必要かを書く
- 節の中の小見出しは、読む順に並べる。後の節で使う語は、先の節で定義する
- 別の章を参照するときは、ファイルへのリンクと章の番号を書く（例：[variance-axes.md](variance-axes.md) の3章）

## 2. 1文の書き方

- 1文には1つのことだけを書く
- 主語と述語を省かない。「これ」「それ」で前の文を指さず、名前で書く
- 条件は数、値、有無で書く。[variance-axes.md](variance-axes.md) の5章の語を使わない
- 文末は「〜する」「〜である」にそろえる（ja）。英語は命令形か現在形にそろえる（en）
- 否定の指示には、代わりにすることを添える（例：「上書きしない。別名で保存する」）

## 3. 用語

- 1つのものは1つの語で呼ぶ。言い換えない（例：「出力」と書いたら、同じものを「成果物」と呼ばない）
- コマンド、パス、キー、ルールIDは `` ` `` で囲む
- 製品名は「Claude Code」「Codex」と書く

## 4. 人への報告

報告は、作業の結果を人が判断するための文章である。

- 結果を先に書き、根拠をその後に書く
- 根拠には、実際の記述とその場所へのリンクを添える（例：[SKILL.md:42](.claude/skills/write-commit-message/SKILL.md#L42) と、その行の引用）
- 確かめたことと、確かめていないことを分けて書く。確かめていないことを確かめたように書かない
- 既定値で決めた値と、決めきれなかったことを書く（RPT-01 の「## 補足」）

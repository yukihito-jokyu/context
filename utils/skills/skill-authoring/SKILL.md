name: skill-authoring
description: Skill の追加・更新・配置判定を行い、対応する README.md も整備する。
---

ユーザーが追加または整備したい Skill について、既存運用に沿って `SKILL.md` と関連ドキュメントを更新してください。

## Scope

- 対象ユーザー
  - Context Repository 上で Skill を追加・整備したいユーザー
- 扱う範囲
  - Skill の新規作成
  - 既存 Skill の差分最小更新
  - 再利用性に基づく配置先判定
  - スキル群 README.md の更新
  - 必要に応じたルート README.md の更新
- 扱わない範囲
  - Skill 内容の実装対象リポジトリ側への配布
  - README.md を正本とする運用
  - ユーザー承認なしでの `grill-skill` 起動

## Rule

- ユーザーが明示的に許可した操作だけを行う。「差分を見て対応」や配置・移動の依頼は、Skill 本体の修正許可を含まない。
- 配置・移動だけを依頼された場合は、対象 Skill のディレクトリ配下にある `SKILL.md`、scripts、assets、references、evals、tests その他のファイルを追加・変更・削除しない。
- 配置・移動に伴うスキル群の `README.md` のカタログ更新は許可範囲に含め、積極的に同期する。
- Skill 本体や同梱ファイルを修正するのは、ユーザーが新規作成、内容の更新、改善などを明示的に依頼した場合に限る。
- 既存 Skill の流用・拡張・統合可能性を先に確認する。
- Skill 本体の修正が明示的に許可され、`SKILL.md` が存在する場合はそれを正とし、差分最小で更新する。
- `SKILL.md` が存在しない場合のみ新規作成する。
- 配置先は再利用性で判定する。
- 複数プロジェクトで再利用する Skill は `utils/skills/<skill-name>/SKILL.md` に配置する。
- 特定プロジェクト専用の Skill は `projects/<repo-name>/skills/<skill-name>/SKILL.md` に配置する。
- ユーザーがスキル本文として使えるプロンプトを持っている場合は、その内容を優先して Skill 化する。
- ユーザーがプロンプトを持っていない場合は、`grill-skill` を使ってよいか一度だけ承認を取る。
- 承認を得たら AI エージェントが自動で `grill-skill` を読みに行き、要件定義を進める。
- `README.md` は要約カタログとして更新し、`SKILL.md` と重複しすぎないようにする。
- プロジェクト固有 Skill を追加または更新する場合は、対応する `projects/<repo-name>/skills/README.md` を整備する。
- ルート `README.md` にはプロジェクト説明と、対応する GitHub URL を記載する。
- ルート `README.md` には Skill 一覧を持ち込みすぎず、プロジェクトの入口として整理する。

## Task

1. 既存の Skill 配置、README、運用ルールを調査する。
2. ユーザーがスキル本文として使えるプロンプトを持っているか確認する。
3. プロンプトがない場合は、`grill-skill` を使ってよいか承認を取る。
4. 承認後は `grill-skill` を読み込み、要件定義を完了させる。
5. Skill が共通かプロジェクト固有かを再利用性で判定する。
6. 配置先の既存 `SKILL.md` の有無を確認する。
7. Skill 本体の修正が明示的に許可されている場合だけ、既存があれば更新し、なければ新規作成する。配置・移動だけの場合は内容を変更しない。
8. 対応するスキル群の `README.md` を要約カタログとして更新する。
9. プロジェクト固有 Skill を追加または整備した場合は、必要に応じてルート `README.md` にプロジェクト説明と GitHub URL を追加または更新する。
10. 作成・更新内容と判断根拠を簡潔に報告する。

## Output

- 作成または更新した `SKILL.md`
- 更新した `README.md`
- 配置先の判断結果
- 既存 Skill を更新したか、新規作成したかの判断
- `grill-skill` を利用した場合は、その承認有無と利用結果
- 未解決論点がある場合は、保留事項と暫定前提

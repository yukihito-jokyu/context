# 盲検比較エージェント

どのスキルが生成したかを知らずに、2つの出力を比較します。

## 役割

盲検比較器は、どちらの出力が評価タスクをより良く達成しているかを判断します。AとBというラベルの2つの出力を受け取りますが、どちらをどのスキルが生成したかは知りません。これにより、特定のスキルや手法への偏りを防ぎます。

判断は、出力の品質とタスクの達成度のみに基づきます。

## 入力

プロンプトで次のパラメーターを受け取ります。

- **output_a_path**: 1つ目の出力ファイルまたはディレクトリへのパス
- **output_b_path**: 2つ目の出力ファイルまたはディレクトリへのパス
- **eval_prompt**: 実行された元のタスク・プロンプト
- **expectations**: 確認する期待値のリスト（任意。空でもよい）

## 手順

### ステップ1: 両方の出力を読む

1. 出力A（ファイルまたはディレクトリ）を調べる
2. 出力B（ファイルまたはディレクトリ）を調べる
3. それぞれの種類、構造、内容を記録する
4. 出力がディレクトリの場合は、中の関連ファイルをすべて調べる

### ステップ2: タスクを理解する

1. eval_prompt を注意深く読む
2. タスクの要件を特定する。
   - 何を生成すべきか
   - どの品質が重要か（正確性、完全性、形式）
   - 良い出力と悪い出力を分けるものは何か

### ステップ3: 評価ルーブリックを作成する

タスクに基づき、次の2つの観点からなるルーブリックを作成します。

**内容のルーブリック**（出力に何が含まれるか）:
| 基準 | 1（不十分） | 3（許容可能） | 5（優秀） |
|-----------|----------|----------------|---------------|
| 正しさ | 重大なエラー | 軽微なエラー | 完全に正しい |
| 完全性 | 重要な要素が欠けている | おおむね完全 | すべての要素がある |
| 正確性 | 大きな不正確さ | 軽微な不正確さ | 全体を通して正確 |

**構造のルーブリック**（出力がどのように整理されているか）:
| 基準 | 1（不十分） | 3（許容可能） | 5（優秀） |
|-----------|----------|----------------|---------------|
| 構成 | 整理されていない | ある程度整理されている | 明確で論理的な構造 |
| 書式 | 一貫性がない・崩れている | おおむね一貫している | プロフェッショナルで洗練されている |
| 使いやすさ | 使いにくい | 努力すれば使える | 使いやすい |

基準は具体的なタスクに合わせます。例:
- PDFフォーム → 「フィールドの位置合わせ」「テキストの読みやすさ」「データ配置」
- 文書 → 「セクション構造」「見出しの階層」「段落の流れ」
- データ出力 → 「スキーマの正しさ」「データ型」「完全性」

### ステップ4: ルーブリックに照らして各出力を評価する

各出力（AとB）について:

1. ルーブリックの**各基準を採点する**（1〜5点）
2. **観点ごとの合計を計算する**: 内容スコア、構造スコア
3. **総合スコアを計算する**: 観点スコアの平均を1〜10に換算する

### ステップ5: アサーションを確認する（指定されている場合）

期待値が指定されている場合:

1. 各期待値を出力Aに照らして確認する
2. 各期待値を出力Bに照らして確認する
3. 各出力の成功率を数える
4. 期待値のスコアは補助的な根拠として使う（主な決定要因にはしない）

### ステップ6: 勝者を決定する

AとBを次の優先順位で比較します。

1. **主な根拠**: ルーブリックの総合スコア（内容 + 構造）
2. **補助的な根拠**: アサーションの成功率（該当する場合）
3. **同点の場合**: 真に同等であれば TIE と宣言する

明確に決めてください。同点はまれであるべきです。わずかな差でも、通常は一方の出力がより良いものです。

### ステップ7: 比較結果を書く

結果は指定されたパスのJSONファイルに保存します（指定がなければ `comparison.json`）。

## 出力形式

次の構造のJSONファイルを書きます。

```json
{
  "winner": "A",
  "reasoning": "出力Aは適切な書式と必要なすべてのフィールドを備えた完全な解決策を提供している。出力Bには日付フィールドがなく、書式にも不整合がある。",
  "rubric": {
    "A": {
      "content": {
        "correctness": 5,
        "completeness": 5,
        "accuracy": 4
      },
      "structure": {
        "organization": 4,
        "formatting": 5,
        "usability": 4
      },
      "content_score": 4.7,
      "structure_score": 4.3,
      "overall_score": 9.0
    },
    "B": {
      "content": {
        "correctness": 3,
        "completeness": 2,
        "accuracy": 3
      },
      "structure": {
        "organization": 3,
        "formatting": 2,
        "usability": 3
      },
      "content_score": 2.7,
      "structure_score": 2.7,
      "overall_score": 5.4
    }
  },
  "output_quality": {
    "A": {
      "score": 9,
      "strengths": ["完全な解決策", "適切な書式", "すべてのフィールドがある"],
      "weaknesses": ["ヘッダーのスタイルに軽微な不整合がある"]
    },
    "B": {
      "score": 5,
      "strengths": ["読みやすい出力", "正しい基本構造"],
      "weaknesses": ["日付フィールドがない", "書式の不整合", "データ抽出が不完全"]

  },
  "expectation_results": {
    "A": {
      "passed": 4,
      "total": 5,
      "pass_rate": 0.80,
      "details": [
        {"text": "出力に名前が含まれる", "passed": true},
        {"text": "出力に日付が含まれる", "passed": true},
        {"text": "形式がPDFである", "passed": true},
        {"text": "署名を含む", "passed": false},
        {"text": "テキストが読みやすい", "passed": true}
      ]
    },
    "B": {
      "passed": 3,
      "total": 5,
      "pass_rate": 0.60,
      "details": [
        {"text": "出力に名前が含まれる", "passed": true},
        {"text": "出力に日付が含まれる", "passed": false},
        {"text": "形式がPDFである", "passed": true},

      ]
    }
  }

```

期待値が指定されていない場合は、`expectation_results` フィールド全体を省略します。

## フィールドの説明

- **winner**: "A"、"B"、または "TIE"
- **reasoning**: 勝者を選んだ理由（または同点とした理由）の明確な説明
- **rubric**: 各出力に対する構造化したルーブリック評価
  - **content**: 内容の基準（正しさ、完全性、正確性）のスコア
  - **structure**: 構造の基準（構成、書式、使いやすさ）のスコア
  - **content_score**: 内容の基準の平均（1〜5）
  - **structure_score**: 構造の基準の平均（1〜5）
  - **overall_score**: 1〜10に換算した合計スコア
- **output_quality**: 品質評価の要約
  - **score**: 1〜10の評価（ルーブリックの overall_score と一致させる）
  - **strengths**: 良い点のリスト
  - **weaknesses**: 問題点または不足点のリスト
- **expectation_results**: （期待値が指定されている場合のみ）
  - **passed**: 成功した期待値の数
  - **total**: 期待値の合計数
  - **pass_rate**: 成功した割合（0.0〜1.0）
  - **details**: 個々の期待値の結果

## ガイドライン

- **盲検性を保つ**: どのスキルがどちらの出力を生成したかを推測しない。出力品質だけで判断する。
- **具体的にする**: 強みと弱みを説明するときは、具体例を挙げる。
- **明確に決める**: 出力が真に同等でない限り、勝者を選ぶ。
- **出力品質を優先する**: アサーションのスコアは、タスク全体の達成度に対する補助的な指標である。
- **客観性を保つ**: スタイルの好みで出力を優遇せず、正しさと完全性に焦点を当てる。
- **理由を説明する**: reasoning フィールドで勝者を選んだ理由を明確にする。
- **エッジケースを扱う**: 両方の出力が失敗した場合は、より軽微な失敗の方を選ぶ。両方が優秀なら、わずかに優れている方を選ぶ。

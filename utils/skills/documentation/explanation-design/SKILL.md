# explanation-design

読者に何を理解させたいのかを起点に、そこへ到達するための情報の道筋を設計する。HTML、記事、ドキュメントは最後の表現手段として扱う。

## Purpose

- 情報をそのまま出力せず、読者の理解順に組み替える。
- 説明に必要な前提知識を洗い出す。
- 不足または曖昧な前提をユーザーへ確認する。
- 抽象説明、具体例、補足、注意点の置き場所を決める。
- ユーザー承認後に、設計済みの情報をHTMLなどの表現へ変換する。

## Inputs

- ユーザーから与えられた素材、メモ、仕様、記事案、説明したい内容。
- 想定読者。
- 読者に最終的に理解してほしいこと。
- 出力形式の希望。例: HTML、Markdown、記事、社内説明資料。
- 既知の制約。例: 技術レベル、長さ、トーン、含めたい/含めたくない具体例。

## Process

1. 与えられた情報を、結論、前提、理由、比較、具体例、注意点、補足へ分ける。
2. 読者に最終的に理解してほしい結論を一つに絞る。
3. 読者がすでに知っていそうな前提と、理解に必要な前提知識を分ける。
4. 情報同士の依存関係を整理する。
5. 説明順を、読者が理解しやすい依存順へ並べる。
6. 表に出す抽象説明と、トグルや補足へ入れる具体例・詳細を分ける。
7. 不明点や前提の曖昧さを質問する。
8. ユーザーの承認後に、HTMLや記事本文へ変換する。

## Required Intermediate Output

HTMLや完成本文を出す前に、必ず次の形式で伝達設計を作る。

```markdown
# 伝達設計

## 1. 最終的に伝えたいこと

読者に理解してほしい結論。

## 2. 読者の前提

読者がすでに知っていそうなこと。

## 3. 必要な前提知識

この記事や説明を理解するために必要な知識。

## 4. 情報同士のつながり

- Aを理解するにはBが必要。
- Bを理解するにはCが必要。

## 5. 伝える順番

C -> B -> A のような説明順序。

## 6. 抽象と具体の配置

- 表に出す抽象説明:
- トグル内に入れる具体例・詳細・補足:

## 7. 不明点・確認事項

ユーザーに確認する質問。
```

## Question Rules

質問すべきなのは、内容の代筆に必要な細部ではなく、主に前提の範囲である。

- 読者が何を知っている前提にするかを確認する。
- どこから説明を始めるべきかを確認する。
- 概念説明に留めるか、具体例や実行例まで含めるかを確認する。
- 回答によって説明順、前提知識、具体例の深さが変わる質問を優先する。
- 質問が多い場合は、重要なものを1から3個に絞る。

### Example Questions

```text
この説明では、読者はOpenAPIを知っている前提でよいですか？

Schemathesis自体の説明から始めるべきですか？
それともcoverage / fuzzing / statefulの違いに絞りますか？

具体例はCLI実行例まで含めますか？
それとも概念説明に留めますか？
```

## HTML Mapping

伝達設計が承認された後、HTML化する場合は次の対応を使う。

| 伝えたいこと | HTML表現 |
| --- | --- |
| 最重要の結論 | Hero / Summary Card |
| 前提知識 | Accordion / Toggle |
| 情報の流れ | Timeline / Step |
| 比較 | Table |
| 注意点 | Warning Box |
| 補足 | Tip / Note |
| 詳細な具体例 | Toggle |
| 関係性 | Diagram / Flow |
| 実装例 | Code Block |

## Outputs

- 伝達設計。
- 必要な確認質問。
- ユーザー承認後のHTML、Markdown、記事本文、説明資料。

## Rules

- いきなり文章化・HTML化しない。
- HTML生成を目的にしない。HTMLは最後の表現手段として扱う。
- 読者に理解させたい結論から逆算する。
- 情報の網羅より、理解に必要な順序を優先する。
- 前提が曖昧なまま断定しない。
- 詳細や具体例を本文へ出しすぎず、必要に応じてトグルや補足へ逃がす。
- ユーザーが承認するまで最終HTMLへ進まない。

## Anti-patterns

- 与えられた情報をその順番のまま整形する。
- 読者の前提を確認せずに説明範囲を決める。
- HTML部品選びを先に始める。
- 抽象説明と具体例を混ぜて、読者の理解順を崩す。
- 確認事項を大量に並べる。

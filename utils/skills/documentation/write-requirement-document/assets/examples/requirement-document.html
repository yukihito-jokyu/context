社内備品予約システム 要件定義書

部署ごとの紙台帳による重複予約を防ぐ。社員が空き時間を確認して予約し、管理担当者が予約できる備品を登録する。

1. 概要

解く課題

部署ごとに紙台帳で予約を受け付けるため、同じプロジェクターを同じ時間帯に予約してしまう。

達成すること

社員が備品の空き時間を確認して予約し、重複する時間帯の予約を確定させない。

2. 用語と前提

後の章で使う用語と、業務に関わる人の役割をそろえる。

予約の確定
備品と時間帯を指定した申し込みについて、重複がないことを確認して受け付けた状態を指す。

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

社員

空き時間を確認し、予約と自分の予約の取消を行う。

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

管理担当者

予約できる備品を登録する。

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

3. 対象範囲

目的を達成するために扱う範囲と、今回扱わない範囲を分ける。

対象

  • 備品の登録
  • 空き時間の確認
  • 予約の受付と重複確認
  • 自分の予約の取消

対象外

  • 貸出・返却の記録
  • 備品購入

4. 全体像と業務

全体の境界、利用者ができること、業務の流れの順に確認する。図の下の要件名から、詳しい条件へ進める。

システムの境界と外部の関係

社員と管理担当者が、システムに対して何を行うかを確認する。

誰が何をできるか

社員と管理担当者の役割を、実現する要件と対応させる。

予約の受付が分かれる条件

社員の確認と申し込みの後、重複の有無で結果が変わる順序を確認する。

予約の状態と取消

予約が確定した後、社員の取消によって状態が変わることを確認する。

5. 機能要件

各要件は、必要な振る舞い、理由、受入条件の順に読む。「入力に記載」は資料の記述を示し、承認済みを意味しない。

空き時間を確認する

入力に記載

社員は予約する前に、選んだ備品の空き時間を確認できる。

理由

重複する時間帯を避けて申し込めるようにするためである。

受入条件

  • 予約済みの時間帯がある備品を選ぶと、その時間帯を空き時間と区別できる。

関連図：システムの境界と外部の関係誰が何をできるか予約の受付が分かれる条件

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

予約し、重複を拒否する

入力に記載

社員が備品と開始・終了時刻を指定すると、システムは確定済みの予約と照合する。重複があれば確定せず社員に伝え、重複がなければ予約を確定する。

理由

部署をまたぐ重複予約を防ぐためである。

受入条件

  • 10時から11時まで予約済みの備品に、10時30分から11時30分まで申し込むと、予約は確定しない。
  • 予約のない備品の時間帯に申し込むと、予約が確定する。
  • 境界時刻の扱いは「予約時刻の境界の扱い」の回答後に確認する。

関連図：システムの境界と外部の関係誰が何をできるか予約の受付が分かれる条件予約の状態と取消

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

自分の予約を取り消す

入力に記載

社員は自分の確定した予約を取り消せる。

理由

利用しなくなった予約を取り消せるようにするためである。

受入条件

  • 自分の確定した予約を取り消すと、状態が取消に変わる。
  • 取消から確定へ戻す操作の要否は「取消済みの予約を戻す操作の要否」で確認する。

関連図：誰が何をできるか予約の状態と取消

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

備品を登録する

入力に記載

管理担当者は、社員が予約できる備品を登録できる。

理由

社員が予約の対象となる備品を選べるようにするためである。

受入条件

  • 管理担当者が備品を登録すると、社員が予約対象として確認できる。

関連図：システムの境界と外部の関係誰が何をできるか

根拠：備品予約の打ち合わせメモ · 会話の要望 · 発言1

6. 品質と制約

品質の目標と確認方法を示す。入力に条件がない項目は未決とし、数値や合意を補って確定しない。

性能 / 可用性 / セキュリティ / 個人情報 / 運用 / アクセシビリティ

未決

入力に目標と条件の指定がない。「品質の目標と確認方法」で業務上の条件と確認方法を定める。

    指定された制約

    入力に構成や技術の指定はない。

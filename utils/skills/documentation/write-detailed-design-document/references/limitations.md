# 検査の範囲と既知の限界

このスキルは詳細設計の案を作り、台帳からMarkdownとHTMLを生成する。自動検査は必須項目、引用、ID、参照、キー構成、状態と遷移IDの一致、生成物の一致を確かめる。条件の意味を全て判定するものではない。

## 内容を読んで確認する箇所

独立した担当による最終測定では、次の4種類の不整合が構造検査を通過した。各機能を入口から結果まで読み、状態・保存・画面・返却と確認条件を照合する。

| 箇所 | 残った不整合 | 確認すること |
| --- | --- | --- |
| 要求のnull方針 | 項目はnullを許すが、要求方針では一律に拒否する。 | required・nullable・constraintとrequest_policyが同じ入力を受け付けるか。 |
| 保存失敗と状態 | 保存不成立を含む応答が、失敗を保存済みとする遷移へ一律に対応する。 | 取消・未確定・確定不明と、失敗状態の保存確定を区別しているか。保存できなかった結果で確定状態を進めないか。 |
| エラーの返却 | エラーを列挙しても、実際の応答に種類・理由の項目や対応する状態がない。 | 列挙した全エラーを呼出し元が判別できる形式で返せるか。応答不能の場合と拒否結果を返す場合を分けているか。 |
| 完了後の照会 | 完了済みの状態を保ちながら、「未完了」を意味するpendingを返せる。 | 確定状態と応答の意味が一致するか。矛盾した外部結果を照会エラーへ写像し、終端を覆していないか。 |

## 測定の結果

2026-11-07時点で4ラウンドを実施した。最後は4題材を各2人が実行し、8件全てが生成・文書検査・完了処理を通過した。内容の判定は対象99件中92件通過、7件不合格で、7件は上記4種類に対応する。別の13ページは割当が空であり、元の全境界が他ページにあることを検査した。判定資料の途中省略はない。

ファイル集合は一致したが、構造の一致度は0.154〜0.538、名前は0.409〜0.468で基準未達だった。要件・確認条件・未決の分け方、未採用の物理列やエラーの提案名が異なる。違いがある設計を同じ実装として扱わず、採用する案を決めてから実装へ渡す。

違反例34件とhooksの検査11件は通過し、意味を読むレビューでは4見本を各2人が全件検出した。これらは独立生成の内容判定とは別の結果である。利用者が追加測定を行わず残課題を明記して仕上げると選んだため、上記の未達を残している。全項目が収束したとは扱わない。

測定はCodexの同じモデルのサブエージェントによるものだった。製品間の差、一時プロジェクトのhooksの実動作、自動起動そのもの、実DB・実アダプターの結合、HTMLとMermaidの実描画は未確認である。公開例の文書検査が通っても、これらを確認済みとはしない。

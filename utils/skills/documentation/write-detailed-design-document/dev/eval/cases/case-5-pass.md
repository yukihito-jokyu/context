## 未決U1と依存する設計

開発側がCodex側とClaude側の実行基盤・アダプターの版を固定し、依頼A完了後に接続を切断し、再起動後に会話IDと対象依頼の対応だけからAの回答を取得する。後続依頼Bの回答と取り違えないかも確かめる。記録する証拠は版・起動条件・操作順・対象ID・取得結果・標準エラーである。

採用条件は、同じ対象依頼を識別でき、本文・回答を仲介へ永続保存せずに再取得できること。片方だけ対応する場合は実行基盤別に可否と理由を返す設計案を示し、元の受入条件を満たせるかを別に判断する。

U1は結果再取得のアダプター実装と対応表の整理方法に影響する。内部の状態照会型、受付順の採番、承認の状態遷移はU1に依存しないので提案を具体化し、模擬アダプターで確認条件を作る。模擬試験を実アダプターの結合検証の成功と数えない。

> 元の要件定義書の「質問・回答・実行結果を保存」「Wailsで内容を確認」「会話の期限削除」は設計レビューで変更された。

変更対象は保存・履歴表示・会話の期限削除。変更前は仲介で全文を保存・画面で確認・期限削除する要件、変更後の設計方針は呼出し関係と状態を追跡し、会話全文の管理を実行基盤へ委ねるもの。理由は会話全文の二重管理を避けるためと基本設計に記録されている。

影響先はrequirement.mdの5.19・6.4・8の受入確認、画面項目、保存データ、削除処理、結果再取得試験。本詳細設計では記載の違いと変更理由を残し、元の受入条件まで整合したとは扱わない。変更判断の出典と要件反映を確認する項目を残す。先に確定できる独立した設定保存・承認回答の設計を進める。

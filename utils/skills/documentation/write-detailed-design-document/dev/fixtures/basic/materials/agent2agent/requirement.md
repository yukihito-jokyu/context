### 5.7 AIから問い合わせ・作業を依頼し結果を受け取る

人間からタスクを受けたCodexまたはClaude Codeは、コマンドラインツールを介して専門エージェントへ質問や作業を依頼できる。回答・実行結果・エラーは、仲介サービスとコマンドラインツールを経由して呼び出し元へ返す。失敗時は同じ依頼を自動で再実行せず、失敗内容を受け取った呼び出し元AIが再度依頼するか判断する。

目的：別領域の知識や作業能力を、人間から受けたタスクに利用するため。

受入条件

- CodexとClaude Codeの双方から、質問と、監査などの作業依頼を行える。
- 呼び出し元が回答・実行結果を受け取り、自分の作業に利用できる。
- 失敗を呼び出し元が識別でき、仲介サービスは失敗した依頼を自動で再実行しない。

### 5.12 同じセッションの依頼を到着順に処理する

同じセッションの依頼を処理している間に次の依頼が届いた場合、後から届いた依頼を待機させる。先の依頼の処理が終わってから、到着順に1件ずつ処理する。

目的：同じ会話状態に対する処理の順序を保つため。

受入条件

- 同じセッションの依頼Aを処理中に依頼Bが届くと、Bは待機する。
- Aの処理が終わってからBを処理し、同じセッションで同時に実行しない。

### 5.17 承認を求め設定した期限で判断を返す

専門エージェントが承認を必要とする操作を要求した場合、人間がWails画面で内容を確認し、許可または拒否を判断できる。画面が閉じている場合は、承認画面を自動で表示する。承認の待ち時間を設定でき、時間内に回答がなければ拒否として扱う。判断結果を対応する専門エージェントへ返す。

目的：承認が必要な操作に人間の判断を反映し、無回答時の扱いも定めるため。

受入条件

- 人間が許可・拒否した結果が、対応する専門エージェントへ返る。
- Wailsアプリ本体の動作中に画面だけを閉じていても、承認要求で画面が表示される。
- 設定した待ち時間内に回答がなければ、拒否の結果を返す。

原資料: requirement.md 485〜493行

### 6.2 利用できる状態と会話の保持

Wailsアプリの画面を閉じても、仲介サービスを利用できる。アプリ本体終了時には仲介も停止する。専門エージェントのプロセス終了後も、保存期間内の会話を復元できる。

受入条件

- 画面を閉じた後もコマンドから利用できる。
- 保存期間内のセッションを指定して会話を復元できる。


原資料: requirement.md 527〜533行

### 6.7 技術と表記の制約

- 動作対象はmacOSとし、人間向けの画面と仲介機能をWailsアプリ内に置く。
- 専門エージェントの実行基盤はCodexとClaude Codeの双方を対象とし、対応機能が完全に一致するとは仮定しない。
- 仲介サービスと専門エージェントの間にAgent Client Protocolを使い、仲介サービスをクライアントとする。宛先管理と多段問い合わせは本システムで扱う。
- ファイルアクセス制御には、実行基盤の既存機能を優先利用する。作業ディレクトリの指定だけでアクセス制限を保証したとは扱わない。
- 英単語3語の頭文字を取った省略表現は使わず、同じ概念には同じ用語を使う。

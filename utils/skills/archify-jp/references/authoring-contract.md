# 作成契約

高速作成手順でさらに詳細が必要になった場合にのみ、このリファレンスを参照してください。schemaとexamplesが引き続き正本です。

## schemaの参照

モード別schemaと `schemas/common.schema.json` の両方を参照します。モード別schemaは `$ref` を使用するため、共有enumはcommonファイルにあります。

- `componentType`: `frontend`, `backend`, `database`, `cloud`, `security`, `messagebus`, `external`
- `variant`: `default`, `emphasis`, `security`, `dashed`
- 関係IDは共有識別子パターンを使用し、そのコレクション内で一意でなければなりません。

フィールドを捏造しないでください。構造には最も近いexampleを使用し、ID、文言、事実、レイアウトは新しく作成します。

## ワークフローのレイアウト契約

新しいワークフローにはschema v2を使用し、既存ソースで固定ジオメトリを維持する必要がある場合はschema v1を維持します。どちらのバージョンでも `col` は `0..5` の範囲に留め、間隔修復のためにセマンティックなエッジラベルを削除してはいけません。絶対座標が存在する場合に `schema_version` だけを変更せず、正規の[移行とレイアウトレシート契約](../renderers/workflow/README.md#migration-and-layout-receipt)に従います。完全な規範的不変条件は、ワークフローレンダラーの[レイアウト契約](../renderers/workflow/README.md#layout-contracts)にあります。

## 凡例契約

誠実な既定値には `meta.legend` を省略します。`auto` は型付きIRに存在するセマンティック種別だけを一覧表示します。レンダラーのリファレンスには `mode: "all"`、凡例全体の削除には `mode: "hidden"` を使用します。`entries` では、選択モードのschemaに列挙されたキーだけが有効です。各キーは `label`、`visible`、またはその両方を受け入れます。`visible: true` では未使用の対応規約を表示でき、`visible: false` では非表示にします。`hidden` は上書きできません。

ラベルの上書きが変更するのは読者向け文言だけです。文章から種別を推測したり、欠けているノード、状態、メッセージ、フローを凡例で補ったりしてはいけません。長いラベルは計測され、決定論的な行へ折り返されます。Architectureの暗黙的な自動viewBoxは、同じ計測済み領域から拡張されます。後方互換性のため、`meta.legend` のない旧文書では、明示的viewBoxに収まらない暗黙auto凡例を省略することがあります。型付きトポロジーは決して変わりません。`meta.legend` を追加すると表示は意図的かつ厳格になります。解決済みラベルが作成済みviewBoxに収まらない場合は、ラベルを短縮または非表示にするか、出力された診断に従ってviewBoxを広げます。

## 言語の一貫性

主要な作成言語を1つ選びます。ユーザーの明示的な選択を優先し、それ以外ではリクエストの言語、リクエスト自体が言語中立なら会話の主要言語を使用します。Viewerロケールは別途選択します。対応言語では、必ず一致する `meta.locale` を指定します。日本語は `"ja"`、英語は `"en"`、簡体字中国語は `"zh-CN"` です。レンダラーは図内文字列から言語を推測せず、作成済みロケールを使用します。省略した文書も有効で、既定は日本語です。

`meta.locale` が制御するのはレンダラー所有の読者向け表示だけです。`<html lang>`、文書タイトル接尾辞、既定のSVG説明とフォーカスラベル、既定の凡例ラベル、固定Viewer操作、状態、アクセシビリティ名、エラーが対象です。作成済み内容を翻訳することはありません。タイトル、サブタイトル、ノードと関係の文言、境界、レーン、グループ、引導ビュー、凡例ラベルの上書き、カードには、主要言語を別途適用します。二言語の図でもViewerの主要ロケールは1つです。明示的な主要言語指定、プロンプト内の順序、会話での優勢言語の順に従います。

リクエスト言語が `ja`、`en`、`zh-CN` 以外の場合は、未対応ロケールを指定しないでください。読者向けの作成済み文字列はすべてリクエスト言語に保ち、`meta.locale` を省略してレンダラー所有UIを安全に日本語へフォールバックさせ、固定Viewer UIと `<html lang>` は日本語のままで成果物が完全にはローカライズされないことをユーザーへ明示します。このフォールバックはレンダラー所有の表示面だけに適用され、作成済み文言を日本語へフォールバックさせるものではありません。別の言語や中国語ロケールを `zh-CN` へ暗黙に置き換えてはいけません。

正確な製品名、コード識別子、コマンド、プロトコル、APIパス、環境名は維持します。これらの用語はローカライズ済み文言内で英語のままでも構いませんが、周囲の説明文は選択言語にします。レンダラー所有の既定凡例ラベルは `meta.locale` に従います。図に異なるドメイン文言が必要な場合にのみ `meta.legend.entries.*.label` を上書きし、その作成済み上書きは主要言語に保ちます。

## ビジュアルプリセットの既定値

既定では `meta.visual_preset` を省略します。レンダラーはライト／ダークの両カラーモードで図を `classic` として開きます。カラーモードとビジュアルプリセットは独立したViewer状態です。Light／Darkを切り替えても現在のプリセットを維持しなければなりません。ユーザーがその視覚スタイルを明示的に求めた場合にのみ、`signal-flow`、`blueprint`、`editorial` を指定します。

## エンジニアリングプロファイルの既定値

通常のシステムアーキテクチャでは `meta.engineering_profile` を省略します。region、cluster、security boundaryという文言だけでエンジニアリングプロファイルが有効になることはありません。ユーザーが本番デプロイ構成、所有権の引き渡し、安全側に失敗するデプロイレビューを明示的に求め、ソースの事実が判明している場合にのみ `deployment-ownership` を有効にします。有効化した後は、検証を通すためだけにエンジニアリングプロファイルを削除してはいけません。作成済みの事実を修復するか、診断を誠実に報告します。

## タイトル階層

簡潔なタイトルを1つ使用し、説明は図に担わせます。既定では `meta.subtitle` を省略し、タイトル、ノード、エッジ、カードの言い換えに使用してはいけません。ユーザーがサブタイトルを明示的に求めた場合にのみ、短い補助行を1つ含めます。省略または空のサブタイトルによって、生成Viewerに空の表示行が残ってはいけません。

## 実行可能なジオメトリ規則

- ノードアンカーは辺の中点から始まります。`left`／`right` は水平端点を、`top`／`bottom` は垂直端点を変更します。Architectureの自動関係では、両端点が16pxの角余白を維持している場合、軸オフセットが16px未満で遮られていない対向ポートは、水平軸または垂直軸を共有できます。一方の端点だけが分散グループに属する場合、共有されない側だけを移動します。両端で分散する関係は、異なるポートと外側ブリッジを維持します。
- 辺は方向契約です。最初と最後の経路区間は、指定方向に対して垂直で、外向き／内向きでなければなりません。
- Automatic Port Spreadは、architecture、workflow、data-flow、lifecycle図におけるレンダラーの既定動作です。共有された自動端点を、16pxの角余白で決定論的かつ対称に分散します。sequenceメッセージ、単一の関係、明示的な `via`、`channelX`、`channelY`、`labelAt`、または `auto` 以外の経路には適用されません。
- Showcaseの経路リズムでは、0でない各区間を8px以上、各内部区間を16px以上にします。分散ポートがほぼ平行な場合、ルーターは小さな屈曲を作る代わりに、24pxの端点スタブと16pxの外側ブリッジを使用します。
- 共有端点経路は、セマンティックに曖昧でない場合にのみ許可されます。無関係な同一直線上の重なりが8px以上あるとshowcaseは失敗します。
- コンテナー境界は意図的な通過ジオメトリですが、構造境界に沿って長く走るエッジは違います。
- 無関係で不透明なノードを横切るエッジは、品質プロファイルにかかわらず常に重大な失敗です。

### 間隔とラベル

間隔の推奨値は中心間距離ではなく、ボックス間の空き幅を意味します。幅165pxのノード間で中心間距離が200pxなら、空き幅は35pxしかありません。

関係ラベルには次を要求します。

```text
clear gap > label mask width + 8px breathing room
label mask width ≈ 6.5px × ASCII units + 13px
CJK characters count as two units
```

関係ラベルはセマンティックデータです。空き幅が狭すぎる場合は、ラベルを移動し、経路または間隔を調整してから、意味を保ったまま文言を短縮します。両端点からすでに完全に示され、プロトコル、操作、方向、同期／非同期動作、境界横断メカニズムを何も伝えない文言だけを省略します。意味のあるラベルはすべて維持します。削除は間隔の修復ではありません。端点から完全に意味が分かるため関係を最初から無ラベルにする場合は、文言が冗長である理由を説明します。これはセマンティックな作成判断であり、間隔修復ではありません。workflow v2では、診断された `labelAt`、`labelDx`／`labelDy`、`labelSegment` を適用する前に、コンパイラーが計測済みマスクを割り当てるようにします。診断済みのジオメトリ制御は一度に1つ適用します。

### 修復順序

1. 欠落／無効な `meta.quality_profile` とschemaエラーを修正します。
2. ノードの重なりまたは範囲外配置を修正します。
3. エッジのノード貫通と端点方向エラーを修正します。
4. 交差、曖昧な経路、境界沿いの走行、経路リズムを修正します。
5. ラベル対ノード、ラベル対ラベル、最後にラベル対経路のクリアランスを修正します。

編集のたびに `validate` を実行します。`diagnostics[]` は、安定した `code`、正確な `subject`、計測済み `evidence`、`supportedFixes` によって処理します。診断が `labelAt` を提示した場合、別のオフセットを推測せず、その点を使用します。

## モード別配置

### Architecture

短い垂直分岐を持つ左から右への幹を1本使用します。主要コンポーネントは6～12個を推奨し、実際の所有権、信頼、プロセス、デプロイ境界だけをグループ化します。境界は関係の代わりにはなりません。

schemaが対応する場合はグリッド配置を推奨します。自由配置は、限定された例外には適切ですが、文章レベルの座標計画には適しません。事実として正しい場合、外部アクターはシステム境界の外側に保ちます。

### Workflow

レーンは責任またはフェーズを表し、列 `0..5` は論理的進行を表します。新しいワークフローは `readable-v2` で開始し、旧ジオメトリ互換性のためだけに `fixed-v1` を維持します。正常系経路を単調に保ち、セマンティックなエッジラベルを維持し、再試行と例外復帰はメインレーン経路の外側へ通します。

### Sequence

参加者は会話上の役割順に並べます。メッセージが垂直順序を所有します。return／async／securityバリアントは装飾ではなく意味のために使用します。sequenceはAutomatic Port Spreadを使用しません。

### Dataflow

ステージは変換または管理責任を表し、行は並行ストリームを分離します。明白でないデータ契約、分類、境界横断移動だけにラベルを付けます。

### Lifecycle

主要フェーズは列 `0..4`、event帯とterminal帯は列 `0..2` を使用します。event／terminal列 `N` は、main列 `N + 2` と同じx座標へ揃います。回復可能な失敗には、活動状態へ戻る実際の遷移が必要です。「retry」と書かれたカードや引導ビューはトポロジーではありません。

### Class

クラスは `pos` で明示配置し、属性・操作をUML区画へ分離します。可視性、型、static、ステレオタイプを保持し、継承／実現／集約／合成の種類を交換可能な装飾として扱ってはいけません。関係端の多重度は省略せず、クリック時のカメラ対象は選択クラス単体です。

### ER

エンティティは `pos` で明示配置し、列ごとに型、NULL許可、PK／FK／UQを保持します。FKと関係端は存在するエンティティ列を参照しなければなりません。Crow's Footの端点カーディナリティと識別／非識別関係を保持し、クリック時のカメラ対象は選択エンティティ単体です。

## リポジトリ証拠

アーキテクチャ図が実際のコードを反映する必要がある場合は、作成前にリポジトリのエントリーポイント、ランタイム境界、ストレージ、転送、デプロイ構成を調査します。実際に検証した証拠だけを記録します。`--repo-root <path>` はarchitecture専用で、architectureの `render`、`validate`、`deliver`、`preview`、`compare` が受け付けます。workflow、sequence、dataflow、lifecycleは拒否します。ファイルの近接性や命名だけからランタイム因果関係を推測してはいけません。

## 手動配置へのフォールバック

どのレンダラーも実行できない場合にのみ使用します。`assets/template.html` から開始し、セマンティックCSSクラスを保ち、インラインSVG／アクセシビリティ構造を維持し、配信時の視覚チェックリストを実行します。ダーク／ライトの同等性を壊すインラインのリテラル色を決して導入しないでください。

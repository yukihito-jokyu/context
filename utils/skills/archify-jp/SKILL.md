# Archify

小規模な型付きJSON仕様から、自己完結型のインタラクティブHTML図を作成します。既定では静的に出力し、ユーザーがデモまたはプレゼンテーションを求めた場合にのみアニメーションを有効にします。

## 高速オーサリング手順

通常の生成では、以下の範囲を限定した手順を使用します。ユーザーがその機能を求めない限り、任意のViewer Runtimeリファレンスは読みません。

1. 質問内容から `architecture`、`workflow`、`sequence`、`dataflow`、`lifecycle`、`class`、`er` のいずれかを選びます。
2. `schemas/` 内の該当スキーマ1つ、`schemas/common.schema.json`、および `examples/` 内の該当JSON例1つを読みます。それらのファイルだけを読んでください。新規作成では、新しい安定ID、ドメイン固有の文言、レイアウトを使用します。例はフィールド構造の参考にし、事実は流用しません。新しいワークフローソースでは `schema_version: 2` と可読性重視のレイアウト契約を使用し、既存ワークフローの固定ジオメトリを維持する場合にのみ `schema_version: 1` を残します。実在製品の識別情報が重要な場合は `node bin/archify.mjs brands "<name>" --json` を実行します。ユーザーがURLを提供した未知のブランドについてのみ `references/brand-marks.md` を読みます。
3. 成果物を先に作成します。次のツール操作では候補を書き込まなければなりません。レンダラー内部を調べる前に候補を書き込んでください。正確な座標を文章で計画しません。明確な主経路を1つ、短い側枝、少数のラベル、最大12個の主要ノードから始めます。ユーザーが密集した `standard` マップを明示的に求めない限り、`meta.quality_profile` を `"showcase"` に設定します。自動ルートと自動ラベルから始めます。診断で必要とされる前に `via`、`channelX`、`channelY`、`labelAt` を追加しません。1回の修正で適用する診断済みジオメトリ制御は最大1つです。
4. 候補を編集するたび、および引き渡し直前に検証します。

   ```bash
   node bin/archify.mjs validate <type> <candidate.json> --quality showcase --json
   ```

   成果物チェックが4項目だけのレシートは基本検証であり、showcaseの合格ではありません。showcaseの合格には、成果物チェック9項目すべて、構成エラー0件、警告0件が必要です。候補で正確な `meta.quality_profile` フィールドが省略または誤記されている場合は、ジオメトリより先に修正します。workflow v2のジオメトリ診断では `node bin/archify.mjs validate workflow <candidate.json> --layout-json` を実行し、安定したコンパイラーレシートを使用します。ソルバー内部はオーサリング制御ではありません。最終検証に合格した時点で候補を凍結し、それ以降は編集しません。
5. 配布するHTMLでは、`deliver` を最終受け入れコマンドとして使用します。

   ```bash
   node bin/archify.mjs deliver <type> <candidate.json> <output.html> --quality showcase --json
   ```

   0以外の終了コードを成功と説明してはいけません。配布に失敗しても以前の出力は保持されるため、そのパスに対して `visual-check` を実行しません。失敗した候補ではなく、古い最終正常成果物を検査してしまうためです。検証に失敗した場合は、診断された `subject` だけを変更し、`evidence` を確認し、`supportedFixes` から選択して再実行します。客観的なエラー数の最小値が更新される間は、焦点を絞った修正を続けます。2回連続で最良値が改善しない場合は停止し、未解決の診断を正確に報告します。

## 更新の認識

最初の候補ができた後、同梱チェッカー `scripts/check-update.mjs` をNodeで一度実行し、依頼された作業を続けます。コマンドを実行できない場合は、確認について言及せずに続行します。

- `silent` の場合、更新確認に言及せず続行します。
- `update_available` の場合、インストール済みバージョン、最新バージョン、チェッカーが返す固定ローカル要約、公式リリースノートへのリンクを含む簡潔な通知を、ユーザーとの会話言語で表示します。`severity` が `security` の場合は、セキュリティ更新であることを明記し、控えめな警告記号を使います。これは強調方法だけを変えるもので、ユーザーの選択権には影響しません。インストール済みSkillは変更されておらず、更新するかどうかと時期はユーザーが決めることを明示します。この固定ローカル文は翻訳しても構いませんが、リモートマニフェストの要約を引用、要約、翻訳してはいけません。通知を表示した後、同じチェッカーを `--ack "<eventKey>"` 付きで実行して正確な `eventKey` を確認済みにし、ユーザーの元の作業を続行します。

通知は情報であり、許可ではありません。インストール済みバージョンは変更しません。このv0.1ワークフローは更新をダウンロード、インストール、実行せず、沈黙を同意とみなしません。

最初の候補を作成する前に、`renderers/shared/geometry.mjs`、レンダラーソース、バリデーターソース、テスト、ベンチマークを読んではいけません。未対応の内部診断がある場合、または焦点を絞った修正が2回失敗した後にのみ実装を調査します。

ワークフローに関する注記：新しいワークフローではスキーマv2を使用し、既存ソースで従来の固定ジオメトリが必要な場合はスキーマv1を維持します。意味のあるエッジラベルを保持し、コンパイラー診断に従います。標準のレイアウト、固定、移行、レシート契約は [`renderers/workflow/README.md`](renderers/workflow/README.md#layout-contracts) にあります。

ライフサイクルに関する注記：フェーズ列 `0..4` は主レールを占めます。`0..2` のイベント／終端列 `N` は、主列 `N + 2` の真下に正確に揃えます。回復可能な状態では `type: "failure"` と、アクティブ状態へ戻る実際の遷移を使用します。

## 種類の振り分け

| 種類 | 用途 |
|---|---|
| `architecture` | コンポーネント、サービス、クラウド／セキュリティ境界、インフラストラクチャ |
| `workflow` | プロセス、承認ゲート、ツール呼び出し、ランブック、CI/CD |
| `sequence` | API呼び出しチェーン、リクエストのライフサイクル、非同期トレース、戻り値 |
| `dataflow` | パイプライン、ETL/ELT、リネージ、ガバナンス、利用者 |
| `lifecycle` | 状態／ステータス遷移、再試行、待機、終端状態 |
| `class` | UMLクラス、インターフェース、属性、操作、継承／実現／集約／合成 |
| `er` | エンティティ、列、主キー／外部キー、Crow's Footカーディナリティ |

曖昧な場合は `node bin/archify.mjs guide "<scenario>" --json` を実行します。シナリオの実証例は構造上の参考資料であり、コピーする事実ではありません。

## Mermaid入力

Mermaidからトポロジーと意味を読み取り、新しいArchify JSONを作成します。Mermaidのスタイルを機械的に描画しません。

- `flowchart` / `graph` → `workflow`。コンポーネントマップの場合は `architecture`。
- `sequenceDiagram` → `sequence`。参加者は意味のある参加者に、矢印はメッセージになります。
- `stateDiagram` → `lifecycle`。状態と遷移はMermaidのスタイルではなく意味を保持します。
- `classDiagram` → `class`。可視性、属性、操作、継承・実現・集約・合成を保持します。
- `erDiagram` → `er`。エンティティ、列、キー、関係、カーディナリティを保持します。

## オーサリングの不変条件

- 明白な主経路を1つ設け、側枝は最も近い主経路ノードから分岐させます。ルーティング制御を追加する前に、価値の低いエッジを削除します。
- 解決されたカラーモードがライトかダークかにかかわらず、すべての図が `classic` で開くよう、既定では `meta.visual_preset` を省略します。カラーモードと視覚プリセットは独立したViewer状態です。Light / Darkの切り替えでは現在のプリセットを維持しなければなりません。ユーザーがその視覚スタイルを明示的に求めた場合にのみ、`signal-flow`、`blueprint`、`editorial` を設定します。
- 既定では `meta.subtitle` を省略します。タイトル、ノード、カードを言い換えただけのサブタイトルを作ってはいけません。ユーザーが明示的に求めた場合にのみ、短い補足行を1つ含めます。
- 単体デスクトップViewerは、浅い帯ではなく、既定でファーストビューを構成する成果物として扱います。ノートPCと外部ディスプレイ向けにレスポンシブな成果物を1つ生成し、端末固有のHTMLや別トポロジーは作りません。Viewerがライブビューポートの高さに応じて変更できるのは外側の閲覧幅だけです。作成済みのSVG/viewBox、比率、意味的ジオメトリ、通常の文書フローを維持しなければなりません。幅広または縦長のデスクトップでは、図パネルと必要な結論カードが画面全体を均衡よく占めるよう、作成時に十分な垂直リズムを確保します。実行時の拡大縮小では、Y方向に過度に圧縮されたレイアウトや小さすぎる明示的な `meta.viewBox` を修復できません。表示確認をユーザーが明示的に依頼した場合に限り、実際のHTMLを1440×900、1600×1000、1920×1080で開き、大型デスクトップ表示向けの構成ではさらに2048×1320でも確認します。確認したすべてのサイズで `document.documentElement.scrollWidth <= window.innerWidth` と `scrollHeight <= window.innerHeight` を満たす必要があります。また、確認した最大ビューポートで図が無理なく読め、縦方向に均衡していることを目視確認します。オーバーフローは、ノード、ラベル、主パネルを縮小する前に、本当に冗長な内容だけを削除するか、間隔を詰めて修正します。最大ビューポートでもViewerの幅上限内の下部に目立つ空白帯が残る場合は、作成したY位置を再配分し、viewBoxの高さを比例して増やします。水増しの文章や装飾カードを追加しません。`overflow: hidden`、内容の切り落とし、図内部のスクロール領域、引き伸ばしたSVGの高さ、小さな文字で合格を偽装してはいけません。狭幅／モバイルのレイアウトは、収めるために必要な場合は縦スクロールして構いません。
- 正確な既定値 `auto` を使用するため、`meta.legend` を省略します。必要な場合は `mode: auto|all|hidden` と、レンダラーが対応する `entries.<kind>.label|visible` だけを使用します。ラベルが意味を変えることはありません。
- 明示されたユーザーの選択から主要な作成言語を1つ選びます。明示されていない場合は、依頼または会話で優勢な言語に従います。`meta.locale` が制御するのはレンダラー所有のViewer UIだけです。日本語には `"ja"`、英語には `"en"`、簡体字中国語には `"zh-CN"` を使用します。`meta.locale` を省略した場合、固定Viewer UIと `<html lang>` は日本語になります。その他の言語では `meta.locale` を省略し、固定Viewer UIと `<html lang>` が日本語にフォールバックすること、成果物が完全にはローカライズされないことを明示します。レンダラーは作成済みの内容を翻訳しません。詳細は `references/authoring-contract.md` を参照してください。
- 正確な製品名、コード識別子、コマンド、プロトコル、APIパス、環境名を保持します。ローカライズした文章内で英語のままでも構いませんが、それを理由に周囲の説明文まで別言語のままにしてはいけません。
- ブランド識別情報は任意かつ明示的です。ノードが実在製品を指す場合は、標準の組み込みIDを `brand` に設定します。一致するプリセットがなく、ユーザーが公式HTTP(S) URLを提供した場合は、まず `node bin/archify.mjs brands capture "<url>" --json` を実行し、返されたダイジェスト固定済み `brand` オブジェクトを作成します。renderとvalidateでは固定されていない取得を行いません。それ以外では `brand` を省略します。「database」のような曖昧な役割からブランドを推測せず、バッジで意味的な `type`、ラベル、関係の事実を置き換えません。
- シーケンス図では、安定した `fixed` レイアウトを使うため `meta.column_fit` を省略します。幅広のviewBoxで水平方向の空白が生じる場合、または意味のある参加者ラベルが固定ボックスに収まらない場合は `"spread"` を設定します。`spread` を試す前に意味のあるラベルを短縮しません。
- コンポーネント種別は `frontend`、`backend`、`database`、`cloud`、`security`、`messagebus`、`external` です。バリアントは `default`、`emphasis`、`security`、`dashed` です。
- 関係ラベルは意味を持つデータです。衝突する場合は、意味を保ったままラベルの移動、ルートまたは間隔の調整、文言の短縮の順に対応します。両端点から完全に推測でき、プロトコル、操作、方向、同期／非同期の動作、境界をまたぐ仕組みを一切含まない文言だけを省略します。意味のあるラベルはすべて保持します。削除はジオメトリ修正ではありません。両端点から完全に推測できるため最初から関係にラベルを付けない場合は、文言が冗長な理由を説明します。これは意味上のオーサリング判断であり、ジオメトリ修正ではありません。
- 既定では `meta.engineering_profile` を省略します。リージョン、クラスター、セキュリティ境界という文言だけでは有効にしません。ユーザーが本番デプロイメントトポロジー、所有権の引き継ぎ、フェイルクローズ方式のデプロイメントレビューを明示的に求め、元となる事実が判明している場合にのみ `deployment-ownership` を有効にします。有効にした後は、検証に合格させる目的だけでエンジニアリングプロファイルを削除してはいけません。事実を修正するか、診断を正確に報告します。
- 間隔とは中心間距離ではなく、空きの幅です。関係ラベルでは、空き幅が測定済みマスク幅を上回る必要があります。ラベルを保持する修正順序に従います。
- 自動ルートが端点の辺を所有します。辺は方向の契約です。最初と最後の線分は、その辺に対して垂直に出入りしなければなりません。
- Automatic Port Spreadは、architecture、workflow、data-flow、lifecycleにおけるレンダラーの既定動作です。単一の関係、および明示的な `via`、`channelX`、`channelY`、`labelAt`、または `auto` 以外のルートは対象外です。ほぼ平行なポートでは外側のブリッジを使用し、自動ルーティングによる8px未満の線分や16px未満の内部曲がりを防ぎます。architectureでは別途、遮るものがない向かい合う自動ポート（`left`/`right` または `top`/`bottom`）について、オフセットが16px未満で両ポートが角からの余白を維持できる場合、同一軸上に保ちます。一方の端点だけが分散された場合は、共有されていない端点だけをその軸上へ移動できます。両端点が分散された場合は外側のブリッジを保ち、競合するポートを区別します。
- 関係のない不透明ノードを横切るエッジ、曖昧な共有経路、関係ラベルが別ルートを覆う状態を受け入れてはいけません。

フィールドの列挙値、間隔の計算、ジオメトリ修正規則、リポジトリの根拠、種類固有の配置が必要な場合にのみ `references/authoring-contract.md` を読みます。

## 配布

修正中は `validate` を使用し、最終受け入れでは `deliver` を一度だけ使用します。配布処理は仕様の正確なバイト列を同一ディレクトリ内の非公開スナップショットへ凍結し、そのスナップショットをレンダリングして確認し、HTMLをアトミックに確定します。また、仕様と成果物それぞれのSHA-256とバイト数を報告します。

ユーザーが表示確認を明示的に依頼した場合にのみ、配布後の信頼済みHTMLを変更または再レンダリングせず、範囲を限定したデスクトップ証跡を収集します。依頼がない場合は `visual-check`、ブラウザでのオープン、スクリーンショット取得を実行しません。

```bash
node bin/archify.mjs visual-check <output.html> --json
```

`visual-check` は1440×900、1600×1000、1920×1080、2048×1320で収まりを測定し、最小および最大サイズでライト／ダークのスクリーンショットを取得し、成果物の隣に相対パスのコンタクトシートとJSONサイドカーを書き込みます。自動レシートは常に `visualReview: "pending"` を報告します。スクリーンショットは確認用の証拠であり、自動的に洗練済みと判断するものではありません。終了コード0は収まりとキャプチャの合格、1はオーバーフローまたはキャプチャ失敗、2はChrome/Chromiumが利用できずレシートが `skipped` であることを意味します。このコマンドは配布済みHTMLを変更しません。

ユーザーが即時のローカルプレビューを求める場合にのみ `--open` を追加します。デスクトップでの継続的なオーサリングには、必要に応じて次のコマンドを使用します。

```bash
node bin/archify.mjs preview <type> <input>.json <output>.html --quality showcase
```

既定ではpreviewを開始しません。preview、リポジトリの根拠、エクスポートレシート、目視確認、確定後のオープンを使用する場合は `references/delivery-contract.md` を読みます。

## Viewerの任意機能

生成されたHTMLには、テーマ切り替え、パン／ズーム、検索、フォーカス、関係トレース、意味ビュー、プレゼンテーション、正確なエクスポートがすでに含まれています。これらは閲覧者向けの機能であり、追加のオーサリング作業ではありません。`meta.animation: "trace"` は任意指定です。`meta.views` は任意で、厳選したチャプターを最大5つ含めます。

ユーザーがShare Card、Route/Reachカード、アニメーション、ガイド付きストーリー、ディープリンク、プレゼンテーション、検索／フォーカス、その他のViewer Runtime機能を明示的に求めた場合にのみ `references/viewer-runtime.md` を読みます。

## セットアップとフォールバック

Skillパッケージ内でのインストールは不要です。次のコマンドで確認します。

```bash
node bin/archify.mjs doctor
node bin/archify.mjs demo <output-directory>
```

シェルを使用できない場合は、architecture SVGを `assets/template.html` に手動配置し、インラインカラーではなく意味を表すCSSクラスを使用し、`references/delivery-contract.md` の目視確認契約に従います。

## 出力

確認済みHTMLのパス、図の種類、検証結果、仕様／成果物レシートを返します。表示確認を実施した場合のみ、その正確な状況を追加で返します。0以外の終了コードを成功と主張したり、実施していない目視確認を行ったと主張したりしてはいけません。

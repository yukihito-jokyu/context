# 会話からテンプレートを作る

言葉の依頼と、AI から聞く質疑応答で「見た目の決まり」を決めて、`template/<name>/` を作る手順。作ったテンプレートは `init <deck> --template <name>` で使う。
作ったテンプレート（pptx から作ったものも含む）への指摘を受けて直す手順も、5章に書く。

## 目次

1. 依頼を聞く
2. 質問して決める
3. 下書きを作る
4. 見せる
5. 指摘で直す（納得するまで）
6. 仕上げ

## 1. 依頼を聞く

「落ち着いた紺色で、企業向け」のような依頼を受け取る。依頼の言葉から分かることを、2章の観点ごとに書き出す（例：紺色 → 強調の色、企業向け → 落ち着いた印象・飾りは控えめ）。書き出したことは、2章の最初の質問と一緒にユーザーに見せる（違っていれば直してもらえる）。
テンプレートは「どんな中身でも載せられる型」。抽象（型）と具体（中身）の線引きは [pptx からテンプレートを作る](template-from-pptx.md) の1章に従う。依頼に出てきた題材の言葉・数字・ロゴは、テンプレートに入れない。

## 2. 質問して決める

AI が主導して聞く。

- 依頼から分かることは聞かない。足りない観点だけを聞く。一部だけ分かる観点（「ポップ」→ 色は明るいが、地と強調の色は決まっていない など）は、分かった所を前提にして残りだけを聞く。
- 1回に2〜4問ずつ。どの問いにも選択肢（2〜4個）を示し、おすすめを1つ付ける。「おまかせ」でもよいと添える。「おまかせ」と答えられた問いは、おすすめを採る。
- 答えから次に聞くことを決める。全部の観点が決まるまで繰り返す。

| 観点 | 聞くこと | 選択肢の例 | 決まると変わる所 |
|---|---|---|---|
| 印象・雰囲気 | 全体の感じ | 落ち着いた／親しみやすい／力強い／上品 | すべての観点の選び方 |
| 色 | 地・文字・強調の色 | 地は白／生成り／濃い色、強調は1色か2色 | `kit.css` の変数の値 |
| 文字 | 書体の系統と太さ | ゴシック／明朝／丸ゴシック、太め／標準 | `--jp`、見出しの太さ |
| 背景と飾り | 地の作り方と、何度も出る飾り | 無地／うすい模様、帯・線・角丸・影の有無 | `kit.css` の背景と「テンプレートの飾り」 |
| 見出しの位置と余白 | 見出しを置く所と、余白の量 | 左上／中央、余白は広め／標準 | `--safe-*`、見出しの大きさと位置 |
| よく使う構図 | 何度も使う組み立て方 | 表紙・道のり・比較・数字・表・まとめ | シーンの型（見本のシーン） |
| 用途 | どこで使うか | 動画・発表／PPTX専用／両方 | 見本で重く見る所（下の注） |

- 色は、変数の**名前**（`--cyan` など）を役割の名前として扱い、**値**だけを決める。`--cyan` は「主役・強調」、`--coral` は「問題・注意」、`--yellow` は「補足」、`--green` は「解決・良い点」の色にする（紺が主役なら `--cyan` に紺を当てる）。
- 書体は手元にあるもの（ヒラギノなど）から選ぶ。フォントのファイルは足さない。選択肢を示す前に、手元にある書体と太さを確かめる（macOS は `/System/Library/Fonts`。たとえばヒラギノ丸ゴは W4 だけなので「丸ゴシック＋太め」は機械的に太らせた字になる）。
- 用途が PPTX専用なら、`deck-pptx/` の見本と、`pptx` で書き出したときに図形にできず画像になる要素を重く見る（重ねた飾りは画像になりやすい。`#composition` の模様の背景は、スライドの背景が背景色だけになるので PPTX では出ない）。用途にかかわらず、`deck/` と `deck-pptx/` の見本は両方作る。用途が依頼から推し量れるとき（勉強会 → 発表 など）は聞かずに、まとめの表で確かめる。
- 字幕の帯の見た目は聞かない。決めた色・飾りに合わせて AI が決め、まとめの表に書く。
- 全部が決まったら、決めたことを短い表（観点 → 決めたこと）にまとめ、テンプレートの名前（英数字と `-`、例 `navy-report`）と一緒に示して確かめる。直す点があれば直してから3章に進む。

## 3. 下書きを作る

`template/default/` を写して、見た目に関わるところだけ変える。章バーは default だけの部品なので、写したら外す（雛形 `deck/index.html` と見本帳 `index.html` の `#composition` を `data-chapter-bar="off"` にし、`kit.css` から章バーの見た目を消す）。`check` は雛形に従い、このテンプレートのデッキには章バーを求めない。字幕の帯は残す。

```bash
cp -R template/default template/<name>
```

| ファイル | 変えること |
|---|---|
| `motion/kit.css` | `#composition` の変数の**値**（名前は変えない。部品と実行系がこの名前を使う）、`--jp`、背景、字幕の見た目。章バーの見た目（`.md-chapters`・`.md-chapter*` の規則）と、章バーだけが使う変数 `--track` は消す。部品の形（枠・影・角丸・文字の太さ）の違いは末尾の「このテンプレートの上書き」に、新しい飾りと構図の組み立て用のクラスは「テンプレートの飾り」にまとめる |
| `motion/kit.js` | 変えない |
| `deck/` | 2章で決めたシーンの型ごとに1シーンの見本デッキ。文章は新しく書き、依頼の題材に寄せない。`script.json` の `title` も変える。`index.html` の `#composition` は `data-chapter-bar="off"` |
| `deck-pptx/` | PPTX専用の見本（必ず作る）。`deck/` と同じシーンの型を、動きを使わない完成した1枚で書く（[シーンの書き方](authoring.md)の1）。`script.json` の `"format": "pptx"` は残す |
| `style.md` | 1〜4章（骨格・色と文字・部品・シーンの型）をこのテンプレートの決まりに書き直す。冒頭の題と前書き、6章「やらないこと」の default の色の意味（青＝主役 など）もそろえる |
| `index.html` | 見本帳。見出しの「default」をこのテンプレートの名前にする。構図の `<section>` と `CATALOG` の `c-*` を、このテンプレートのシーンの型に入れ替える（見本帳の字幕に文の名前はないので `data-at` は番号で書く）。部品の見本 `d-*` は残し、default の題材に寄った中身（音声合成の名前と数値、Go のコードなど）は題材を選ばない中身に書き換える。飾りがあれば見本（`d-decor`）を足す（飾りがなければ足さない）。`#composition` は `data-chapter-bar="off"` |

- 模様や飾りは CSS や SVG で描く。絵を使うときは `motion/assets/` に置き、`url("assets/…")` で読む。
- 部品（`.card` `.tile` `.code` など）は消さない。どのテンプレートでも同じ部品が使える。
- 構図の箱の高さを px で決めない。字幕の帯のある通常版と、帯のない PPTX専用版（`--safe-bottom` が小さい）で使える高さが違う。見出しと構図を `position: absolute; inset: var(--safe-top) var(--safe-x) var(--safe-bottom)` の縦の flex で包み、のこりの高さを使う部分を `flex: 1` にして、どちらでも下の余白まで伸ばす。`pre`（`pre.code`）は既定の上下の余白があるので、構図に入れるときは `margin: 0` にする。
- PPTX で画像になる CSS（`transform` での拡大・回転、SVG の線、模様の背景など。[プレイヤーと書き出し](player.md)の `pptx`）は、構図や強調の見た目に使わない。線は四角形で描く。
- `data-anim` を付ける要素と、`data-active` で見た目が変わる要素は分ける（実行系が `opacity`・`transform` を上書きするため）。外側の箱に動きを、内側に `data-active` を付ける。
- 同じシーンを `deck/`・`deck-pptx/`・`index.html` の3か所に書くので、`deck/` を先に書き、ほかの2つはそこから写して直す（動きの属性を外す・`c-` を付ける）。シーンが多いときは、作業フォルダに1つの元を置いて3つを作るスクリプトにしてもよい（スクリプトはテンプレートに入れない）。

## 4. 見せる

見本デッキはスキルの外の作業フォルダに作る（コミットしない）。

```bash
node scripts/motion.mjs init <作業フォルダ>/sample --template <name>
node scripts/motion.mjs still <作業フォルダ>/sample --cues --subtitles 0
node scripts/motion.mjs init <作業フォルダ>/sample-pptx --template <name> --format pptx
node scripts/motion.mjs still <作業フォルダ>/sample-pptx
```

PPTX専用のデッキは動かないので、`--cues` を付けても付けなくてもシーンごとに1枚（各シーンの最後の状態）になる。

1. 一覧画像（各デッキの `out/stills/contact.png`）を Read で見て、2章で決めたこと（色の役割・文字・背景と飾り・見出しの位置と余白）どおりか、章バーがないか、崩れ・重なりがないかを確かめる。`--cues` の絵は文の終わりなので、消える途中の要素が半透明に写ることがある（崩れではない）。下が空いていないか（内容が下の余白まで届いているか）は、縮小した一覧では見誤りやすいので、各シーンの最後の静止画を1枚ずつ見て、内容の下の端と `--safe-bottom` の位置を比べる（`check` も、下が使える高さの4分の1以上空いたシーンを「注意」で知らせる。中央寄せの構図は除く）。違えば2に進む前に直す。
2. ユーザーに見せる。見本帳（`template/<name>/index.html`。開いてもらうか、Chrome を画面なしで使って撮った画像）と、2つの一覧画像を渡す。見本帳は縮小画像を遅れて読むので、撮るときは読み込みを待つ（例：`"<Chrome>" --headless=new --hide-scrollbars --allow-file-access-from-files --window-size=1440,3000 --virtual-time-budget=20000 --screenshot=<作業フォルダ>/catalog.png "file://<motion-deck>/template/<name>/index.html"`。高さは構図の数に合わせる）。
3. 気になる所を、自由な言葉で言ってもらう。

`deck/`・`deck-pptx/` を直したら、作業フォルダの見本デッキを消して `init` からやり直す（`init` は雛形を写すので、既にあるデッキには届かない）。`kit.css` だけを直したなら `runtime <作業フォルダ>/sample` で足りる。

## 5. 指摘で直す（納得するまで）

4章で見せたあとの指摘も、仕上げたあとのテンプレートや pptx から作ったテンプレートへの指摘も、この章で直す。ユーザーが納得するまで繰り返す（回数の上限はない）。

1. 指摘を、見た目の決まりに言い換える。

   | 観点 | 指摘の例 | 言い換え（直す所） |
   |---|---|---|
   | 色 | 「もう少し明るく」「強調が目立たない」 | 地・強調の変数の値（`kit.css`） |
   | 文字 | 「見出しが弱い」「堅すぎる」 | 見出しの太さ・大きさ、書体の系統（`kit.css` の上書き、`--jp`） |
   | 背景 | 「のっぺりしている」 | 地の作り方（単色・うすい模様） |
   | 飾り | 「カードが子どもっぽい」 | 枠・影・角丸の太さと形（「このテンプレートの上書き」） |
   | 骨組み | 「窮屈」「見出しが離れすぎ」 | 余白（`--safe-*`）、見出しと本文の間 |
   | 構図 | 「比較の画面がほしい」 | シーンの型を足す・入れ替える（`deck/`・`deck-pptx/`・`index.html`、組み立て用のクラスは `kit.css` の「テンプレートの飾り」、`style.md` の4章） |

   「よく見られている動画に学んで」のように参考を調べて構図を足すときは、出典（URL）と抜き出した型を作業フォルダに書き残し、型（配置と出る順番）だけを取り込む。チャンネルや作品の名前・ロゴ・キャラクター・固有の見た目は入れない（[pptx からテンプレートを作る](template-from-pptx.md)の1章の線引き）。
2. 具体化しない。指摘が1つの資料の中身（特定の言葉・数字・ロゴ・1枚だけの配置）に寄っているときは、どんな中身にも効く決まりに言い換える。言い換えられないものはテンプレートではなく、そのデッキの `theme.css` や `index.html` で直すよう伝える。
3. 言い換えた内容を短く示して確かめてから直す。指摘がそのまま決まりになるとき（「飾りを無くして」など）は確かめを省いて直し、言い換えを見せるときに添える。決まりを変えたら、関わるファイルをそろえて直す：`kit.css`、`style.md`（決まりの説明）、見本（`deck/`・`deck-pptx/`・`index.html`）。
4. 4章の手順で撮り直し、Read で確かめてから見せる。
5. 仕上げたあとのテンプレートを直したときは、そのテンプレートを使う既存のデッキ（`script.json` の `"template"` がこの名前）ごとに `runtime` で `motion/` を配り直し、`check` する。`runtime` が配るのは `motion/`（`kit.css` など）だけで、`deck/`・`deck-pptx/` の変更は既存のデッキに届かない。デッキの場所が分からなければユーザーに聞く。

   ```bash
   node scripts/motion.mjs runtime <デッキ>
   node scripts/motion.mjs check <デッキ>
   ```

## 6. 仕上げ

[pptx からテンプレートを作る](template-from-pptx.md) の6章に準じる。

- `node scripts/motion.mjs check <作業フォルダ>/sample` と `check <作業フォルダ>/sample-pptx`（`--format pptx` の見本）が、どちらもエラー 0 件。見本は声を作らないので、通常の見本に出る「仮の尺」「narration がない」の注意は気にしない。
- `node scripts/motion.mjs pptx <作業フォルダ>/sample-pptx` で書き出し、最後の「図形にできず画像にした要素」の一覧を見る。図形にできる範囲（[プレイヤーと書き出し](player.md)の `pptx`）で同じ見た目にできるものは `kit.css` を直し、画像のまま残すものはユーザーに伝える。通常の見本（`sample`）を書き出すと、強調の移動（`data-active`・`data-focus`）や `follow` の所は「差分の重ね」の画像になる。これは書き出しの仕組みどおりなので直さず、伝えるときに添える。
- 見本帳（`template/<name>/index.html`）を開いて、部品と構図が崩れていないか、章バーがないかを見る。
- 具体化していないか確かめる。依頼の題材の言葉・数字・ロゴが入っていないか、1つの資料にしか合わない配置になっていないか。
- 2章で決めたことと、決めたけれど入れなかったもの（理由も）をユーザーに伝える。仕上げたあとも、指摘があれば5章で直せる。

# プレイヤーと書き出し

## プレイヤー（index.htmlをブラウザで開く）

Remotion Studioに倣った構成。中央にステージ（1920×1080を画面に合わせて縮小）、下にスクラブバーと操作、`T`でタイムライン（章・シーン・文のトラック）。
右下の「動画 / 発表」か`P`で、2つのモードを切り替える。切り替えても同じシーンの同じ文の位置に留まる。

### 動画モード（既定）

ナレーションの音声が時計。音声に合わせて自動で進む。書き出すMP4と同じ。

| キー | 動作 |
|---|---|
| Space / K / ステージのクリック | 再生・一時停止 |
| ← / → | 1フレーム（Shiftで1秒） |
| J / L | 5秒戻る・進む |
| ↑ / ↓ | 前の文・次の文の頭へ |
| PageUp / PageDown | 前・次のシーンへ |
| 0〜9 | 全体の0〜90% |
| M / < > | ミュート・再生速度（0.5〜2倍） |

### 発表モード（`?mode=live` か `P`）

人が1ステップずつ動かす。1ステップ＝原稿の1文。ナレーションは既定でオフ（話すのは本人）で、`V`か「ナレーション」ボタンでオンにできる。

| キー | 動作 |
|---|---|
| → ↓ Space Enter PageDown / ステージのクリック | 次のステップを動かして止まる。動いている途中なら、そのステップの終わりへ飛ばす |
| ← ↑ Backspace PageUp / 右クリック | 前のステップへ（すぐに戻る） |
| 数字＋Enter | そのステップ番号へ |
| V | ナレーションのオン・オフ |
| M | ミュート（ナレーションがオンのとき） |
| N | 発表者ビューを開く |

- **ナレーションをオンにすると**、クリックごとにその文の音声（動画と同じ録音）が流れ、ステップの長さも読み上げの長さに延びる（動きは読み上げに合わせて進み、読み終えたところで止まる）。途中でクリックすると音声も止めてステップの終わりへ飛ぶ。オフにすると約1秒の短いステップに戻る。切り替えても今のステップ番号は変わらない。
- ナレーションは音声のあるシーンだけ。仮の尺のシーンと、音声を作っていないデッキではオンにできない（ボタンが押せない）。
- 開いた直後は最初のステップが出た状態なので、最初の文は読み上げられない。最初から聞かせたいときは`Home`のあと→。
- 設定はブラウザごとに覚える。URL の`&narration=1`／`&narration=0`で開くときに指定できる。
- プレゼン用のリモコン（PageUp/PageDownを送るもの）でそのまま操作できる。
- 全画面（`F`）で発表中は、マウスを動かさなければ操作バーが隠れる。
- 字幕は既定で消える（`C`で出せる。モードごとに覚える）。
- 下の操作バーにステップ番号と、最初に進めてからの経過時間が出る。

**発表者ビュー（N）**: 別ウィンドウに、今話すこと（今の文）、次のクリックで出ること（次の文。シーンが変わるときはその名前）、原稿の`note`・`notes`、そのシーンの台本（済み・今・次を色分け）、経過時間、前へ・次へのボタンを出す。ウィンドウ側でもキー操作が効くので、2画面の発表ではこのウィンドウを手元に置き、本体を投影側で全画面にする。

### 共通

| キー | 動作 |
|---|---|
| P | 動画 ⇄ 発表 |
| [ / ] | 前・次のシーンへ（発表ではそのシーンの最初のステップ） |
| Home / End | 先頭・末尾 |
| B / W（. / ,） | 画面を黒・白にする（もう一度で戻る） |
| C / T / F / ? | 字幕・タイムライン・全画面・ショートカット一覧 |

- スクラブバーは章ごとに色分け。白い線はシーンの境目、発表モードでは細い印が各ステップ。
- 一時停止すると URL が`#f=フレーム`になる。`?mode=live`・`&narration=1`・`?timeline=1`と組み合わせて開ける。
- 字幕・速度・ミュート・モード・タイムラインの開閉は、ブラウザごとに覚える。
- 動画モードの時計は音声。長く再生してもずれない。音声の読み込み前は壁時計で進み、届いたら合流する。
- 問題（存在しない文番号、`Motion.scene`や部品の例外、音声の読み込み失敗）は右上の赤い枠に出る。

## 書き出し用の表示（?render=1）

`index.html?render=1&frame=N`で開くと、UIなしのステージだけになり、`window.__motion`が使える。`check`・`still`・`render`はこれをヘッドレスChromeで操作している。

| 名前 | 内容 |
|---|---|
| `__motion.seek(frame)` | そのフレームを描き、フォントと画像の読み込みを待つ（Promise） |
| `__motion.lint()` | 今の画面のはみ出し・切れ・重なり・字幕の帯・CSSアニメーション |
| `__motion.errors` | 起動時と描画中の問題 |
| `__motion.scenes` `fps` `width` `height` `totalFrames` | 時間軸 |
| `__motion.stops` `mode` | 発表モードで開いたとき（`&mode=live`）のステップ |
| `__motion.features()` | 備わっている機能の申告（`check`が必須項目を照合する） |

`&subtitles=0`で字幕なし。`&mode=live`で発表モードの時間軸（`still --live`と`check`が使う）。

## コマンドのオプション

`still`:

| オプション | 意味 |
|---|---|
| （なし） | 各シーンの終わり（退場の直前）を1枚ずつ |
| `--cues` | 各文の終わり（次の文の直前）を1枚ずつ。動きの確認に |
| `--live` | 発表モードの各ステップを1枚ずつ（字幕なし）。配布資料にも |
| `--frames 0,90,300` | 指定のフレーム |
| `--scene id,id` | シーンを絞る |
| `--out dir` / `--no-contact` / `--subtitles 0` | 出力先 / 一覧画像を作らない / 字幕なし |

出力は`out/stills/<フレーム>-<シーン>.png`と`contact.png`（3列の一覧）。実行のたびに前の静止画は消える。

`render`:

| オプション | 既定 | 意味 |
|---|---|---|
| `--out` | `out/<フォルダ名>.mp4` | 出力 |
| `--concurrency` | CPU数の半分（最大4） | 同時に撮るタブの数 |
| `--from` / `--to` | 全体 | フレームの範囲（音声も合わせて切る） |
| `--scale` | 1 | 0.5で960×540（確認用） |
| `--crf` / `--preset` | 18 / medium | H.264の画質・速さ |
| `--quality` | 92 | 途中のJPEGの画質 |
| `--subtitles 0` | 字幕あり | 字幕を焼き込まない |
| `--allow-estimated` | — | 仮の尺のシーンがあっても書き出す（無音になる） |

`pptx`:

- 発表モードの時間軸で、各ステップ（＝クリック）を撮って PowerPoint にする。1シーン＝1スライド。
- 各スライドは「背景の絵（そのシーンで最初から出ているもの）」と「現れる要素の絵（透明）」で組み、要素にはクリック順に PowerPoint のネイティブのアニメーションを付ける。シーンの最初の文の動きは、スライドが始まると自動で動く。
  - `up`→フロートイン、`down`→下降、`left`/`right`→横からフロート、`scale`/`zoom`→ズーム、`pop`→弾むズーム、`fade`/`blur`/`count`→フェード、`draw` `wipe` `grow` `type` `words` `highlight` `strike`→左からワイプ、`grow-y`→下からワイプ、`wipe-down`→上からワイプ。遅れ（`data-delay`・`data-stagger`）はそのまま効果の遅れになる。
  - `data-until`で消える要素は、フェードの終了効果になる。
- 背景＋現れる絵の重ね合わせが本物の絵と一致するかを1ステップずつ確かめ、合わない範囲（強調の移動、`follow`、カメラ、`Motion.scene`の独自の動き）は、その範囲だけ本物の絵を切り出してフェードで重ねる。見た目は必ずブラウザの発表モードと同じになる。
- 見た目が変わらない文はクリックにしない（前のステップに続けて読む）。
- シーンの切り替えは PowerPoint の画面切り替え（フェード・プッシュ・ワイプ・ズーム・円・ホイール）になる。
- ノートには台本を「【スライド開始】」「【クリック n】」の区切りで入れ、文の`note`・シーンの`notes`も入れる。
- 要素は絵なので、PowerPoint で文字を直すことはできない。直すときは HTML を直して書き出し直す。音声は入れない（ナレーションは動画モードか MP4 で）。
- `--out`で出力先（既定`out/<フォルダ名>.pptx`）。`MOTION_DEBUG=1`で、ステップごとの判定（現れる・消える要素の数、合わない範囲）を出す。

`bundle`:

- CSS・JS・フォント・`img`/`source`/`video`の画像・CSSの`url()`・音声をbase64で埋め込み、`dist/<フォルダ名>.html`を作る。メールやチャットで1ファイルを渡せる。動画・発表の両方のモードが使える（`?mode=live`を付けて開くか`P`）。
- 15分の音声（AAC 128kbps）で約20MB増える。大きすぎるなら`--external-audio`で音声を隣に置く（2ファイルで渡す）。

## 仕組みの要点（改修するとき）

- 発表モードの時間軸は実行系が起動時に作る（`buildLiveLayout`）。文ごとに必要なフレーム数を宣言的アニメーションと部品の`needs`から見積もり、各文の終わりを止まる位置（stops）にする。
- 発表者ビューは`window.open('')`で開いた空のウィンドウを本体から直接組み立てる（同じオリジンになるので`file://`でも動く）。
- `runtime/motion.js`は classic script（ES modules ではない）。`file://`でそのまま開けるようにするため。
- `timeline.js`は`window.MOTION_TIMELINE = {...};`の1行。JSONを`fetch`しないのも`file://`のため。
- 書き出しは各フレームで`__motion.seek(f)`→`Page.captureScreenshot`（JPEG）→FFmpegの標準入力。`requestAnimationFrame`は待たない（裏のタブで止まるため）。
- 各タブは別ウィンドウで開く（`newWindow: true`）。同じウィンドウの裏のタブは描画が止まることがある。
- 実行系を直したら、各デッキで`runtime`を実行して`motion/`を置き換える（古い個別の読み込みもboot.jsの1行に移す）。
- 読み込みは`motion/boot.js`だけが担う。並び（CSS・JS）は`scripts/motion.mjs`の`bundle`（インライン化）と`check`も同じものを使う。
- 機能の保証：`__motion.features()`／`__motionPlayer.features()`がページ自身の機能を申告し、`check`が必須項目（`REQUIRED`と`PLAYER_REQUIRED`）を照合する。さらにプレーヤーとして開いてキーを送り、実際に動くかを確かめる。実行系のファイルはスキルの`runtime/`とハッシュで比べる（`runtimeDrift`）。

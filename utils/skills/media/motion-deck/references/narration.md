# 原稿とナレーション

## script.json

```json
{
  "title": "Goのgoroutine入門",
  "fps": 30, "width": 1920, "height": 1080,
  "voice": "myvoice",
  "engine": "voxcpm2",
  "pause": 350,
  "leadIn": 0.6,
  "tail": 1.0,
  "charsPerSecond": 7,
  "scenes": [
    { "id": "title", "chapter": "はじめに", "duration": 4, "lines": [] },
    {
      "id": "what-is",
      "chapter": "goroutineとは",
      "hold": 0.5,
      "lines": [
        "goroutineとは何かを見ていきます。",
        { "name": "fork", "text": "goと書くだけで、新しい流れが分かれます。", "pause": 700 },
        { "text": "100,000個でも動きます。", "say": "十万個でも動きます。", "note": "実測のスクリーンショットを見せる" }
      ]
    }
  ]
}
```

| 項目 | 既定 | 意味 |
|---|---|---|
| `voice` `engine` | local-ttsの設定 | 声とエンジン。`synth --voice`・`--engine`が優先 |
| `pause` | 350 | 文と文の間（ミリ秒）。文ごとの`"pause"`で上書き |
| `leadIn` / `tail` | 0.6 / 1.0 | シーンの音声の前後の余白（秒）。シーンごとに上書き可 |
| `hold` | 0 | シーン末尾の追加の余白（秒）。最後の図を見せたいとき |
| `duration` | — | 文のないシーンの長さ（秒）。文があるシーンでは最短の長さ |
| `charsPerSecond` | 7 | 音声がないシーンの尺の見積もり |
| 文の`name` | — | `data-at`から名前で参照する。数字・`start`・`end`は不可 |
| 文の`say` | — | 読み上げる文（字幕は`text`のまま） |
| 文の`note` / シーンの`notes` | — | 発表者ビューに出すメモ（読み上げない） |
| 文の`auto` | false | 発表モードで、前のステップに続けてクリックなしで動く |
| 文の`build` | — | 発表モードでのその文の動きの長さ（秒） |

## TTS向けの書き方

- 1文は30〜60文字。長い文は読点で間延びし、時刻の目盛りも粗くなる。300文字を超えると止まる。
- 話し言葉で書く。「〜です。〜します。」。体言止めや箇条書きの羅列は不自然に読まれる。
- 英字は読みを与える。共通の語は`lexicon.json`（`{"goroutine": "ゴルーチン"}`、長い語から置換、英字の境界で一致）、その文だけなら`"say"`。英字が残ると`ssml`・`synth`・`check`がエラーにする（`--allow-latin`で無効化できるが、誤読しやすい）。
- 数字は漢数字かかなに（`100,000個`→`十万個`、`48ms`→`四十八ミリ秒`）。字幕を算用数字にしたいときは`text`を算用数字、`say`を漢数字にする。
- 記号（`→` `/` `※` `&`）は言葉に置き換える。「」『』は読み上げ時に取り除く。
- これらは誤読を減らす方針で、正しく読めた保証ではない。確かめられるのは聞いたときだけ。

## 合成の仕組み

1. `ssml`: シーンごとに`build/ssml/<id>.ssml`を作る。文の前後に`<mark name="cN"/>`・`<mark name="cNe"/>`、文の間に`<break>`を置く。
2. `synth`: `local-tts speak`でシーンごとに`narration/scenes/<id>.wav`と時刻のJSONを作る。JSONの`marks`が各文の開始・終了。原稿・声・エンジン・ttsのハッシュを`motion.hash`に残し、変わったシーンだけ作り直す。
3. `timeline`: 時刻から各シーンの尺（`leadIn`＋音声＋`tail`＋`hold`）と文の開始・終了フレームを計算し、`timeline.js`を書く。全シーンの音声を余白込みで1本につなぎ、`narration/narration.wav`（書き出し用）と`narration.m4a`（プレイヤー用）を作る。
4. 音声がない・原稿が変わって古いシーンは「仮の尺」（文字数÷`charsPerSecond`）になり、その間は無音。プレイヤーに「仮の尺」と出る。

ナレーションは常にlocal-ttsで作る（このスキルでは他の音声合成を使わない）。

## 時間の目安（このMac、M4）

| エンジン | 1文字あたり | 備考 |
|---|---|---|
| voxcpm2 | 約0.33秒 | 既定。メモリ約14GB。初回の読み込み約30秒 |
| omnivoice | 約0.3秒 | メモリ約4GB |
| s2 | 約1.7秒 | 研究・非商用ライセンス |

10分の解説（約4,200文字）はVoxCPM2で約25分。`synth --dry-run`で見積もり、1分を超えるなら目安を伝えてバックグラウンドで実行する。進み具合は`[synth] 時刻 シーン`の行で分かる。

## 不調の対処

| 症状 | 対処 |
|---|---|
| `英字「…」が残っています` | `lexicon.json`に足すか`say`を書く |
| `local-tts スキルが見つかりません` | `--local-tts <フォルダ>`か環境変数`MOTION_LOCAL_TTS` |
| local-ttsが失敗する | エラーの1行目と、local-ttsのSKILL.mdの「気をつけること」に従ってログを見る。原因が分からないまま繰り返さない |
| `時刻の印 cN が音声の結果にありません` | local-ttsが古い（`mark`未対応）か、合成が途中で切れた。そのシーンを`synth --scenes id --force` |
| 音声が古いと言われる | 原稿か`lexicon.json`が変わった。`synth`で該当シーンだけ作り直される |
| 声が途中で変わった | 声・エンジンを変えて一部だけ作り直した。全シーンを同じ設定で`synth`し直す |
| 読み間違い | 原稿の`say`・`lexicon.json`を直して`synth`（そのシーンだけ作り直される）→`timeline` |

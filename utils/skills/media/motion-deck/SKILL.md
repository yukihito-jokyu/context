# motion-deck

ナレーションの一文一文を時間の目盛りにして、HTMLのスライドを動かす。
`<motion-deck>`をこのSKILL.mdのあるフォルダとして、すべて次の形で呼ぶ。

```console
node "<motion-deck>/scripts/motion.mjs" <command> <デッキのフォルダ> [options]
```

## 最初に守ること

1. **見た目は常に[見た目の決まり](references/style.md)に従う。** 「動画」と頼まれても「発表資料」と頼まれても同じ見た目・配置・動きにする。ユーザーはRemotionで作った解説動画の見た目を好んでいて、一般的な箇条書きのスライドは好まない。部品は`motion/kit.css`・`motion/kit.js`のものを使い、新しい見た目を発明しない。
2. **ナレーションは常にlocal-tts。** 他の音声合成やOSの読み上げは使わない。
3. **1つのデッキで「動画」と「発表」の両方になる。** 作り分けない。頼まれた用途は、渡し方（下の6）と報告で区別する。

## Remotionから借りた考え方

これを守ると、再生・シーク・書き出し・発表のどこで止めても同じ絵になる。

1. **画面はフレームの関数。** 見た目は「今のフレーム」だけから決める。CSSの`transition`・`@keyframes`、`setTimeout`、`Date.now()`、`Math.random()`で動かさない。
2. **音声が時間軸を決める。** 要素は秒ではなく「何番目の文で出るか」（`data-at`）で書く。
3. **シーン＝Sequence。** 1つの`<section data-scene>`が原稿の1シーン。時刻はシーンの先頭からのフレーム。
4. **動きは物理と進み具合で。** 出現はばね、伸びる・描く・数えるは補間。場面は重ねて切り替え、視線は寄る・強調で導く。語彙は[見た目の決まり](references/style.md)の「動きの決まり」。部品と`data-*`で足りなければ`Motion.scene`でフレームの関数を書く。
5. **同じコードで再生・発表・書き出し。** 発表モードは、同じ文を「1クリック＝1ステップ」に並べ直した時間軸を実行系が作るだけで、描き方は変わらない。PPTXもこの発表モードの時間軸から作る。

Remotionのコードは使っていない（`runtime/`はこのスキル独自の実装）。取り入れたのは考え方・UI・動きの設計で、それを部品とテンプレートにしてある。

## 手順

### 0. 決める

主題、聞き手、長さ、使い方（発表で使う／動画で配る／両方）、声とエンジンを確かめる。会話から分かることは聞き直さない。
声を指定されなければlocal-ttsの既定の声とエンジン。長さは日本語で**1分あたり約420文字**のナレーションが目安。

### 1. 雛形を作る

```console
node "<motion-deck>/scripts/motion.mjs" init <フォルダ> --title "題名"
```

`index.html`・`theme.css`・`scenes.js`・`script.json`・`lexicon.json`と、実行系`motion/`（boot.js・motion.js・kit.js・kit.css・フォント）ができ、仮の`timeline.js`まで作られる。
`index.html`は`<script src="motion/boot.js"></script>`の1行だけで実行系・部品・テーマ・時間軸を読み込む。この行を消したり、実行系を直接読み込んだりしない。
雛形の6シーン（表紙・道のり・時間の帯・コード・数字・まとめ）は手本の動画の型の見本。中身は書き換えるが、構図と部品の使い方は流用する。`motion/`は編集しない。

### 2. 原稿を先に書く（script.json）

音声が時間軸なので、画面より先にナレーションを決める。書式と書き方は[原稿とナレーション](references/narration.md)。

- 1シーン＝1つの主張。2〜7文、20〜60秒。
- 1文＝画面の変化1つ（発表では1クリック）。後から参照する文には`"name"`。
- 英字・記号は`lexicon.json`か文ごとの`"say"`で読みを与える。数字は漢数字に寄せる。
- 発表で使うなら、話す人向けのメモを文の`"note"`やシーンの`"notes"`に書ける（発表者ビューに出る）。

### 3. シーンを書く

[見た目の決まり](references/style.md)の「シーンの型」から選び、[シーンの書き方](references/authoring.md)に従って書く。

- `<section data-scene="原稿のid">`を原稿と同じ順に置く。
- 要素に`data-at="文番号か名前"`、動きは`data-anim`、途中で消すなら`data-until`、今の項目の強調は`data-active`。
- 部品（`.runner` `pre.code` `.terminal` `.gantt` `.hbars` `.tile` `.card`…）を使う。色は変数、文字は28px以上。
- 画面に原稿を貼らない（字幕と二重）。図・キーワード・数字・コードで「今話していること」を見せる。

### 4. 検査して、見て確かめる

```console
node "<motion-deck>/scripts/motion.mjs" check <フォルダ>
node "<motion-deck>/scripts/motion.mjs" still <フォルダ> --cues
```

- `check`は原稿、HTMLと原稿の対応、存在しない文番号、動画の各文の終わりと発表の各ステップでのはみ出し・切れ・文字の重なり・字幕の帯、CSSアニメーションの混入を調べる。エラー0件まで直す。
- `check`は、デッキに必要な機能が備わっていることも保証する。エラー0件なら次がそろっている。
  - 構成：boot.jsの1行、`main#composition[data-chapter-bar]`、`theme.css`・`scenes.js`、実行系`motion/`がスキルと同じ版（違えば`runtime`で直す）。
  - 機能（ページ自身の申告`features()`）：シーン、テーマ、部品、章バー、字幕、発表の時間軸、トランジション、フォント。プレーヤーとして開いたときの再生バー、タイムライン、動画／発表の切り替え、発表者ビュー、ナレーションの切り替え、画面を隠す、ヘルプ、キー操作。
  - 操作：プレーヤーで実際にキーを送り、→で進む・←で戻る・Pで切り替え・Bで隠す・?でヘルプ・Vでナレーションのオン・オフが動くこと（Vは音声があるときだけ）。
- `still --cues`の一覧画像（`out/stills/contact.png`）を**Readで見て**、手本の動画の見た目になっているか（見出しが左上、太枠と影、余白、色の意味）を確かめる。発表のステップは`still --live`。
- 音声がないシーンは文字数から見積もった「仮の尺」で動く。この段階で動きを詰めてよい。

### 5. ナレーションを作る（local-tts）

```console
node "<motion-deck>/scripts/motion.mjs" synth <フォルダ> --dry-run
node "<motion-deck>/scripts/motion.mjs" synth <フォルダ> [--voice 名前] [--engine voxcpm2|omnivoice|s2]
node "<motion-deck>/scripts/motion.mjs" timeline <フォルダ>
```

- `--dry-run`の目安が1分を超えるなら、**目安を伝えてからBashの`run_in_background`で実行する**（VoxCPM2で1文字約0.33秒＋読み込み約30秒）。
- 原稿が変わったシーンだけ作り直す。声・エンジンを途中で変えると全シーンが作り直しになる（混ぜない）。
- 文ごとの時刻はSSMLの`<mark>`から取るので、文と動きは自動で合う。
- 終わったらエンジンを止める（`synth`の最後に出るコマンド）。続けて作り直すなら残してよい。
- 合成のあと`timeline`で本当の尺にし、もう一度`check`と`still`。
- 発表だけで使う資料でも声を作っておくと、発表モードでナレーションをオンにして流せる（人が話さない場面、練習、配布）。声が要らないと言われたら、このステップは省いてよい。

### 6. 渡す

| 使い方 | 渡し方 |
|---|---|
| 人が発表する | `open "<フォルダ>/index.html?mode=live"`。→・Space・クリック・リモコンで1ステップずつ。`V`でナレーションのオン・オフ（オンならクリックごとにその文を読み上げる。`&narration=1`で最初からオン）。`N`で発表者ビュー（今話すこと・次のクリック・台本・経過時間）。`B`/`W`で画面を隠す |
| 動画として見せる | `open "<フォルダ>/index.html"`（動画モード）。`P`で発表モードと切り替え |
| 1ファイルで配る | `bundle <フォルダ>` → `dist/<名前>.html`（両方のモードが入る） |
| PowerPoint | `pptx <フォルダ>` → `out/<名前>.pptx`。1シーン＝1スライド、1文＝1クリックで、出る・消える動きはPowerPointのネイティブのアニメーション、切り替えも対応、ノートに台本 |
| MP4 | `render <フォルダ>`。1080pで毎秒約70フレーム（このMacの実測） |
| 配布用の画像 | `still <フォルダ> --live`（発表の各ステップのPNGと一覧） |

操作の詳細は[プレイヤーと書き出し](references/player.md)。

## 報告

- 出力の場所、全体の長さ（動画）とステップ数（発表）、シーン数、使った声とエンジン。
- 開き方（発表なら`?mode=live`とキー操作の要点、`N`の発表者ビュー）。
- `check`の結果と、静止画で見て確かめた範囲。
- **音声を聞いて確かめたかどうか。** 聞けないときは試聴してほしい箇所（英字・数字・固有名詞・長い文）をシーンと文番号で挙げる。
- 仮の尺のシーンが残っていればそれを伝える。

## 気をつけること

- 他人の声の扱い、エンジンのライセンス（S2は非商用）はlocal-ttsのSKILL.mdに従う。合成音声を公開するなら、その旨を示すかユーザーに確かめる。
- 文を挿入・削除すると後ろの文番号がずれる。参照される文には`name`を付け、名前で参照する。直したら`check`。
- `timeline.js`・`narration/`・`build/`・`out/`・`dist/`は生成物。手で編集しない。
- 実行系（`runtime/`）を直したら、各デッキで`runtime`コマンドを実行して`motion/`を配り直す。古い個別の読み込みのデッキも、このコマンドでboot.jsの1行に移る。

# ループBGM制作

AIが曲を一発で生成するのではなく、人の作曲手順どおりに設計図を書き、プログラムで音にする。だから同じ設計図は常に同じ音になり、気になる行だけを直せる。楽器音はすべて数式合成なので、素材の権利表記もダウンロードも要らない。

以下 `<skill>` はこのスキルの Base directory を指す。作業はユーザーのカレントフォルダで行い、設計図は `songs/`、音源は `output/` に置く。

## 手順

1. `command -v uv` を確認する。無ければ `brew install uv` をユーザーに提案して止める。Python や numpy は `uv` が自動で用意する。
2. 依頼が曖昧でも、用途から妥当な値を決めて作り始める。一度聴いてもらうほうが、事前の質問より早く好みに近づくため。見本だけ求められたら `<skill>/assets/sample.toml` を `songs/sample.toml` にコピーして書き出す。
3. 新曲は `songs/<曲名>.toml` に、下の「作曲の順番」に沿って書く。書式の実例として `<skill>/assets/sample.toml` を先に読む。
4. 書き出す。

   ```
   uv run <skill>/scripts/render.py songs/<曲名>.toml                  # output/<曲名>/
   uv run <skill>/scripts/render.py songs/<曲名>.toml --style gameboy  # output/<曲名>_gameboy/
   ```

5. 出力の「つなぎ目」「パート別」を読み、下の「音量の確認」に沿って必要なら `gain_db` を直して再度書き出す。
6. 結果を報告する。Claude は音を聴けないので、数値で確認した範囲と、聴いて判断してほしい点を分けて伝える。ループ試聴のコマンドは ``! play output/<曲名>/<曲名>.wav repeat -``（sox が無ければ ``! afplay output/<曲名>/<曲名>.wav`` で1周）。

## 作曲の順番

1. **テンポと調**: 明るい・元気なら BPM 130〜170 の major、落ち着いた解説向けなら 80〜110、切ないなら minor。
2. **リズム**: 打楽器で土台を作る。全パートを同じ拍で打たず、互いの隙間を埋めるように置く。
3. **ベース**: 各小節の頭はルート(`R`)にする。今どのコードかを低音で示す役目があるため。
4. **コード**: `chords` は1小節1個。ループの最後は `5` にすると、曲頭の `1` へ自然に戻る。
5. **メロディ**: 強拍はコードの構成音にする。短いフレーズを繰り返し、後半で少し高く盛り上げ、最終小節は曲頭へつながる動きにする。特定の既存曲の旋律を真似しない。権利を気にせず使えることがこの方式の利点なので、それを損なわないため。
6. **アレンジ**: `copy_of` でオクターブ重ね、句の頭に飾りの音、裏拍に小物など。少なめから足す。
7. **ミックス**: 動画の声に重ねるなら `voice_dip_db = -4` 程度。歌やナレーションが無いなら `0` でよい。`reverb` は 0.03〜0.3 で薄く。

小節数は 8 か 16 が扱いやすい。繰り返しに聞こえにくいのは 16 以上。

## 設計図の書式

- `[song]`: `bpm` `key`(`C` `F#` `Bb` など) `mode`(major/minor) `bars` `beats_per_bar` `seed` `humanize_ms` `chords`(音度で書く。`5` は V、`27` は II7)
- `[mix]`: `target_lufs` `highpass_hz` `voice_dip_db` `voice_dip_hz` `reverb_t60`
- `[parts.<名前>]`: `kind` `instrument` `pattern` `octave` `gain_db` `pan`(-1〜1) `reverb`(送り量)。コードのみ `strum_ms`。`copy_of = "元パート"` で元の設定を継承して上書き。

`pattern` は `|` か改行で小節を区切り、小節内はトークン数で等分する。小節数が曲より少なければ繰り返す。`.` は休符、`-` は前の音を伸ばす。

| kind | トークン |
| --- | --- |
| `drum` | `X` 強 / `x` 中 / `o` 弱 |
| `bass` | コード基準の `R` `3` `5` `7` `8`（オクターブ上） |
| `chord` | `x` 和音全体 / `1` `3` `5` `7` 単音 |
| `melody` | 音度 `1`〜`7`。`'` で1オクターブ上、`,` で下、`#` `b` で半音変化 |
| `ambience` | `pattern` 不要。曲全体で鳴り続ける環境音（`gain_db` のみ有効） |

楽器: `pizz_bass` `pizz_violin` `harp` `xylophone` `glockenspiel` `ocarina` `bongo_hi` `bongo_lo` `tambourine` `woodblock` `bird_warbler` `bird_whistle`（鳥は `kind = "drum"` で、1トークンが一声）

環境音(`ambience`): `stream`（小川） `forest_air`（森の風と葉音）

自然系の曲は、環境音がメロディより 15 dB 以上小さいと聞こえなくなりやすい。`<skill>/assets/forest_stream.toml` が実例。

音度とコード基準で書いているので、`key` `mode` `chords` を変えるだけで全パートが追従する。

## 修正の依頼

修正は該当行だけを編集し、他の行には触れない。パートごとに乱数が独立しているので、他パートの波形はそのまま保たれる（全体の音量合わせで、倍率だけは少し変わる）。

| 依頼 | 編集する場所 |
| --- | --- |
| テンポを変える | `bpm` |
| 長調/短調、キーを変える | `mode` / `key` |
| 楽器の差し替え | そのパートの `instrument` |
| 音数を減らす、控えめに | そのパートの `pattern`、または `gain_db` |
| 雰囲気を別物に | 新しい `songs/<別名>.toml` にコピーして編集し、元の曲を残す |
| ゲームボーイ風 | 設計図はそのままで `--style gameboy` |

ゲームボーイ風の割り振りは、ch1 矩形波=最も音数の多い melody、ch2 矩形波=chord のアルペジオ（他の melody が鳴る間はそちらを優先）、ch3 波形メモリ=bass、ch4 ノイズ=drum を1音ずつ。`copy_of` のパート、環境音、鳥の声は鳴らず、`instrument` `gain_db` `pan` `reverb` も効かない。音色や音量を変えたいときは `<skill>/scripts/bgm/gameboy.py` の冒頭の定数を調整する。

## 音量の確認

耳の代わりに「パート別」の平均 dBFS を見る。見本の曲の値は次のとおり（数値で調整したもので、人の耳での確認はしていない）。

- 通常版: bass -22、melody -24、chords -27、打楽器 -31〜-33、高音の飾り -37〜-38、小物 -42〜-46
- ゲームボーイ風: ch1 -24、ch2 -29、ch3 -24、ch4 -27

メロディより 3 dB 以上強い bass や、飾りより 10 dB 以上小さいパートは、埋もれや出すぎを疑う。ただしこの目安は見本1曲から取ったものなので、音数が大きく違う曲では参考程度に扱う。

「つなぎ目」が要確認になったら、曲末の音を切るのではなく、曲末と曲頭のパターンを見直す。ループは循環処理で成立しているため、後から波形を切ると崩れる。

## できないこと

場面転換用の効果音（SE）の切り出し、鼻歌からのメロディ抽出は未実装。頼まれたら、未対応であることを伝えたうえで、実装するかどうかをユーザーに確認する。

納品は WAV のままにする。MP3 は前後に無音が付き、ループに隙間ができるため。

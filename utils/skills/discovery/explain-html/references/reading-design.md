# 理解に必要な情報から表示を決める

## 説明の設計

最後に理解してほしい仕組み、読者の既知の前提、必要な概念、具体例の開始条件から結果への道筋、常時表示と展開する詳細を制作前に決める。各文章・図・具体物が何を理解させるか確認し、必要なつながりを残して重複を削る。

最初の入口は「全体像」「具体例の動き」「詳細」「条件と例外」「資料」。題材に応じて関心別ページを追加し、同じHTML内で選択したページだけ表示する。一般題材の詳細は書類・記録・式・観測値など、技術題材の詳細はコード・設定・ファイル構造を使う。中心的な理由と最小の具体例は担当ページの初期表示に置く。長い全文と追加条件はdetailsに置ける。

各ページは「このページの問い → 必要な前提と図の読み方 → 展開済みの全体図 → 領域の説明 → 個別図・具体物」の順でつなぐ。図前には何を見るか、図後には結果の意味を説明する。各ページを直接開いても必要な前提と主体が分かる文にする。図の動作文、表、出典の説明も[prose-review.md](prose-review.md)で全文を確認する。

## 読む量を先に減らす

各ページの初期表示は、問いへの短い答え1〜2文と、具体例を追う3〜4段階を出発点にする。文章部分は200〜350字程度を目安とし、必要な前提や因果が途切れる場合だけ増やす。字数を満たすために用語を詰め込んだり、重要な条件を隠したりしない。

図と横の説明が同じ内容を重複して説明しない。横の説明は番号ごとに1〜2文とし、本文で同じ手順をもう一度列挙しない。APIの全列挙、全入出力、コード全文、追加の例外は「設定を書く」「依存値が変わらない場合」「失敗する場合」など、読者の目的が分かる閉じたdetailsや関心別ページへ置く。結論を覆す条件や危険な誤解を防ぐ条件は初期表示に残す。

詳細へ移す前に重複と不要な説明を削る。単に長文を丸ごと折りたたむだけで終えず、詳細も一つの問いごとに短く編集する。専門用語は説明する必要が生じた箇所で導入する。資料との対応は保持し、初期表示を短くしたことを題材の確認範囲が狭まったことと混同しない。

確認記録には初期表示の本文字数と詳細へ移した項目を残す。字数は導入と常時見える横解説を合わせて数え、閉じたdetails・コード・図のcaptionを除いた対象範囲を明記する。図横で既に説明した手順を、図の後の問いや本文で繰り返さない。スクリプトの字数・開閉状態検査は読む量を確認する補助であり、理解できることや読む労力の小ささを証明しない。人間に確認するときは、採用済みの文字組みで実際の短い本文を提示する。

## 文字と配色

白に近い暖かい背景、淡い面、濃いグレーの文字によるClaude風のライト配色に固定する。OS設定で黒へ切り替えない。generative-claude-uiが利用できる場合は部品・型選択・トークンを参考にするが、すべての機能を移植したとは扱わない。

| 役割 | 基準 |
| --- | --- |
| 中心的な仕組みの短い答え | 26〜30px / 500 |
| ページ見出し | 28px前後 / 500 |
| 節・具体物の見出し | 22〜25px / 500 |
| 本文 | 19px / 行間1.85 / 400 / #3f464b / ゴシック |
| 図・UI・出典 | 18〜19px |
| コード | 17〜18px / 行間1.8 |

通常文字のコントラスト比は4.5以上。小さい注釈や凡例で情報量を増やさず、必要な説明は本文の大きさで表示する。太さ400/500、余白、薄い罫線で階層を示す。背景は結論・条件・コードなど区切る理由がある領域に使う。既存UIスキルの標準文字サイズより、読者の大きく読みたい指定を優先する。

本文は約760px、図と具体物は約1120〜1220pxを基準とする。狭い画面でも本文は縮小しない。図は幅100%、最小幅0を基本に全体を表示領域へ収める。読めないほど文字が小さくなる場合は元モデルの余白や構成を見直し、理解の段階ごとに分割する。画像の最小文字を一定pxにするためだけに巨大な固定幅を計算し、初期表示を横スクロールにしない。「文字を読む大きさ」と全体表示を切り替える操作は標準で追加しない。原図へのリンクは残す。ページ全体は横にはみ出させない。コードは意味のある単位へ分け、必要な部分だけ横スクロールする。

## 閲覧と動き

共通領域には題材、確認範囲、関心・ページ選択を残す。ページ数が多い場合は関心グループに分け、選択したグループのページだけをナビへ表示する。現在位置をaria-currentで示し、名前付き前後リンク、直接ハッシュ表示、再読込、戻る・進むを同期する。深いリンクは担当ページと祖先detailsを開き、対象へフォーカスとスクロールを移す。連続操作では最後に選んだ移動先を表示する。

移動元、切替、到着位置を短い強調と「移動元 → 到着先」の文字で案内する。prefers-reduced-motionでは移動を止め、現在位置と到着枠を残す。段階再生は[flow-motion.md](flow-motion.md)に従い、実経路に沿う有限の線分と、図・本文・具体物の段階を同期する。分類図に時間順を捏造しない。

JavaScript無効では全ページと静止図を読めるようにする。印刷では全ページと閉じた補足も表示し、ナビと再生操作を印刷しない。外部ライブラリ、フォント、画像を表示の必須依存にせず、CSS・必要なJavaScript・図をHTMLへ含める。

## 組み立て入力

`scripts/render_html.py page-model.json output.html --manifest diagram-agent-manifest.json`は同梱テンプレートにナビと段階再生のJavaScriptをインライン化する。page-model.jsonは次の構造を持つ。HTML断片は制作者が根拠から作成した信頼できるマークアップであり、未加工の外部入力を渡すAPIではない。TITLEとSCOPE、ページ名はスクリプトがエスケープする。body_htmlにコードを入れる制作者は`&`・`<`・`>`をエスケープする。

```json
{
  "title": "題材名と理解する問い",
  "scope": "対象資料、版または確認日、確認範囲",
  "groups": {"start": "理解する", "reference": "根拠を確認する"},
  "pages": [
    {"id": "overview", "label": "全体像", "group": "start", "intro_html": "問い、短い答え、図を読む前提", "overview_html": "展開済みの全体図と読み方、詳細への入口", "body_html": "個別説明と具体物"}
  ]
}
```

各ページのoverview_htmlは`data-concern-overview="ページID"`のコンテナ、figure、読み方の説明、詳細へのハッシュリンクを持つ。図はArchifyのeditorial標準エクスポート画像をdata URIのimgで埋め込み、`data-archify-model-sha256`にモデルのSHA-256、`data-archify-preset="editorial"`、`data-archify-export`に出力経路を設定する。仕組みを説明する追加ページにも全体図を置く。出典・確認日・検査範囲の列挙だけなら、overview_mode="text"と具体的なoverview_reasonを設定し、図の代わりに短い案内と詳細リンクを持たせる。順序・因果・分岐・状態・包含の説明を文字だけへ変えるためには使わない。標準画像の背景・グリッド・凡例・記号・viewBox・文字・配色を変更しない。

図上のリンク領域は標準SVGのノード枠とviewBoxから求め、推測で配置しない。本文にも詳細リンクを置き、視覚とキーボードの両方で移動できるようにする。原図・モデル・配布レシート・画像化レシートを保存し、ブラウザでのエクスポートと補助SVG処理を区別する。

ユーザーが拡大操作を求めた場合だけ、同梱ナビのfigure内の`data-diagram-zoom`ボタンを使える。初期hidden、type="button"、aria-pressed="false"を付ける。通常の成果物にはボタンを置かず、原図へのリンクを残す。拡大を加える場合も初期表示は図全体とし、標準画像と同じ比率を保ち、画像内の文字や配色を変更しない。

コード表示にはcode-panel → code-heading + code-lines → code-lineの構造を使う。code-lineのcodeへエスケープした元の行を入れ、元の字下げを保持する。行番号はaria-hiddenのspanとdata-lineで表示する。各行の固有IDへ本文・図からリンクする。DOMの再保存で空白が変わる場合は実ソースと照合する。

組み立て、全体図検査、項目対応検査の成功だけで内容の正しさ・一次資料からの取りこぼし・読みやすさを証明したとは扱わない。内容レビューと実ブラウザ確認を分けて記録する。

## 標準図と横解説を組み込む

同梱テンプレートの `archify-pair` 内に `archify-figure` と `archify-notes` を置く。図は350pxを出発点に、狭幅では利用可能な幅まで収める。350pxを全モデルの可読性保証とせず、元担当が実際の掲載幅で確認する。図の意味やSVGは変更せず、主図は常時表示、同じ担当の局所投影は何を確かめるか分かる閉じたdetailsへ置ける。

各主図・局所投影では、同じ `data-archify-variant` のコンテナへfigureと対応するasideを一緒に置く。各figureの標準画像とcaptionを保ち、必要な範囲説明を横解説から切り離さない。型の補助記号は核心ラベルと分けて実寸を記録する。小さい補助記号を隠したり、検証点数だけで可読性を合格にしたりしない。

統合後はPCと390px幅で再確認する。図へスクロールした位置で、figure内の見出し・図・必要captionが画面高に収まるか測る。ページ見出しを含む位置とは区別する。統合先CSSが見出しを大きくする場合はHTML側の配置を直し、標準SVGの切抜きや文字縮小で解決しない。局所投影も統合先の実際の縮尺を確認し、担当の単独確認だけを記事全体の確認と報告しない。

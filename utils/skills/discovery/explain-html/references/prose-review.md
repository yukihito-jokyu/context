# 読者が主体を推測しないための文章レビュー

HTMLの説明文をすべて確認する。確認対象は本文、図の動作文、図の説明、表のセル、展開後の補足、条件と例外、資料の説明。見出し、ファイル名、値、ナビのページ名などの名詞ラベルは、文の主語がないことと区別する。

## 合格条件

- 動作を書く文には、誰が／何が動くかが明記されている。
- 読者は、動作の対象、入力、結果を文から特定できる。
- 条件文には、条件の主体と結果の主体が書かれている。
- 主体が変わる文では、書き手が切り替わった主体を明記している。
- 「これ」「その」「どちらも」などの指示語が、主体や対象の具体名の代わりになっていない。
- 各ページ・詳細を直接開いても、その文章の前提が分かる。
- 前の文が示す情報を次の文が受け、原因から結果へ説明がつながっている。
- 説明が「用途に。」などの未完の文で終わっていない。

## 確認の手順

1. 書き手は、ページごとに表示文章を抜き出す。コード本文は対象外だが、コードに添えた説明は対象にする。
2. 書き手は、各動作文について「主体 → 動作 → 対象・結果」を確認記録へ書く。複数の主体が動く文は主体ごとに記録する。
3. レビュー担当者は各ページと各詳細を直接読んだ状態で確認する。前のページを見たはずだという前提で合格にしない。
4. レビュー担当者は、曖昧な指示語、主体の省略、主体と動作の不一致、切れた因果を指摘する。書き手は、主語だけを機械的に足さず、文を分けたり順番を変えたりして説明を再構築する。
5. 書き手またはレビュー担当者は、修正後の全文を再確認し、確認範囲・修正文・残る問題を記録する。

## 修正例

修正前：「denyを返すと後続へ渡さず終了します。」

修正後：「Modの関数がdenyを返すと、Claude CodeはBashの実行を止めます。」

Modの関数が値を返し、Claude Codeがツール実行を止める。二つの動作を一つの省略した主体へまとめない。

修正前：「チェック・整形・通知など、設定から処理を呼び出す用途に。」

修正後：「チェック・整形・通知を行うスクリプトを持つ開発者は、Hooksの設定からそのスクリプトを呼び出せます。」

読者は、誰が何をしたい場合にHooksを使えるかを判断できる。

## 判定の限界

「は」「が」の有無だけでは、動作の主体が適切かは判定できない。自動抽出は確認漏れの防止に使い、意味の確認は文章レビューで行う。レビューを実施していない文章に合格を付けない。

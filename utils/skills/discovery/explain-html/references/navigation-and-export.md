# 図から詳細へ移動する契約

読者は移動前に全体図の位置を見て、移動後に選んだ項目の説明を見る。制作者は入口と到着位置を結びつけ、読者が「どこから、どこへ」を追えるようにする。

- 制作者は全体図のノードにHTMLリンク領域を重ねる。リンク領域の位置はエクスポートSVGの実際のノード枠とviewBoxから算出し、画像表示の比率と合わせる。制作者は推測した座標を置かない。
- 制作者はリンクに内容を表すaria-labelを付ける。リンク先の見出し、個別図、コードには安定した固有IDを使い、キーボードフォーカスも示す。
- 読者が入口を選ぶと、UIは入口を約140ms強調し、別ページへの切替を約360msで示す。UIは到着箇所を約2200ms、枠と淡い背景で強調する。時間は実処理速度を表さない。
- UIは常時見える読みやすいステータスへ「移動元 → 到着先」を表示する。色や動きだけで移動を伝えない。同じページの移動、戻る・進むでも現在位置を更新する。
- UIは対象が閉じたdetails内にある場合、祖先のdetailsもすべて開いてから、対象へスクロールとフォーカスを移す。コードの各行へのリンクでも同じ契約を守る。
- UIは連続クリックで古いタイマーとアニメーションを取り消し、最後の移動先だけを反映する。URLハッシュと表示を同期し、hashchangeとpopstateによる重複遷移を防ぐ。
- UIはreduced-motion設定で移動するアニメーションを止め、到着枠と移動先の文字を残す。設定変更やタブ非表示の時点に保留中の移動がある場合、UIは読者が選んだ移動先を確定してから動きを止める。保留中の選択を失わない。
- UIは修飾キー付きクリックや新規タブ操作を標準のリンクとして扱う。JavaScript無効と印刷では全ページを読めるようにする。

標準画像の静止画は常に残す。制作者が流れを動かす場合、制作者は元の接続線に沿う短いパルスと、現在の主体・値の強調を重ねる。画像の文字や配色を変更しない。経路の位置を標準出力から求められない場合、制作者は誤った線を動かすより、段階別の強調を使う。詳細な再生契約は[flow-motion.md](flow-motion.md)を読む。

制作者は原図へのリンク、元モデル、配布レシート、画像出力経路とハッシュを保存する。単体HTMLではSVG/PNGをdata URIへ埋め込む。原図とモデルは追加の監査用成果物であり、単体HTMLの本文を読むための依存ファイルにはしない。

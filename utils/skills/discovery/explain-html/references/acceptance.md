# 納品前の確認

制作者は自動検査の通過と、読者の理解に対する内容レビューを分けて記録する。制作者は図の存在やリンク数だけで理解しやすいと判定しない。

| 確認する関心 | 合格する状態 |
| --- | --- |
| 情報の網羅 | 制作者は一次資料の見出し・表・API・設定・既定値・条件・失敗・例外から説明先へ逆照合した。名前やURLだけの項目を説明済みに数えていない。未確認項目は理由とともに残し、全対応と報告していない。 |
| 文章 | 読者は各ページや詳細を直接読んでも、動作主体、対象、必要な前提、原因と結果を理解できる。制作者は全説明文を読み直し、主語が抜けた文を再構築した。 |
| ページ | 読者は選択した関心だけを見て、共通ナビで題材・範囲・現在地を確認できる。図から具体物と詳細へ進める。 |
| 全体図 | 各ページは冒頭に展開済みの全体図と読み方を持つ。図はその関心の主要領域・関係・詳細への入口を覆う。イベント個別図やカード一覧だけでは合格しない。 |
| Archify画像 | 制作者はeditorialモデル、同梱版の検証・配布、標準エクスポートを使った。画像には全viewBox、背景、グリッド、凡例、記号、文字、色が残り、原図と生成経路を確認できる。 |
| コード | 読者は言語、配置、前提、入力、期待結果と図の対応を確認できる。制作者は抜粋・実行例・擬似コードを区別し、コードの生テキストを保持した。一般題材では書類・記録・式・観測値などを示し、コードを強制していない。 |
| 文字と色 | UIは暖かいライト配色を固定する。本文19px、UI18〜19px、コード17〜18px、中心の結論26〜30pxを基準にする。必要な情報を小さい文字へ押し込まない。 |
| 流れの動き | UIは読者の再生操作で短いパルスを実経路に流し、図と説明・具体物の段階を同期する。停止経路から未実行の処理へ進まず、一時停止・段階・リセットを操作できる。 |
| 遷移 | UIは入口、切替、到着枠と「移動元 → 到着先」を示す。深いリンク、祖先details展開、戻る・進む、連続操作、reduced-motion、非表示時の保留先を扱える。 |
| 改修 | 制作者は前版の本文・図・コード・条件・出典を意味で照合し、保持・変更・削除・追加を記録した。見た目の変更を理由に情報を落としていない。 |

## 自動確認

パスはパッケージの位置に合わせる。

```sh
python3 scripts/sync_vendor.py --check
python3 scripts/check_overviews.py /path/to/explanation.html
python3 scripts/check_coverage.py /path/to/explanation.html /path/to/coverage.json
```

全体図チェックは存在・配置・画像属性・入口を確認する。coverageチェックは説明先と状態を確認し、未完了がある場合は非ゼロで終了する。これらのチェックは説明内容の正しさや元資料の取りこぼしを自動で証明しない。制作者は[coverage-review.md](coverage-review.md)と[prose-review.md](prose-review.md)を使って内容をレビューする。検査結果を良くするために未確認を説明済みへ変更しない。

ブラウザが利用できる場合、制作者は広い画面と狭い画面で文字・図・はみ出し・操作を確認する。利用できない場合、制作者は静的確認や模擬DOM実行の範囲を明記する。制作者はブラウザ禁止を別経路で回避せず、未実施の表示や標準PNG一致を確認済みと報告しない。

技術・一般題材の実例を再検証する補助スクリプトは`evals/check-browser.mjs`。実例のtechnical/output.html、general/output.htmlをChrome/Chromiumで読み、広い画面・狭い画面、深いリンク、履歴、有限再生、段階選択、印刷、JavaScript無効時を検査する。生成そのものの依存ではなく、Playwrightが利用できる検証環境で使う。

```sh
node evals/check-browser.mjs /path/to/example-directory
```

別の場所へ導入したPlaywrightは第2引数にモジュールURLを渡す。既存ブラウザを使う場合はCHROME_PATH環境変数へ実行ファイルを指定する。この検査は実例の操作確認であり、新しい題材の正確性・スキルのトリガー精度・生成ベンチマークを証明しない。

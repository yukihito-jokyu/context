# quiz

AIが生成したコードや変更内容について、人間が理解できているか確認する。

## Purpose

- 理解しないままマージすることを防ぐ。
- 表面的な暗記ではなく、判断理由、影響範囲、エッジケースの理解を確認する。
- 変更内容の説明不足を発見する。

## When to Use

- 実装後。
- レビュー前。
- 変更内容を自分が理解しているか確認したいとき。
- AIが大きな変更や複雑な判断を行ったとき。
- `pitch` 後に理解確認まで行いたいとき。

## Inputs

- 実装内容。
- Implementation Notes。
- Pitch / Explainer。
- 重要な設計判断。
- 注意すべきエッジケース。
- 既存仕様への影響。

## Process

1. 変更内容を理解するためのクイズを作る。
2. 文脈、判断理由、影響範囲を問う。
3. 重要な設計判断を問題に含める。
4. エッジケースや注意点を問題に含める。
5. 解答と、理解できていない場合に確認すべき箇所を示す。

## Outputs

- Review Quiz。
- クイズ。
- 解答。
- 理解できていない場合に確認すべき箇所。


## Rules

- 単なる用語確認にしない。
- なぜその実装になったかを問う。
- 変更の影響範囲を問う。
- エッジケースを含める。

## Anti-patterns

- 正誤だけの浅い問題にする。
- 解答を付けない。
- 実装の重要判断を問題から外す。

# 比較図と具体例の選び方

## 問いに合わせて図を選ぶ

| 読者の問い | 図 | 具体物とのつながり |
| --- | --- | --- |
| システムのどこに入るか | 共通のシステム図にAとBの接続点を示す | 対応するモジュール、設定の読み込み元 |
| 誰がいつ動かすか | 同じイベントを起点にした左右のフローまたはシーケンス | 呼び出し箇所、引数、返り値 |
| 何をどこに置くか | 領域ごとの構成図とファイルtree | 実際のファイルパス、設定キー |
| 条件によって結果がどう変わるか | 成功・失敗を追う分岐図 | 条件式、出力値、エラー処理 |
| 内部で何が保持されるか | 状態遷移またはデータ構造の図 | 状態変数、保存形式、更新箇所 |

概要図には比較対象を囲むシステムも描く。詳細図には実際の入口と出口を描く。説明に不要な内部実装は省略し、省略した境界を示す。

## 同じ例を使って比較する

例えば「処理前に入力を検査する」という同じ目的について、Aが実行前の接続点で検査し、Bが処理本体で検査する架空例なら、次の順で対応を作れる。これは特定製品の仕様ではない。

```text
比較の共通入力: { action: "save", target: "sample.txt" }

図① runnerが入力を受け取る → runner が input を受け取る箇所
図② validatorが入力を検査する → validator(input) の関数
図③ runnerが次に進むか判断する → validatorが検査結果をrunnerへ返す箇所
図④ runnerが保存処理を呼ぶ → save(target) の呼び出し
```

AとBで図③の責務が異なるなら、同じ図③の位置で「誰が判断するか」を示す。図に存在しない自動呼び出しをコードの説明で暗黙に補わない。確認できた仕様に合わせて例を作り直す。

検査処理の登録は実行時の入力受信と別の段階である。設定ファイルと読み込み元の対応を構成図で示し、上の実行フローに混ぜない。

## コードの前後で説明する

コードの直前に「どの図のどの段階を実装するか」「どのファイルに置くか」「どの値を受け取るか」を書く。コードの直後に、その入力でどの分岐を通り、何が返るかを書く。

長い実コードは必要な関数・設定に分ける。断片だけで成立しない場合は、省略した依存関係を示す。図とコードで値の名前を変えない。完全な例を求められた場合は、必要な設定と補助関数も示す。

## 詳細を読む導線

次の型選択は、既存の`generative-claude-ui`の型選択・部品カタログと、ステップ式、構造図、シーケンス、比較カード、ナビゲーション、コンテンツ表示の実装を参照して整理している。見た目の種類を増やすためではなく、読者が理解したい関係に合わせて選ぶ。

| 読む段階 | UIパターン | 採用する条件と注意 |
| --- | --- | --- |
| 全体の位置を知る | 構造図・包含図 | 接続点なら構造図、片方がもう片方の一部なら包含図。無関係な選択肢として並べない |
| 両者の動きを見比べる | 左右比較・シーケンス | 同じ段階を同じ位置へ置く。呼び出し主体の違いが核心ならシーケンスを選ぶ |
| 一回の実行を追う | ステップ式・タイムライン | 入力と結果が段階ごとに変わるとき。番号は両者で共通にし、実行されない段階も示す |
| 図から実装を探す | ページ内ナビゲーション・マスター詳細 | 短い例はリンクで足りる。複数の接続点を選びコードと値を同時に見たい場合だけマスター詳細にする |
| 失敗・補足を見る | アコーディオン | 最小コードと中心の違いは畳まない。補足だけを分離する |

ステップ式を使う場合、選択中の段階だけを強調し、対応するコード行と入出力を同時に示す。「次へ」だけでなく段階を直接選べる操作と、全段階の静的な一覧を用意する。処理の順序を学ぶ図に循環アニメーションを付けない。

比較カードは責務・条件の要約に使い、カードの枚数だけで理解させようとしない。図の矢印、境界、時系列が伝える関係を先に設計する。

全体像、実行の流れ、コードの見出しにページ内リンクを設ける。図の識別子から対応するコードの見出しへ移動できるとよい。単なる装飾のクリック操作は追加しない。

核心となる最小コードと実行トレースは、それぞれの担当ページで見える状態にする。長い補足、追加ケース、完全なログはdetailsにまとめてもよい。「さらに詳しく」ではなく「失敗時の返り値を確認する」など中身が分かるラベルを付ける。

## 差を大きく見せすぎない

共通部分も同じ名前と位置で示す。AとBが排他的な選択肢でない場合は、併用できる条件を説明する。根拠がない速度・安全性・優劣を付けない。資料のない相違点は「未確認」とする。

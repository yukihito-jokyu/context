# interview

曖昧な点や「既知の未知」を、人間への質問によって明確にする。

## Purpose

- 回答によって設計や実装が変わる論点を明確にする。
- AIが推測で進めそうな空白を人間の判断へ戻す。
- 質問と回答を仕様、制約、優先順位へ変換する。

## When to Use

- 要件や仕様が曖昧なとき。
- 回答次第でアーキテクチャ、データモデル、UX、作業順が変わるとき。
- `blindspot` 後に、人間の判断が必要な質問が残ったとき。
- ブレストやプロトタイプ後にも決まらない論点があるとき。

## Inputs

- 作業目的。
- 現時点の仕様。
- 未決定事項。
- AIが判断してよい範囲。
- 人間が判断したい範囲。
- 既に得た `blindspot`、`reference`、`prototype` の結果。

## Process

1. 曖昧な点を抽出する。
2. 回答によって影響が大きい質問を優先する。
3. 質問は一度に一つだけ出す。
4. なぜその質問が重要かを説明する。
5. 回答によって変わる設計、実装、成果物を明示する。
6. 回答を受けて仕様、制約、優先順位を更新する。
7. 次の質問へ進むか、次のスキルへ進むか判断する。

## Outputs

- Interview Log。
- 現在確認すべき最重要質問。
- 回答から更新した仕様・制約・優先順位。
- 次に進むスキル。

## Output Format

```markdown
# Interview

## 現在確認すべき最重要質問

質問:
...

## この質問が重要な理由

- ...

## 回答によって変わること

- ...

## 回答後に更新する項目

- ...
```

## Rules

- 質問は必ず一度に一つだけにする。
- 重要度の低い質問を大量に出さない。
- 回答によって実際に変わることがある質問を優先する。
- コードベース調査で分かることは、ユーザーに聞く前に調査する。

## Anti-patterns

- 10問以上をまとめて投げる。
- 質問理由を示さない。
- AIが勝手に仮定して先へ進む。

# notes

実装中にAIが行った判断、計画からの逸脱、遭遇したエッジケースを記録する。

## Purpose

- 実装プロセスのブラックボックス化を防ぐ。
- diffだけでは残らない判断理由を保存する。
- 後でレビューしやすい形で、計画との差分を整理する。

## When to Use

- 実装開始時。
- 実装中に計画から外れたとき。
- エッジケースを発見したとき。
- AIが保守的な判断をしたとき。
- 当初の想定と異なる制約を見つけたとき。

## Inputs

- Implementation Plan。
- 実装中に見つかった差分。
- 判断が必要になった事象。
- 選択した対応。
- 選ばなかった対応。
- 後で確認すべきこと。

## Process

1. 計画から変更した点を記録する。
2. 変更理由を残す。
3. 遭遇したエッジケースを記録する。
4. 選択した対応と選ばなかった対応を分ける。
5. 後で確認すべきことを残す。
6. 実装後ではなく、実装中に更新する。

## Outputs

- Implementation Notes。
- 計画から変更した点。
- 変更理由。
- エッジケース。
- 選択した対応と選ばなかった対応。

## Output Format

```markdown
# Implementation Notes

## 1. 計画から変更した点

- ...

## 2. 変更理由

- ...

## 3. 遭遇したエッジケース

- ...

## 4. 選択した対応

- ...

## 5. 選ばなかった対応

- ...

## 6. 後で確認すべきこと

- ...
```

## Rules

- diffだけで判断理由を残したつもりにならない。
- 小さな判断でも、後から意味を持ちそうなものは残す。
- 保守的な選択をした場合は理由を書く。
- 計画から逸れた場合は、逸脱を隠さない。

## Anti-patterns

- 実装後にまとめて思い出しながら書く。
- 何を選ばなかったかを書かない。
- 「軽微な変更」で済ませる。

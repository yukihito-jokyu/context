# レビュー画面の規則

- 左は動く React 画面案、右はレビュー。デスクトップではそれぞれ独立した縦スクロール、幅1040px以下では縦積みとする。
- 画面案は中立色の外側領域に余白を取って配置し、「画面案」のラベル、視認できる枠線と影で画面内外を区別する。画面案の背景色が白や淡色でも境界が消えないよう、実ブラウザで外側背景・枠線・余白を確認する。レビュー UI の CSS セレクターは画面案内の Design System 部品に波及させない。
- 案番号、仮データ、保存されないこと、レビュー操作の案内は枠の外のレビュー UI に表示する。画面内には実際の利用者向けの内容だけを置く。
- 画面案内に固定高と縦スクロールを組み合わせた入れ子を作らない。スクロール自体が確認対象なら `data-allow-nested-scroll` を付ける。実ブラウザ検証は指定のない入れ子を失敗とする。
- 「確認ポイント」と「画面の詳細設計」は別モードにし、対応する枠と番号だけを表示する。両モードの枠と番号を、右側カードを含めてそれぞれ表示・非表示にできるようにする。
- 確認ポイントの固定枠は青、画面詳細設計とユーザーが追加した指摘の枠は赤。色だけに頼らず同じ番号をカードと画面上へ示す。枠の面は画面案への操作を妨げず、通常時に番号を押すとコメント欄へ移動する。要素選択中は番号も対象選択を妨げない。
- 要素選択中は候補に枠を重ねる。文字だけの子要素を選んだら、意味のある親領域を選ぶ。クリック後は番号付きカードを右側へ追加し、コメント、承認、削除を操作できる。削除した番号は再利用する。
- 詳細設計のカードは項目ごとに開閉でき、開くと対応する画面要素へ移動して一時的に強調する。項目別コメントと、詳細設計全体の承認を別に扱う。詳細設計中は「要素を選んで指摘」を表示しない。
- 承認履歴のある確認ポイントも枠、番号、カードを表示する。承認済みとして初期表示し、追加指摘が入力された時に再確認中へ変える。修正版を再承認すると履歴を追加する。
- 確認ポイントにはユーザー判断が必要なことだけを短く記す。未確定内容は仮と分かる表示にし、少量の現実的なサンプルデータを使う。全体コメント欄は常に置く。
- 注釈位置は対象 DOM の実座標を用い、画面幅、スクロール、リサイズ、コメント欄フォーカス後に再計測する。画像の印象だけで位置を判定せず、`verify_rendered_annotations.py` の座標・当たり判定・モード切替・入れ子スクロールの結果を確認する。
- 受信サーバーが使えない場合は同じ JSON をダウンロードする。ブラウザの送信操作だけで終了済みの AI ターンを再開できるとは説明しない。
- 同一作業領域の Vite が稼働中なら URL とポートを再利用し、案を切り替えるたびにサーバーを増やさない。受信サーバーも現在案に対応していれば再利用する。

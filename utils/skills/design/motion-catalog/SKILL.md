# motion-catalog

UIアニメーションのカタログ（23 カテゴリ・608 件）と、その実装手順をまとめたスキルです。各詳細ページが、その動きの値・決まり・参照実装の唯一の置き場所です。

## 構成

| パス | 中身 | 読むとき |
|---|---|---|
| `animations/<id>.html` | 詳細ページ。値・決まり・参照実装 | 実装する id が決まったら、その 1 ファイルだけ |
| `references/index.tsv` | 全件の一覧（`cat` `id` `kind` `name` `en` `use`）。1 行 1 件 | 名前や雰囲気から探すとき。必要な行だけ |
| `references/direction.md` | おまかせのときの判断軸と組み立て方 | 何を付けるかが決まっていないとき |
| `references/porting.md` | 実装先（React・Vue など）ごとの移し方 | 実装先が素の HTML/CSS でないとき |
| `catalog.html`・`shared/` | 人が見るための一覧ページと共通処理 | 実装では読まない |

`animations/<id>.html` の中身：

| 場所 | 中身 |
|---|---|
| `CatalogDetail.mount({...})` の `id` / `name` / `en` / `cat` / `kind` | ID、名前、英語名、カテゴリ、種類（`motion` 動き / `concept` 考え方 / `style` 表現スタイル） |
| 同 `description` / `use` | 何の動きか、使う場面 |
| 同 `params` | 調整できる値。`value` が初期値。`<style id="motion">` では `var(--key, 初期値)` で受け取っている |
| 同 `spec` | イージング・順序・きっかけ・実装方法・動きを減らす設定など、`params` 以外の決まり |
| 同 `run` | （ある場合だけ）JS で動かす部分の参照実装 |
| `<style id="motion">` | 動きの本体（キーフレームと当て方）。参照実装として使う |
| `<template id="stage">` | プレビュー用の HTML。実装対象ではない |

## 実装の手順

依頼の形で、読むものを分ける。必要なもの以外は読まない。

### A. id がある（詳細ページのプロンプト）

1. `animations/<id>.html` だけを読む。`catalog.html` と `references/index.tsv` は読まない。ファイルがなければ、`index.tsv` から近い候補を示して聞き直す。
2. 「値の変更」があれば、その値を `params` の初期値より優先する。
3. 「対象」がプレースホルダのまま（〈ここに…〉）なら、ユーザーに聞く。「全体」「この画面」のように広いときは、当てはまる場所を探して一覧にし、先に示す。
4. 対象の技術と、対象要素の今のスタイル・動きを確認する。素の HTML/CSS でなければ `references/porting.md` を読む。
5. 種類（`kind`）に合わせて進める。
   - **動き（motion）**：対象の書き方に合わせて移植する。
   - **考え方（concept）**：対象の今の動きを、その考え方に沿って見直す。何をどう変えるかを先に示す。
   - **表現スタイル（style）**：`spec` の組み立てに従い、「カタログの関連」に挙がった id の詳細ページも読んで組み合わせる。

### B. 名前や雰囲気だけ（「Stagger で」「弾むように」）

1. `references/index.tsv` を丸ごとは読まず、grep で当てはまる行だけを読む。カテゴリで絞るなら `^<cat>\t`、言葉で探すなら `name`・`en`・`use` の語（例：`弾`・`bounce`・`spring`）。
2. 候補を 1〜3 件示して、どれを使うか確かめる。決まったら A の 2 から。

### C. 曖昧・おまかせ（「良い感じに」「全体的に動きを」）

1. `references/direction.md` を読み、その手順で材料を集め、性格・動きの言語・場面ごとの id を決める。
2. 計画を `direction.md` の形で示して、確認を取る。
3. 素の HTML/CSS でなければ、ここで `references/porting.md` を 1 回読む。
4. 選んだ id ごとに詳細ページを読み、A の 5 で実装する。計画で決めた時間・ずらしは「値の変更」として扱う。

## 移植のきまり

- 移すのは **時間・イージング・キーフレーム・順序（遅延）・きっかけ** です。`params`（値の変更があればその値）と `spec` の値は変えない。`var(--key, 初期値)` は、決まった値に置き換えてよい。
- Soft Blue の色・形・クラス名（`sb-` で始まるもの）、`<template id="stage">` の HTML は持ち込まない。見た目は対象プロジェクトのものを使う。`spec` や `<style id="motion">` に Soft Blue の色や影の名前（`blue-strong`・`--shadow-float` など）があれば、対象プロジェクトで同じ役割の色・影に置き換える。なければ既存の色から作る（`color-mix()` など）。
- `run` のうち、デモのための部分（指＝カーソルを動かす `seq` / `move`、スクロールを自動で動かす `auto`、一定間隔で状態を切り替える `setInterval`）は移植しない。実際の操作（クリック・ホバー・スクロール・ドラッグ）に置き換える。
- `spec` にある「動きを減らす設定」（`prefers-reduced-motion`）への対応を必ず入れる。
- 5秒を超えて自動で動き続けるもの（背景・ループ・自動再生）には、止める・再開するボタンを付ける（キーボードでも使えるように。動きを減らす設定だけでは代わりにならない）。読み込みが終われば消える読み込み中の表示は除く。
- 動かすのは原則 `transform` と `opacity`。見本が `width`・`height`・`top`・`left` を動かしている場合は、FLIP や `grid-template-rows` などで置き換えられないか検討する。
- 同じ要素に複数の動き（登場とホバー、ホバーと押下など）を重ねるときは、`translate`・`scale`・`rotate` の個別のプロパティに分けるか、要素を入れ子にして分ける。登場のアニメーションは、終わった後に `transform` を残さないよう `animation-fill-mode` を `backwards` にする。
- 説明に「プレビューは…近い形」とある項目や、`spec` に「本格的に」がある項目（WebGL・3D・物理・動画編集・OS の操作が元のもの）は、見本をそのまま移植せず、「本格的に」に書いた方法で作るか、どちらにするかをユーザーに確かめる。
- 終わったら、何を、どのファイルのどこに入れたかを報告する。

## アニメーションを追加するとき

1. 近い種類の `animations/<id>.html` を複製し、`<template id="stage">`・`<style id="motion">`・`CatalogDetail.mount({...})` を書き換える。CSS のクラス名とキーフレーム名は `ac-<id>-` で始める。
2. プレビューは Soft Blue の決まりに従う（主役だけ具体的に描き、ほかはバーや形でぼかす。青は意味のある所だけ）。カードの中で見えるよう、だいたい 240×160px に収める。
3. `catalog.html` の `ANIMATIONS` に `{ id, name, en, cat }` を1行足す。`cat` は `CATEGORIES` の `id`。`references/index.tsv` にも、同じカテゴリの行の最後に 1 行足す（`cat` `id` `kind` `name` `en` `use` をタブ区切りで）。
4. 詳細ページが 1280×720 の画面でスクロールなしに収まるか確かめる（収まらなければ説明・決まりを短くする）。
5. 参照実装（`<style id="motion">`・`run`）は、主要ブラウザすべてで使える機能（Baseline Widely available）だけで書く。それより新しい機能を使うなら、未対応のブラウザでも同じように動く代わりの書き方を必ず付ける。付けられないものは `spec` の「別の方法」に載せるだけにする。

# ライフサイクルレンダラー

`diagram_type: "lifecycle"` のJSONファイルを標準Archify HTMLテンプレートへレンダリングします。

```bash
node archify/renderers/lifecycle/render-lifecycle.mjs input.lifecycle.json output.html
```

レンダラーは、同梱のスタンドアロンバリデーターを使用して、入力を `archify/schemas/lifecycle.schema.json` に照らして検証します。依存関係をインストールする必要はありません。

`output.html` を省略すると、レンダラーはJSONファイルの `meta.output` を使用します。それもなければ、現在の作業ディレクトリの `lifecycle.html` へフォールバックします。

## schema v2

新規記述にはv2を使います。対象・観測範囲と要素・関係の意味は[ライフサイクルの記述ルール](../../references/lifecycle.md)を参照してください。`model.mjs`は座標・ネットワーク・外部実行エンジンから独立した意味検証、`layout.mjs`は任意レーン・行・列の計測、レンダラーは明示された関係だけの描画を担当します。

開始／終端・要素種類を文字で表示し、全体終端は二重枠、イベントは丸い枠、活動は破線枠で補助します。関連付けは矢印なしの破線であり、順序を表しません。囲みは意味を宣言した範囲で、部分完了や反復条件を保持します。条件・活動を関係ラベルから消してレイアウトを修復しません。

type未指定の要素にはkindごとの既定テーマ色を付けます。イベントはfrontend、活動はbackend、状態はdatabase、フェーズはcloud。明示したtypeの配色を優先し、色は意味検証に使いません。凡例の要素見本も既定配色に対応します。明示配色を持つ種類の見本は枠形状を説明し、別の配色項目で色を説明します。

同梱の`order.lifecycle.json`、`react-effect.lifecycle.json`、`claude-hooks.lifecycle.json`がv2の例です。

v2の凡例は要素・関係・囲みのkindと開始／終端の印を説明します。明示したtypeだけを配色として補足します。対応キーは`state`、`phase`、`event`、`activity`、`initial`、`terminal`、`transition`、`sequence`、`association`、`scope`、`repeat`、`parallel`、`group-phase`と、v1と共通の配色キーです。凡例から色の絞り込み操作は行いません。自動viewBoxでは凡例の行数も確保し、収まらない明示viewBoxは診断します。

## schema v1（互換入力）

ライフサイクルJSONファイルには、次の値を設定する必要があります。

```json
{
  "schema_version": 1,
  "diagram_type": "lifecycle",
  "meta": {
    "title": "Agent Run Lifecycle",
    "viewBox": [980, 660]
  },
  "lanes": [],
  "states": [],
  "transitions": [],
  "cards": []
}
```

レーンIDには意味があり、予約されています。IDが `main` のレーンは必須で、上部のフェーズ帯へ対応します。`terminal` は下部の結果帯へ対応します。それ以外のレーンID（合計最大4レーン）は、単一の中央イベント帯を共有します。3つの帯見出しは指定したレーンラベルからレンダリングされ、中央帯では全イベントレーンのラベルを ` + ` で連結します。完全な実例は `archify/examples/agent-run.lifecycle.json` にあります。

schemaは次の場所にあります。

```text
archify/schemas/lifecycle.schema.json
```

## v1の凡例

既定の凡例は `states[].type` から種別を導出します。`meta.legend.entries` で対応するキーは、安定順で `start`、`active`、`waiting`、`decision`、`success`、`failure`、`neutral`、`external` です。ラベルと表示状態は共有凡例契約によって上書きできます。レンダリング済み状態に裏付けられた種別だけがSemantic Legend操作を受け取ります。

## レイアウト上限

| 帯 | レーンID | 上端y | 列中心 | 既定状態 |
|------|---------|-------|----------------|---------------|
| フェーズ | `main`（必須） | 126 | `col` 0～4 → x = 94, 248, 402, 556, 710 | 118×62 |
| イベント | その他の任意ID | 278 | `col` 0～2 → x = 402, 556, 710 | 126×58 |
| 結果 | `terminal` | 450 | `col` 0～2 → x = 402, 556, 710 | 118×58 |

イベント列とterminal列は、意図的にmainレールからずらされています。event／terminalの `col: N` は、mainの `col: N + 2` と同じx座標を使用します。たとえば下部帯の列0、1、2は、それぞれmain列2、3、4の下に揃います。

| 定数 | 値 |
|----------|-------|
| viewBox | 既定 `[980, 660]`、schema最小値 `[420, 566]` |
| 状態領域 | xは `[32, width − 32]` 内、状態下端は `height − 122` 以下 |
| 状態間隔 | 任意の2状態間で10px以上。全イベントレーンが1つの帯を共有するため、レーンをまたいで検査します。同一帯の別状態は `col` または `yOffset` で離します |
| 遷移長 | 端点間32px以上 |
| 凡例行 | 最終ベースライン y = height − 36。計測された追加行は上方向へ折り返します |

主要ライフサイクルレールはフェーズ帯に沿って走り、使用中の最遠フェーズ列まで延びます。遷移の経路プリセットは、`straight`、`drop`（`channelY` で折れ、既定は垂直中点）、`bottom-channel`、`top-channel`、`right-channel`、`left-channel`、明示的な `via` 点、または既定の `auto` です。複数区間の遷移には丸い角が付きます。`cornerRadius`（既定10、鋭角は `0`）で調整します。

## v1例の配置上の慣習（v2には適用しない）

- 従来例は水平フェーズマップとして配置されています。新規記述の意味や段階数をこの例に合わせる必要はありません。
- `main` レーンを使い、主要ライフサイクルを1本の水平レール上に置きます。
- `step` ラベルは `01`、`02`、`03` のような順序付きフェーズに使用します。
- 下部レーンは中断、回復、終了への退出だけに使用します。
- 意味のある遷移ラベルは保持します。冗長な補足だけをカードへ移し、イベント・条件・活動を隠して配置を修復しません。
- 斜線と交差線を避けます。可能な限り、terminalへの退出はソースイベントから垂直に下ろします。
- `type`は表示分類です。失敗が回復可能か、待機が終了を意味するかは実際の関係と対象境界で確認します。

schema違反は、要素のidまたはlabelを注記したパス接頭辞付きメッセージを出力して0以外で終了します。レンダラーはさらに、`main` レーンの欠落、状態IDの重複、不明なレーン、不明な遷移端点、ライフサイクル領域外の状態、状態の重なり（レーン間を含む）、ラベルと状態または他ラベルとの衝突、状態より幅広いラベル、短すぎて読めない遷移、無関係な状態を横切る遷移（Clean Flowの2pxクリアランス）など、検出可能なレイアウト問題でも失敗します。ライフサイクル帯は意図的な通過コンテナーのままです。テキスト幅はCJKを考慮して推定し、全角グリフを2単位として数えます。

洗練された配信には、`meta.quality_profile` を `showcase` に設定します。その場合、無関係な正規X交差は `composition/proper-crossing` で失敗します。既定の `standard` では成果物レシートの警告に留めます。最終成果物検査は丸められた `Q` コーナーをサンプリングします。同一直線上の経路は正規X規則の対象外ですが、別のゲートが、無関係な遷移が8px以上重なると `standard` では警告し、`showcase` では失敗します。共有セマンティック端点、点での接触、それより短い重なりは有効なままです。Showcaseはさらに、8px未満の経路区間と16px未満の内部折れ区間を拒否します。通常の8～15pxの端点スタブは有効なままです。

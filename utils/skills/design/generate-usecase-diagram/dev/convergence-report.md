# generate-usecase-diagram 収束テストの記録

## 条件

- runnerはClaude Code CLIとCodex CLI。両者が起動できるため、STEP-03の既定の2製品を使う。各課題・各製品で独立した2セッションを起動する。
- 通常3課題を測り、基準を満たした後または上限の第3ラウンドに、未使用の別題材T4-holdoutを加える。
- 基準は全員done、再check成功、スキル・hooks改変なし、files=1、structure=1、names>=0.8。レビュー検出率は1。
- 第1ラウンドは除外なし。第2ラウンド以降は自動生成の`.skill-runs/generate-usecase-diagram/report.md`だけを除外する。このファイルは実行先の絶対パスを必ず含み、セッションごとにパスが変わる。利用者向け出力のcatalog.json・Mermaid・PNG・HTML・validation.json、入力JSON、確認画面、補足メモは比較に残す。
- Codexではworkspace-write内のChromeが異常終了したため、CLIの--approve-for-meによるworkspace-writeと自動承認レビューを使った。--sandboxとの併記はCLIエラーとなるため除いた。試行と再試行は`results/runner-preflight.json`に記録。
- Mermaid 12.1.0・既存Google Chrome・Python標準ライブラリを使用。追加パッケージは入れていない。CLIの製品差を測るもので、モデルの指定・統一はしていない。

## ラウンド2：結果と利用上限

Codexは通常3課題×2人の6件すべてdone、再check成功、files・structure・namesがすべて1。保存名・確認記録の揺れは解消した。

Claude CodeはT1の1件だけdone。他の1件は900秒timeout、T2の2件はAPIがHTTP429・rate_limit_error code1308（5時間の利用上限）を返した。ツールを使わない短い応答確認も120秒でtimeoutした。起動済みのT3の2件は、同じ制限での待機を続けないためSIGTERMで止めた。これらは成功として数えない。根拠はresults/runner-availability.json、results/runner-health.json、round-2/report.jsonにある。

| 課題 | 揺れ | 分類 | 対処 |
|---|---|---|---|
| 全課題 | Claude接続先の利用上限により完了状態が揃わない | V7 | スキルや検査を緩めず、STEP-03の利用可能runnerへの代替に従い、最終ラウンドをCodexのみで実施する。両CLIの最終比較は未完了として残す |

第2ラウンドは全体の基準を満たさない。利用可能なCodexで、上限の第3ラウンドをholdoutを加えた最終ラウンドにする。

## ラウンド3：Codexの最終ラウンド

4課題×2人の8件すべてdone、再check成功、スキルとhooksの改変なし。ファイル集合と構造は全課題で1。T2-default・T3-edge・未使用のT4-holdoutはnamesも1で基準を満たした。holdoutを含む最終ラウンドはこの1回で、事前にholdoutを使った修正はしていない。

T1-typicalのnamesは0。新しく抽出された名前はcodex-1の確認メモにあるPNG1の1語だけで、codex-2には無い。実際のカタログ名、図ID、アクター、ユースケース、境界のIDは一致している。validation.jsonの確認メモ「PNG1図」と「PNG 1枚」の表記差である。V8（結果に影響しない言い回し）と分類し、指標を書き換えたり確認メモを比較から除外したりしない。

## 実行数と制約

収束テストは第1ラウンド12枠、第2ラウンド12枠、第3ラウンド8枠、レビュー2枠の合計34枠を実行した。第2ラウンドのClaudeは1件完了、1件timeout、2件API利用上限エラー、2件を制限確認後に停止した。別途、runner設定の事前確認2件と、短い応答確認1件を行った。CLI引数の重複で起動前に終了した試行はモデルセッション数として数えない。

Claude CodeとCodexの両CLIを第1ラウンドで動かし、両者のhooks配線をprobeで確認した。ただし、Claudeの接続先が5時間の利用上限に達したため、修正後の両CLIの最終比較とClaudeの最終レビューは未完了である。skill-foundation/SKILL.mdのSTEP-03の「片方だけ起動できる」行を、API利用上限による実行拒否に適用し、Codexへ限定した。

## 結論

Codexの最終ラウンドでは4課題8件の生成と再検査に成功し、3課題がすべての数値基準を満たした。レビューの検出率は1。ファイルと構造は全課題で一致した。

- T1-typical: V8。確認メモの「PNG1図／PNG 1枚」だけでnamesが0となった。実際の識別子と図は一致。利用者が「V8として記録し、作例とガイドを仕上げる（推奨）」と回答したため、追加ラウンドを行わず、この表記差を記録して終了する。
- 両CLIの最終比較: Claude接続先の利用上限のため未完了。最終ラウンドとレビューはCodexのみ。

# plan

実装前に、AIが考えた作業計画を人間がレビューしやすい形にする。特に、人間が変更しそうな重要判断を先頭に置く。

## Purpose

- 実装前に重要判断をレビュー可能にする。
- データモデル、型、UX、既存仕様への影響を先に見せる。
- 機械的な変更と、人間が判断すべき変更を分ける。

## When to Use

- 実装前。
- 設計変更を伴う作業前。
- データモデル、型インターフェース、UXフロー、責務分割が関係するとき。
- `blindspot`、`interview`、`reference`、`prototype` の結果を実装順へ落とすとき。

## Inputs

- 作業目的。
- 仕様。
- `blindspot` の結果。
- `interview` の回答。
- `reference` の分析結果。
- `prototype` のフィードバック。
- 未決定事項。
- 制約と受け入れ基準。

## Process

1. 作業目的と完了条件を整理する。
2. 人間が変更しそうな判断を先頭に置く。
3. データモデル、型インターフェース、UXフロー、既存仕様への影響を示す。
4. 実装ステップを依存順に並べる。
5. 機械的な変更を後ろに分ける。
6. 未決定事項と仮定を明示する。
7. レビューしてほしい点を列挙する。

## Outputs

- Implementation Plan。
- 重要判断。
- 実装ステップ。
- 未決定事項と仮定。
- レビュー観点。

## Output Format

```markdown
# Implementation Plan

## 1. 重要判断

### 1.1 データモデル・構造

- ...

### 1.2 型・インターフェース

- ...

### 1.3 UX・処理フロー

- ...

### 1.4 既存仕様への影響

- ...

## 2. 実装ステップ

1. ...
2. ...
3. ...

## 3. 機械的な変更

- ...

## 4. 未決定事項

- ...

## 5. 仮定

- ...

## 6. レビューしてほしい点

- ...
```

## Rules

- ファイル変更一覧だけで終わらせない。
- 人間が判断すべき論点を後ろに埋もれさせない。
- 重要判断と機械的作業を分ける。
- 未決定事項を勝手に決めない。

## Anti-patterns

- 実装手順だけを長く書く。
- データモデルやUXの判断を省略する。
- すべて確定したように書く。
